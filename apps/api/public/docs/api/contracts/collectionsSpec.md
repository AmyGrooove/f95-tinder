# Подборки: спецификация API

[Каталог эндпоинтов](../endpoints.md) · [Схемы подборок](../requestFlows/collections.md)

Актуальные маршруты подключены в [модуле подборок](../../../../src/endpoints/collection/collection.module.ts).

Связанные документы: [сущности](../entities.md), [личная библиотека](librarySpec.md), [границы MVP](../../product/mvpScope.md). Эта спецификация определяет отдельно согласованный объём подборок; прежнее исключение публичных подборок из стартового MVP не означает отказа от описанного здесь API.

## Модель

- `Collection` хранит основные данные, автора, тип custom/franchise/tag, `version`, `deletedAt` и массив `blocks`. При `author=null` подборка принадлежит сайту, иначе — указанному пользователю. Отдельного поля ownership нет.
- Все подборки публичные. Сайтовые теговые подборки (`type=tag`, `author=null`) связаны с Tag полем `tag` и наполняются автоматически по прямым TagItem. Для франшиз и пользовательских подборок сохраняется ручной состав; приватность не предусмотрена.
- Порядок блоков определяется их порядком в массиве. У каждого блока стабильный ObjectId `id` и тип group или text.
- `group` содержит необязательные `title` и `description` на RU/EN. Группа без названия выглядит обычным списком. Полей `appearance` и сворачивания нет.
- `text` содержит `content` на RU/EN с хотя бы одним непустым переводом. Поля группы у текстового блока и content у группы запрещены.
- `ItemCollection` хранит состав отдельно от Collection: `collectionId`, `item`, обязательный `groupId`, `position` внутри группы, необязательную `note` и nullable `relevanceScore` (по умолчанию null; конечное число больше 0 и не больше 1). Ссылка groupId должна указывать на блок типа group той же подборки.
- Обычные участки списка, именованные группы и текстовые вставки могут чередоваться в любом авторском порядке. Отдельного раздела «Без группы» нет: все элементы относятся к группам, в том числе безымянным.
- Пара collectionId/item уникальна: произведение нельзя повторить в другой группе той же подборки.
- `UserCollection` хранит независимые личные реакции: `isFavorite`, целую оценку `rating` от 1 до 10 или null, `isHidden`.
- Состав подборок независим от библиотеки UserItem. Добавление и удаление Item в подборке не меняет статус, оценку, избранное, заметку или попытки пользователя.

## Маршруты

При старте приложения недостающие предопределённые Tag создаются из единого справочника; независимо от создания Tag для каждого сохранённого тега проверяется наличие отдельной сайтовой подборки с одной обычной безымянной группой. Уникальный частичный индекс по `Collection.tag` предотвращает дубли автоматических подборок. Существующие Tag и состав не переписываются.

Назначения через `TagItemRepository.write/bulk` публикуют событие после записи, а внутри `MongoTransactionService.run` — после commit. Обработчик BullMQ перечитывает текущие прямые TagItem произведения, добавляет и удаляет членство, копирует значимость в `ItemCollection.relevanceScore` и сохраняет позиции. При переносе назначения между произведениями обрабатываются оба Item. Потомки и родители не включаются автоматически. Первоначального наполнения по уже сохранённым TagItem, backfill и ежедневной сверки нет. Между MongoDB commit и постановкой задания возможна потеря события; outbox и гарантированное восстановление не реализованы. Прямые записи в БД обходят события репозитория. Новых HTTP-операций назначения тегов нет. В предыдущей редакции зафиксирована проверка автоматизации интеграционными тестами на изолированных MongoDB 8.0.17 и Redis 8.2.3. При сверке документации 7 ноября 2026 года эти проверки не повторялись; рабочее окружение не проверялось.

| Метод и путь                   | Назначение                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| `GET /collections/:id`         | Основные данные, полная структура блоков и общая статистика                         |
| `QUERY /collections/:id/items` | Публичная порция Item с поиском, фильтрацией, сортировкой и курсором                |
| `GET /collections/:id/user`    | Реакция текущего пользователя и прогресс по всему составу                           |
| `PATCH /collections/:id/user`  | Изменить поля личной реакции                                                        |
| `PUT /collections/:id/poster`  | Загрузить изображение обложки                                                       |
| `POST /collections`            | Создание подборки                                                                   |
| `PATCH /collections/:id`       | Единое атомарное редактирование основных данных, блоков, состава, заметок и порядка |
| `DELETE /collections/:id`      | Мягкое удаление подборки                                                            |

Изменения групп, состава и порядка входят в единый PATCH. Полная запись UserItem читается через библиотеку.

## Реализованное чтение подборки

`GET /collections/:id` доступен без авторизации. Успех — 200 с `Cache-Control: no-store` и полями `id`, `version`, `author` ({id, avatar, displayName} или null), `type`, `title`, `description`, `media`, `blocks`, `createdAt`, `updatedAt`, `itemCount`, `ratingAverage`, `ratingsCount` и `favoritesCount`. Переводы представлены объектом `{ru, en}` с nullable-строками, media — массивом `{src, language, type}`, даты — ISO 8601.

`itemCount` считает существующие неудалённые Item, включённые в действующие группы. `ratingAverage` — среднее арифметическое сохранённых ненулевых оценок подборки или null, если оценок нет. `ratingsCount` считает выставленные оценки, `favoritesCount` — реакции с `isFavorite: true`. Скрытие подборки пользователем не влияет на эти показатели.

Блоки возвращаются полностью в авторском порядке. Группа содержит `id`, `type=group`, nullable `title` и `description`; текстовый блок — `id`, `type=text`, `content`. Состав Item, личные реакции и внутренние поля хранения не возвращаются. Для указанного автора сервис читает публичные поля User. author=null возвращается как для подборки сайта, так и при отсутствии записи автора; по одному этому HTTP-полю нельзя безусловно определить официальность.

Некорректный ObjectId возвращает 400. Отсутствующая или помеченная удалённой подборка возвращает одинаковый 404. Личное скрытие не ограничивает этот публичный маршрут. Чтение с фильтром `deletedAt=null` вынесено в `CollectionRepository.findNotDeletedById`; явное формирование DTO выполняет `CollectionService`.

## Реализованное создание подборки

`POST /collections` требует access cookie, активную серверную сессию и существующего пользователя. Автором становится текущий пользователь; поля author/authorId/ownership не принимаются. Создание подборок сайта относится к отдельной админке и не входит в этот маршрут.

Обязательное поле — `title` с хотя бы одним непустым переводом. Необязательны `description`, `type`, `blocks`, `items`. Переводы принимаются как `{ru?, en?}`, строки или null; отсутствующие переводы становятся null. По умолчанию type=custom, description={ru:null,en:null}, media/blocks/items пустые. Допустимы custom/franchise/tag; состав всех типов, создаваемых этим пользовательским маршрутом, ручной. null вместо необязательного объекта, массива или type не допускается.

Блок принимает `type`, необязательный `id` и поля своего типа. Для group разрешены nullable title/description; переданный title должен иметь непустой перевод. Для text обязателен content с непустым переводом; title/description запрещены. content у группы запрещён. Пропущенный id генерируется сервером; для ссылки на группу из начального состава клиент задаёт её id явно.

Начальные items имеют `{itemId, groupId, position, note?}`. position — неотрицательное безопасное целое. note допускает null, обрезается по краям, пустая строка становится null. ID блоков и itemId уникальны с учётом нормализации ObjectId; groupId указывает на group в этом же запросе. Некорректные данные, неизвестные поля и дубли возвращают 400; отсутствующий или удалённый Item — 404, недействительная авторизация — 401. Одинаковые position допускаются. Предварительные числовые лимиты из последнего раздела не введены этим маршрутом.

Collection и ItemCollection создаются одной транзакцией MongoTransactionService; проверка существования Item также выполняется в ней. UserItem не изменяется. ItemRepository.findNotDeletedByIds инкапсулирует выборку действующих Item, ItemCollectionRepository.createForCollection — запись состава с ID подборки; оба принимают сессию вызывающего сервиса. Успех — 201 с {id} и Cache-Control:no-store. Глобальные CSRF, валидация и throttling применяются по общим правилам API.

## Реализованное чтение личной реакции

`GET /collections/:id/user` реализован в отдельном CollectionUserController и CollectionUserService. Требует действующий access cookie, активную серверную сессию соответствующего пользователя и существующий аккаунт. Возвращает 200 с `{isFavorite, rating, isHidden, progress: {completed, total}}` и `Cache-Control: no-store`. rating — целое от 1 до 10 или null. Без сохранённой реакции поля реакции равны false, null и false соответственно.

ID в пути относится к Collection, а не к записи реакции. Некорректный ObjectId возвращает 400, недействительная авторизация — 401, отсутствующая или удалённая подборка — 404. Чтение разрешено также автору подборки; личное скрытие не ограничивает этот маршрут. Реакция выбирается только по паре текущий пользователь/подборка. Общие данные подборки, внутренние ID реакции и реакции других пользователей в ответ не входят.

`progress.total` использует те же правила доступности, что и публичный `itemCount`. `progress.completed` считает среди этих Item те, для которых статус UserItem текущего пользователя равен `completed`. Оба счётчика относятся ко всей подборке, включая скрытые зрителем подборки, и не зависят от параметров `/items`. Для пустого состава оба равны 0. Маршрут выполняет только чтение без транзакции.

## Реализованное редактирование подборки

`PATCH /collections/:id` требует access cookie, активную серверную сессию, существующего пользователя и авторство. Чужая, отсутствующая, удалённая или принадлежащая сайту подборка возвращает 404. Управление подборками сайта остаётся за отдельной админкой.

Обязательна текущая `version` — неотрицательное безопасное целое. Её возвращает GET /collections/:id. POST возвращает только {id}, PATCH — 204 без тела. Новые подборки начинают с 0; документы без сохранённого поля читаются и обновляются как версия 0. Успешный PATCH увеличивает версию на один. Устаревшая версия либо достижение Number.MAX_SAFE_INTEGER возвращает 409.

Необязательные поля — title, description, media, type, blocks и items. Требуется хотя бы одно изменение. При передаче `media` весь массив заменяется. Для каждого элемента укажите непустой `src` с URL и тип `poster`, `screenshot` или `trailer`. `language` можно пропустить или передать как `null`. blocks и items содержат необязательные массивы add, update, move, remove.

- blocks.add принимает {id, type, title?, description?, content?, beforeBlockId?}. id задаёт клиент. Группа использует title и description, текстовая вставка — content.
- blocks.update принимает {id, title?, description?, content?}. Пропущенные поля сохраняются, null очищает заголовок или описание группы. Тип блока сохраняется.
- blocks.move принимает {id, beforeBlockId}, blocks.remove — массив ID блоков.
- items.add принимает {itemId, groupId, note?, beforeItemId?}. Произведение должно существовать и ещё не входить в подборку.
- items.update принимает {itemId, note}. null, пустая или пробельная строка очищают заметку.
- items.move принимает {itemId, groupId, beforeItemId}, items.remove — массив ID произведений.
- Отсутствующий или null якорь в add добавляет объект в конец. В move якорь обязателен, null ставит в конец. Непустой якорь ссылается на существующий элемент в итоговом блоке или в группе назначения на момент операции.
- Добавления, обновления и перемещения каждого вида применяются в порядке массивов. Объект можно обновить и переместить одним запросом. Явно удаляемые объекты исключаются из порядка. При удалении группы исчезают включения, оставшиеся в ней после перемещений. Позиции для затронутых групп рассчитывает сервер.

Изменения выполняются одной транзакцией. Некорректные ссылки, дубли и несовместимые операции возвращают 400. Устаревшая version возвращает 409.

Успех — 204 без тела с `Cache-Control: no-store`. Некорректный ObjectId, неизвестные поля и неверное тело возвращают 400, недействительная авторизация — 401. Глобальные CSRF и throttling применяются по общим правилам. Предварительные числовые лимиты блоков и размера содержимого не вводились. Изменение схемы не запускает миграцию БД; приложение, БД и тесты отдельно не запускались.

## Реализованное изменение личной реакции

PATCH /collections/:id/user принимает isFavorite?, rating? и isHidden?. Требуется хотя бы одно поле. Рейтинг — целое 1–10 или null. Пропущенные поля сохраняются. Автор не может оценить свою подборку. Успех — 204 без тела.

## Реализованное удаление подборки

`DELETE /collections/:id` требует действующий access cookie, активную серверную сессию соответствующего пользователя и существующий аккаунт. Удаление доступно только автору своей неудалённой подборки. Управление подборками сайта относится к отдельной админке; этот маршрут не даёт администратору права удалять чужие подборки или подборки сайта.

Успех — 204 без тела с `Cache-Control: no-store`. Некорректный ObjectId возвращает 400, недействительная авторизация — 401. Чужая, отсутствующая или уже удалённая подборка возвращает одинаковый 404. Глобальные CSRF и throttling применяются по общим правилам API.

CollectionRepository.softDeleteByAuthor одним условным обновлением проверяет ID, автора и deletedAt=null и устанавливает deletedAt. ItemCollection, UserCollection, Item и UserItem сохраняются. Транзакция не нужна: изменяется один документ Collection. Последующие обычные чтения подборки возвращают 404. Поведение в работающем окружении отдельно не проверено.

## Выдача Item

`QUERY /collections/:id/items` принимает JSON-объект, включая `{}` для первой страницы. `id` в пути — ObjectId из 24 шестнадцатеричных символов. Параметров строки запроса нет. Все поля тела необязательны. Неизвестные поля и явный `null` дают 400.

| Поле                           | Правило                                                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cursor`                       | Строка base64url длиной 1–150 символов. Передайте `nextCursor` для продолжения                                                                                                 |
| `limit`                        | Целое число 10, 20 или 50. По умолчанию 50                                                                                                                                     |
| `types`                        | От 1 до 7 уникальных значений `EItemType`. Без поля участвуют все типы                                                                                                         |
| `search`                       | 1–200 символов после обрезки пробелов. Поиск подстроки без учёта регистра по русскому и английскому названиям и псевдонимам Item                                               |
| `rating`                       | Объект с одной или двумя включительными границами `min` и `max` от 1 до 10. При `min > max` или пустом объекте — 400. При активном диапазоне Item без общей оценки исключаются |
| `mode`                         | `grouped` по умолчанию или `flat`                                                                                                                                              |
| `sort`                         | `collection` по умолчанию, `title`, `releaseDate` или `rating`. `rating` использует среднюю оценку Item                                                                        |
| `direction`                    | `asc` или `desc`. По умолчанию `asc` для названия и `desc` для даты и оценки. При `sort: "collection"` действует авторский порядок                                             |
| `language`                     | `ru` по умолчанию или `en` для сортировки по названию. При отсутствии выбранного перевода используется другой                                                                  |
| `isPersonalFilteringEnabled`   | Boolean, по умолчанию `false`. При `true` применяются скрытие подборки и исключения по статусам зрителя                                                                        |
| `isItemStatusFilteringEnabled` | Boolean, по умолчанию `false`. При `true` применяются исключения по статусам зрителя независимо от скрытия подборки                                                            |
| `isMetadataIncluded`           | Boolean, по умолчанию false                                                                                                                                                    |

Ответ 200 содержит `{nextCursor, blocks, isHidden}`, заголовки `Accept-Query: application/json` и `Cache-Control: no-store`. `nextCursor` — строка для продолжения или null. При `isMetadataIncluded: true` на каждой странице дополнительно возвращается `metadata: {label, description}` из названия и описания подборки. Оба объекта содержат `ru` и `en` со строкой или null в каждом поле. `count` и `total` не возвращаются.

В режиме `grouped` группа содержит `{id, type: "group", title, description, items}`. `id` совпадает с ID блока в метаданных и остаётся тем же для всех порций группы. Текстовый блок содержит `{type: "text", content}`. В режиме `flat` карточки возвращаются в верхнеуровневом `items`, а `blocks` всегда пуст. В режиме `grouped` верхнеуровневое поле `items` отсутствует.

Авторский порядок определяется индексом группы, позицией и ID включения. В режиме `grouped` выбранная сортировка действует внутри каждой группы и сохраняет порядок блоков. В режиме `flat` она действует на весь состав. При равенстве ключей используется авторский порядок. Отсутствующие значения сортируются последними в обоих направлениях. Язык влияет только на сортировку по названию.

Карточка содержит `{id, type, title, media, note, ratingAverage, userRating, userStatus, userProgress}`. В локализованном тексте ключи `ru` и `en` содержат строку или null. `title` и `description` группы и заметка карточки допускают null целиком. `media` — массив `{src, language, type}`, где `language` — строка или null, `type` — `poster`, `screenshot` или `trailer`.

Размер порции ограничивает число Item. Группа может продолжиться на следующей странице. Пустые группы опускаются. Текст перед следующей выдаваемой группой идёт вместе с ней, завершающий текст приходит на последней странице. Обычная выдача без Item может содержать только текст или пустой массив.

Например, главная передаёт `{"types":["movie","series"],"isPersonalFilteringEnabled":true,"isMetadataIncluded":true,"limit":10}`, а Баттл может запросить плоский список через `{"mode":"flat","isItemStatusFilteringEnabled":true}`. Без `__Host-accessToken` запрос считается гостевым и оба флага личной фильтрации игнорируются. При предъявленной cookie проверяются JWT, активная сессия владельца и существование пользователя. Недействительная авторизация даёт 401.

У вошедшего зрителя, включая автора подборки, любой из двух флагов со значением `true` исключает `completed`, `dropped` и `blocked` по его UserItem до пагинации. `isPersonalFilteringEnabled: true` дополнительно учитывает личное скрытие подборки даже при `isItemStatusFilteringEnabled: false`. Для ранее скрытой подборки это даёт `isHidden: true`, `blocks: []`, `nextCursor: null` и в режиме `flat` также `items: []`. В остальных случаях `isHidden: false`. Одновременное включение флагов даёт тот же результат, что и один `isPersonalFilteringEnabled: true`.

Для прямого чтения ранее скрытой подборки с исключением по статусам достаточно передать `isItemStatusFilteringEnabled: true`. Поиск, диапазон оценки и ограничение типов также применяются до пагинации. Пустая отфильтрованная страница не содержит текстовых блоков.

`ratingAverage` содержит среднюю оценку сайта, `userRating` — целую оценку зрителя 1–10, `userStatus` — один из `planned`, `inProgress`, `onHold`, `completed`, `dropped`. Каждое поле допускает null. `userProgress` содержит `{value, unit}` из последней попытки записи с библиотечным статусом, если у попытки задано числовое значение. Ноль считается значением. `unit` — `minute`, `episode` или `percent`. При отсутствии такого прогресса возвращается null. У гостя личные поля равны null. Личные поля доступны вошедшему зрителю и при выключенном личном фильтре.

Курсор учитывает ID и версию подборки, режим, поиск, диапазон оценки, набор типов, действующую сортировку, лимит, зрителя и действующий режим личной фильтрации: без исключений, только статусы или статусы и скрытие подборки. При смене области курсора продолжение возвращает 400. Эквивалентные комбинации флагов можно менять при продолжении, как и `isMetadataIncluded`. Авторский порядок продолжает чтение после позиции и ID включения. Остальные сортировки продолжают чтение по смещению, поэтому обновление данных между страницами может сдвинуть границы порций. Снимок между страницами отсутствует.

Неверные ID, тело и курсор дают 400, отсутствующая или удалённая подборка — 404. Действуют общие ошибки HTTP-адаптера, проверки origin и ограничения частоты. Ошибки используют стандартный объект `{error: {code, message, details, requestId}}`.

## Загрузка обложки

PUT /collections/:id/poster принимает один multipart-файл file от автора. Обложка сохраняется в S3 под collections/<id>/poster/<uuid>.webp. В `Collection.media` обложка хранится с типом `poster` и источником `storageKey`. API возвращает публичный URL в `src`. Успех — 204 без тела. При создании подборки поле media не принимается. Загрузка обложки увеличивает version и является отдельной операцией с S3; она не входит в атомарный PATCH блоков и состава.

## Изменения и удаление

- PATCH принимает только изменения, а не требует прислать весь состав, загруженный постранично.
- В одном запросе можно менять основные данные, создавать/редактировать/удалять блоки, добавлять/удалять Item, менять их заметки и группы, переставлять блоки и элементы.
- Весь запрос применяется атомарно либо отклоняется целиком. Согласованные изменения Collection и ItemCollection выполняются одной транзакцией слоя операций.
- При удалении группы удаляются все её ItemCollection. Сами Item каталога и UserItem не удаляются. Автоматического переноса в другую группу нет.
- Итоговое состояние проверяется на существование ссылок, принадлежность групп, уникальность состава и согласованность типа подборки.
- Для защиты от устаревшего сохранения PATCH требует текущую version и возвращает 409 при несовпадении. Каждый успешный PATCH увеличивает версию на один, включая изменения только состава или порядка.
- DELETE подборки устанавливает deletedAt, сохраняя связи. Удалённая подборка недоступна через обычные маршруты.

## Доступ и реакции

- Пользователь изменяет свои подборки; подборками сайта управляет администратор.
- Автор определяется сервером: пользовательский `POST /collections` всегда использует текущего пользователя. Для подборки сайта author=null; её создание и изменение относятся к отдельной административной операции, которая пока не реализована.
- Все неудалённые подборки доступны для чтения без входа. Удалённая подборка возвращает 404.
- Автор не может оценивать свою подборку.
- Избранное, оценка и скрытие независимы друг от друга.
- Скрытие — личная реакция: оно не ограничивает чтение по прямой ссылке, не меняет состав подборки и реакции других пользователей. Пользовательские маршруты изменения не дают администратору права управлять чужими подборками или подборками сайта.

## Кеширование и границы реализации

- Персональные ответы не кешируются общим публичным кешем; для согласованного варианта личные ответы не кешируются. Общие ответы и варианты фильтров могут кешироваться с проверкой доступа и инвалидацией при изменении состава, блоков, удалении Item, тегов или характеристик. Личная реакция не меняет общие варианты фильтров. Конкретный механизм кеширования пока не реализован.
- Производительность выборок пока не подтверждена измерениями текущего контракта. Подсчёт total этот маршрут не выполняет. Наличие индексов в исходниках не доказывает их наличие в БД или производительность сложного запроса.
- Существующие groups и ItemCollection с groupId=null потребуют отдельной миграции при наличии таких данных. Поле version добавлено в схему; старые документы без него поддерживаются как версия 0. Миграции и операции с работающей БД не выполнялись.
