## Справочник тегов

`QUERY /tags` — публичный запрос с JSON-телом и без авторизации. К нему применяются общие проверки CSRF и частоты запросов для QUERY. `{}` возвращает первую порцию словаря.

```json
{
  "search": "приключения",
  "groups": { "anyOf": ["genre", "subgenre"], "noneOf": [null] },
  "limit": 20
}
```

- Все поля необязательные. `search` содержит 1–200 символов после удаления пробелов по краям. Meilisearch ищет по `name.ru` и `name.en` с учётом опечаток. При наличии текста порядок задаёт релевантность, равенства разрешаются по `id`. Без текста используется порядок `id` по возрастанию.
- `groups` принимает `allOf`, `anyOf` и `noneOf` с непустыми массивами уникальных значений `ETagGroup` или `null`. `null` обозначает тег без группы. Условия соединяются через И. `allOf` с несколькими значениями даёт пустую выдачу, поскольку у тега одна группа.
- `limit` — число 10, 20 или 50, по умолчанию 50. Чтобы продолжить, передайте `cursor` из предыдущего `nextCursor` с теми же условиями. Доступны до 10 000 совпадений. Обновление индекса между запросами может сдвинуть границы порций.
- Ответ 200 содержит `{items, nextCursor}`. У каждого тега есть `id`, `key`, `group` и `name: {ru, en}`. `group` и каждый перевод могут быть `null`. `nextCursor` — строка или `null` в конце выдачи. ID передаются в `QUERY /search` через `items.tags`.
- Неверное тело или курсор дают 400. Неизвестные поля и явный `null` вне списков `groups` запрещены. До первой успешной индексации и при недоступности индекса маршрут возвращает 503. Индекс обновляется по понедельникам в 00:00 UTC и при запуске, если требуется начальная загрузка или пропущено обновление текущей недели.

## Реализованный общий поиск

[SearchController](../../../../src/endpoints/search/controllers/searchController/core/search.controller.ts) и [SiteSearchService](../../../../src/endpoints/search/services/siteSearchService/core/siteSearch.service.ts) подключены через SearchEndpointModule в AppModule.

`QUERY /search` принимает JSON-объект и возвращает `Accept-Query: application/json`, `Cache-Control: no-store`. К маршруту применяются общая защита от частых запросов и CSRF-проверка QUERY. Поле `search` необязательно. Без него поиск работает по указанным фильтрам. Неизвестные поля и явный `null` в теле дают 400.

```json
{
  "search": "космос",
  "limit": 20,
  "entities": { "anyOf": ["items", "collections"] },
  "items": {
    "types": ["movie", "series"],
    "tags": { "allOf": ["507f1f77bcf86cd799439011"] },
    "releaseYear": { "min": 2010 },
    "duration": { "field": "movie.duration", "max": 120 },
    "rating": { "min": 7 },
    "sort": "rating",
    "direction": "desc"
  },
  "collections": {
    "collectionTypes": { "noneOf": ["tag"] },
    "source": "user",
    "sort": "rating"
  }
}
```

- Переданный `search` содержит 1–200 символов после обрезки пробелов. `limit` принимает 10, 20 или 50, по умолчанию 20 на группу.
- Верхнеуровневое `entities` выбирает группы `items`, `collections`, `users`. Включаются все группы из `allOf` и `anyOf`. Если оба поля отсутствуют, исходный набор включает все три группы. `noneOf` исключает группы из этого набора. Исключённые группы не выполняют поисковый запрос.
- `items.types` выбирает любой из переданных типов. Допустимы `movie`, `series`, `animatedMovie`, `animatedSeries`, `animeSeries`, `animeMovie`, `game`. `items.tags` фильтрует по ID тегов. `items.rating` задаёт включительные `min` и/или `max` от 1 до 10, причём `min ≤ max`. При активном диапазоне произведения без оценки исключаются.
- `items.releaseYear` задаёт включительный диапазон целых лет от 1 до 9999. Используется год `releaseDate` в UTC. Если дата отсутствует, подходит точный тег года из группы `releaseYear`. Теги исторических интервалов можно выбирать по ID через `items.tags`.
- `items.duration` задаёт включительный диапазон минут с неотрицательными границами. `field` принимает `movie.duration` (по умолчанию), `series.episodeDuration`, `game.mainStoryDuration` или `game.fullCompletionDuration`. Укажите хотя бы одну границу для года или длительности. Если заданы обе, `min ≤ max`. При активном диапазоне произведения без соответствующего значения исключаются.
- `items.countries` и `items.releaseStatuses` принимают ID тегов из `QUERY /tags` с группами `country` и `releaseStatus` соответственно. Статусы представлены ключами `releaseStatusAnnounced`, `releaseStatusOngoing`, `releaseStatusReleased` и `releaseStatusCancelled`. Каждый фильтр поддерживает `allOf`, `anyOf` и `noneOf`. Фильтры сочетаются с `items.tags` через И. Без условия по статусу анонсы и произведения с неизвестным статусом участвуют в выдаче.
- `collections.collectionTypes` фильтрует по типам `custom`, `franchise`, `tag`. В фильтрах типов коллекций и тегов `allOf` требует все значения, `anyOf` — хотя бы одно, `noneOf` — отсутствие каждого. У коллекции один тип, поэтому несколько значений в `allOf` дают пустой результат. Переданный список содержит хотя бы одно уникальное значение. Для списков ObjectId максимум 100 значений, регистр не учитывается.
- `collections.tagGroups` принимает `allOf`, `anyOf` и `noneOf` с непустыми массивами уникальных значений `ETagGroup`. Например, `{"anyOf":["genre","subgenre"]}` выбирает жанровые коллекции по группе тега, указанного в `Collection.tag`. У связанного тега одна группа, поэтому несколько значений в `allOf` дают пустой результат. Коллекции без тега, с недоступным тегом или тегом без группы могут пройти только отрицательный фильтр `noneOf`. Когда поле опущено или передано как `{}`, группа не ограничивает выдачу. Условие сочетается с остальными фильтрами коллекций и применяется в индексе до пагинации.
- `collections.source` выбирает коллекции сайта (`"site"`, автор отсутствует) или пользовательские (`"user"`, автор задан). Без условия доступны оба источника.
- `collections.itemId` — необязательный ObjectId из 24 шестнадцатеричных символов. Оставляет публичные неудалённые коллекции, в действующих группах которых есть указанное неудалённое произведение. Без поля состав не учитывается. `null` и неверный формат дают `400`. Если произведение отсутствует, удалено или никуда не включено, массив коллекций пуст. Фильтр работает без cookie и сочетается с остальными условиями коллекций.
- `collections.authorId` оставляет коллекции указанного автора. `collections.favoritedByUserId` оставляет коллекции, которые указанный пользователь добавил в избранное. Оба поля необязательны, принимают ObjectId из 24 шестнадцатеричных символов и работают без cookie. `null` и неверный формат дают `400`. Без поля соответствующее ограничение выключено. Фильтры применяются через И вместе с `source`, `itemId` и действующими условиями зрителя, включая `isMine` и `isFavorite`. Если авторы не совпадают или избранное указанных пользователей не пересекается, массив коллекций пуст.
- `sort` задаёт один критерий. `direction` (`asc` или `desc`) указывается рядом с ним. Для произведений доступны `relevance`, `title`, `releaseDate`, `latestReleaseDate`, `rating`. Для коллекций доступны `relevance`, `title`, `updatedAt`, `rating`. Для пользователей доступны `relevance` и `displayName`. По умолчанию `relevance desc`. Для `title` и `displayName` направление по умолчанию `asc`, для остальных — `desc`. Сортировка по названию использует `language` (`ru` по умолчанию или `en`) и второй перевод при отсутствии выбранного. Неизвестные даты релиза и оценки остаются в конце. При равенстве явной сортировки используется ID.
- `items.sort = "rating"` сортирует по `ratingScore = (n × R + 20 × C) / (n + 20)`, где `n` — число голосов, `R` — обычное среднее произведения, `C` — среднее по сайту на начало синхронизации индекса (запасное значение — 5,5). При равном балле в обоих направлениях выше произведение с большим числом голосов, затем используется ID по возрастанию. Произведения без среднего или с нулём голосов идут в конце. Диапазон `items.rating` применяется к обычному среднему `R`.
- Для коллекций «Новые» использует существующий порядок `updatedAt desc`. `collections.sort = "rating"` сортирует по среднему арифметическому оценок самой коллекции. Коллекции без оценок идут в конце в обоих направлениях, при равенстве используется ID по возрастанию.
- Для продолжения отправляется то же тело с `cursor` из предыдущего `nextCursor`. Курсор привязан к тексту, лимиту, выбранным группам, действующим фильтрам, сортировкам и зрителю. Максимальная длина `cursor` — 256 символов. Для нового поиска поле опускается. При обновлении индекса между запросами границы порций могут сдвинуться.

Ответ `200` всегда содержит три массива карточек и курсор:

```json
{
  "items": [],
  "collections": [],
  "users": [],
  "nextCursor": null
}
```

| Группа          | Поля карточки                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `items[]`       | `id`, `type`, `title: {ru,en}`, `media: [{src,language,type: "poster"}]`, `rating`, `userRating`, `userStatus`             |
| `collections[]` | `id`, `type`, `title: {ru,en}`, `media: [{src,language,type}]`, `author`, `isSiteCollection`, `itemCount`, `ratingAverage` |
| `users[]`       | `id`, `username`, `displayName`, `avatarUrl: string \| null`                                                               |

В `items[].media` возвращаются все постеры произведения в сохранённом порядке. Если постеров нет, `media` — пустой массив. `rating` — средний балл сайта или `null`, `userRating` — личная целая оценка 1–10 или `null`, `userStatus` — `planned`, `inProgress`, `onHold`, `completed`, `dropped` или `null`. У гостя личные поля равны `null`. Для `blocked` и `skipped` статус равен `null`. Оценка записи `blocked` доступна её владельцу при выключенном личном фильтре.

В карточке коллекции `author` содержит публичные `id`, `displayName` и `avatar` (строка или `null`). Если автор отсутствует или недоступен, `author` равен `null`. `isSiteCollection` истинно, когда у коллекции отсутствует ссылка на автора. `itemCount` считает существующие неудалённые произведения из действующих групп коллекции. `ratingAverage` — среднее по оценкам коллекции или `null`. Карточка читает текущие данные MongoDB. Порядок по оценке использует последнюю проиндексированную оценку. Фильтры профиля сохраняют эту форму ответа без личных полей реакций.

UI показывает секции в порядке `items → collections → users` и сохраняет порядок карточек внутри секций. В каждой активной группе дополнительное поисковое совпадение определяет наличие следующей порции. Доступны до 10 000 совпадений на группу. Исчерпанные и исключённые группы возвращают пустой массив. `nextCursor` — строка, пока хотя бы у одной группы есть продолжение, иначе `null`. Если карточка исчезла из MongoDB, массив может быть короче лимита или пустым при наличии курсора.

Meilisearch ищет произведения по названиям RU/EN, aliases и описаниям RU/EN, коллекции — по названиям и описаниям RU/EN, пользователей — по username и displayName. Явная сортировка применяется перед правилами текстовой релевантности. Допуск опечаток включается с пяти символов, второй опечатки — с девяти. Обратная релевантность обходит индекс пакетами по 500 ID и выбирает порцию по возрастанию `_rankingScore`, затем по ID. Этот путь может быть значительно дороже обычной выдачи.

Ошибки сохраняют формат `{error:{code,message,details,requestId}}`. `400 BAD_REQUEST` означает некорректное тело, фильтр или курсор, `401 UNAUTHORIZED` — недействительную переданную cookie или сессию в запросе с проверкой зрителя, `403 FORBIDDEN` — отклонение CSRF-проверкой, `429 TOO_MANY_REQUESTS` — ограничение частоты, `503 HTTP_503` — отсутствие отметки готовности или сбой зависимости. Ошибка активной группы завершает весь запрос.

Синхронизация BullMQ запускается при старте и раз в пять минут с дедупликацией. MongoDB возвращает актуальные публичные карточки в порядке найденных ID. Поиск и синхронизация индекса коллекций учитывают типы `custom`, `franchise` и `tag`. Между запросами нет единого снимка, поэтому обновления и удаления в индексе могут менять состав и порядок следующих порций.

### Новинки и популярное на главной

```json
{
  "entities": { "anyOf": ["items"] },
  "isPersonalFilteringEnabled": true,
  "items": {
    "types": ["movie", "series"],
    "sort": "latestReleaseDate"
  }
}
```

- Главная выбирает `entities.anyOf: ["items"]` и опускает текст. Для `latestReleaseDate` единственное направление — `desc`; `asc` даёт 400.
- Новинки сортируются по `latestReleaseDate:desc, id:asc`. У фильмов, включая анимацию и аниме, используется `releaseDate`. У сериалов, включая анимацию и аниме, используется `series.lastReleasedEpisodeAt` с запасным вариантом `releaseDate` при отсутствии даты серии. Учитываются известные даты по момент первой страницы включительно. Указанные в `items.types` типы пересекаются с шестью типами фильмов и сериалов.
- Популярное использует `hasRating:desc, ratingScore:desc, ratingsCount:desc, id:asc`. Произведения без оценки идут в конце. Дополнительного ограничения по дате выхода в этой сортировке нет.

### Личные условия

- `isPersonalFilteringEnabled` — boolean, по умолчанию `false`. При включении у вошедшего зрителя скрываются Item со статусами `completed`, `dropped`, `blocked` и коллекции с `UserCollection.isHidden`. Статус `skipped` сам по себе не исключает Item.
- `items.statuses` поддерживает `allOf`, `anyOf` и `noneOf` для пяти статусов библиотеки и значения `outside`. `outside` включает отсутствие записи и статусы `skipped` и `blocked`. Для фильтра по принадлежности к библиотеке используйте `noneOf: ["outside"]` или `anyOf: ["outside"]`. Независимый `items.isUserItemPresent` со значением `true` требует запись `UserItem` любого статуса, а `false` требует отсутствия записи. По умолчанию оба ограничения выключены.
- `items.isFavorite: true` оставляет избранное зрителя. `items.userRating` принимает включительные `min` и/или `max` от 1 до 10 с `min ≤ max`. При заданном диапазоне карточки без личной оценки исключаются. `collections.isMine: true` оставляет коллекции, где зритель указан автором. `collections.isFavorite: true` оставляет только коллекции из избранного. `false` или отсутствие поля для `isFavorite` и `isMine` снимает соответствующее ограничение.
- `items.isCompletedOrDroppedExcluded`, `items.isBlockedExcluded` и `collections.isHiddenExcluded` включают своё исключение через `true` и выключают через `false`. При отсутствии конкретного переключателя применяется значение `isPersonalFilteringEnabled`.
- Сервер проверяет переданную `__Host-accessToken`, активную сессию и существование пользователя. Без cookie личные параметры проходят валидацию, а выдача строится по публичным условиям.
- Для новинок, сортировки Item по рейтингу без текста, фильтров по данным `UserItem` или `UserCollection` и поиска коллекций по публичному автору сервер проверяет до 200 кандидатов на страницу перед выбором порции. Возможна короткая или пустая порция с курсором. Курсор хранит позицию следующего кандидата и для новинок фиксирует временную границу первой страницы. При смене условий или зрителя начните поиск без курсора.
- Актуальные членства для `collections.itemId` и связи с избранным для `collections.favoritedByUserId` отбираются в MongoDB. Meilisearch применяет полученный набор ID и условие `collections.authorId` перед сортировкой и пагинацией. Курсор привязан к переданным ID без учёта регистра. Изменение членства или избранного между запросами может сдвинуть позиции при пагинации по смещению.
