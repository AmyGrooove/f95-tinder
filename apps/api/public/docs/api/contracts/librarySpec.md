# Личная библиотека: спецификация API

[Каталог эндпоинтов](../endpoints.md) · [Схемы библиотеки](../requestFlows/userItems.md)

Реализованы семь операций изменения и публичный список библиотеки. Чтение отдельной записи по ID Item и полное чтение с заметкой и попытками остаются в LIB-01. Ниже сохранены исторические результаты локальных проверок операций `/userItems`.

Связанные документы: [принципы библиотеки](../../product/foundations/library.md), [сущности](../entities.md), [устройство API](../readme.md).

## Реализованные операции библиотеки

| Метод  | Путь                                 | Назначение                                                                         |
| ------ | ------------------------------------ | ---------------------------------------------------------------------------------- |
| QUERY  | `/users/:id/library`                 | Публичный постраничный список по ID пользователя                                  |
| POST   | `/userItems`                         | Создать запись библиотеки: `{ itemId, status }`, только пять библиотечных статусов |
| POST   | `/userItems/skip`                    | Создать временное исключение: `{ itemId }`                                         |
| POST   | `/userItems/block`                   | Создать постоянное исключение: `{ itemId }`                                        |
| PATCH  | `/userItems/:id`                     | Атомарно изменить переданные `status`, `rating`, `isFavorite`, `note`              |
| DELETE | `/userItems/:id`                     | Удалить личную запись вместе с исключением и всеми сохранёнными данными            |
| POST   | `/userItems/:id/attempts`            | Добавить попытку просмотра                                                         |
| PATCH  | `/userItems/:id/attempts/:attemptId` | Изменить переданные поля попытки                                                   |

В операциях `/userItems` параметр `:id` — ID UserItem. Эти операции требуют cookie `__Host-accessToken`, действующий JWT, активную серверную сессию своего пользователя и существующий аккаунт; иначе 401. Для операций изменения чужая или отсутствующая запись возвращает 404. Создание требует существующий неудалённый Item; недоступное произведение даёт 404, существующая пара пользователь/Item — 409. POST skip/block не изменяют существующую запись и не продлевают пропуск. Просроченный skipped перед созданием новой записи удаляется условным запросом. Существующие записи доступны для редактирования после мягкого удаления Item.

Все изменяющие операции возвращают 204 без тела. DELETE не меняет членство в подборках. Все ответы имеют Cache-Control: no-store.

## Публичный список библиотеки

`QUERY /users/:id/library` принимает 24-символьный шестнадцатеричный ObjectId владельца. Тело обязательно, `Content-Type: application/json`. Пустой объект допустим. Query-параметры, неизвестные поля и явный `null` в теле отклоняются. Access-cookie необязательна. Действующий JWT владельца с активной собственной сессией открывает краткий прогресс и ID UserItem. Без действующей сессии владельца возвращается публичное представление.

| Поле | Допустимые значения и умолчание |
| --- | --- |
| `statuses` | `allOf`, `anyOf`, `noneOf` с 1–6 уникальными значениями из `planned`, `inProgress`, `onHold`, `completed`, `dropped`, `outside`. Условия проверяются по одному статусу записи. `outside` не добавляет записи. Без фильтра участвуют все пять статусов |
| `types` | 1–7 уникальных значений из `movie`, `series`, `animatedMovie`, `animatedSeries`, `animeSeries`, `animeMovie`, `game`. По умолчанию все |
| `search` | 1–200 символов после trim. Буквальная подстрока без учёта регистра по `title.ru`, `title.en` и `aliases`. По умолчанию без поиска |
| `isFavorite` | `true` — только избранное. При `false` или без флага допускаются все записи, удовлетворяющие остальным условиям |
| `sort` | `updatedAt`, `createdAt`, `title` или `rating`. По умолчанию `updatedAt` |
| `direction` | `asc` по умолчанию для `title`, `desc` для остальных критериев |
| `language` | Для `title`: `ru` по умолчанию или `en`. С другими критериями поле даёт 400 |
| `limit` | Целое `10`, `20` или `50`, по умолчанию `20` |
| `cursor` | Строка base64url длиной 1–256 символов. По умолчанию первая страница |

Все поля таблицы необязательны. Условия объединяются через «И», значения в `types` — через «ИЛИ». Список включает только существующие неудалённые Item. Даты сортировки берутся из UserItem, оценка для сортировки — личная, с `null` в конце. Названия сравниваются без учёта регистра с переходом на второй язык при отсутствии выбранного перевода. При равенстве используется ID UserItem по возрастанию.

Ответ 200 — `{items, nextCursor}` с заголовками `Cache-Control: no-store` и `Accept-Query: application/json`. Каждая карточка содержит:

- `id` — строковый ID Item, `type` — тип Item, `title` — объект с `ru` и `en` типа строка или `null`
- `media` — массив постеров `{type: "poster", src: string, language: string | null}`. Без постеров приходит пустой массив
- `status` — один из пяти статусов, `isFavorite` — boolean, `rating` — целая оценка владельца от 1 до 10 или `null`
- `ratingAverage` — общая средняя оценка `ItemStats` от 1 до 10 или `null`
- `userItemId` — строковый ID записи или `null` публично. `progress` — `{value, unit}` из последней добавленной попытки или `null` без значения и в публичном представлении. Единицы — `minute`, `episode`, `percent`. Значение — неотрицательное безопасное целое, для процентов максимум 100

Пустая выдача — `{"items":[],"nextCursor":null}`. Заметки, подробные попытки, `blocked` и `skipped` исключены. Курсор связывает владельца, представление, условия, сортировку и размер страницы. Повтори параметры с полученным `nextCursor`, пока он не станет `null`. Между страницами изменения библиотеки могут дать пропуски и повторы.

Ошибки используют `{error:{code,message,details,requestId}}`: 400 — неверный запрос или курсор, 403 — CSRF, 404 — пользователь отсутствует, 413 — слишком большое тело, 415 — неподдерживаемый тип содержимого, 429 — throttling, 500 — внутренняя ошибка. Маршрут проходит через [схему чтения списка](../requestFlows/userItems.md#user-library).

## Статусы и исключения

Пять библиотечных статусов: `planned`, `inProgress`, `onHold`, `completed`, `dropped`. `skipped` и `blocked` — дополнительные взаимоисключающие состояния той же записи, вне обычной библиотеки и распределения её пяти статусов. Статуса none нет; отсутствие UserItem означает отсутствие личной записи. Показ произведения сам по себе запись не создаёт.

- `skipped`: временное исключение из рекомендаций на 90 суток. Допустимы только `rating=null`, `isFavorite=false`, `note=null`, `attempts=[]`; несовместимое конечное состояние возвращает 409. Добавление личных данных без смены статуса также запрещено.
- `blocked`: постоянное исключение до явного изменения или удаления пользователем. Прежние оценка, избранное, заметка и попытки сохраняются; автоматического срока удаления нет.
- PATCH принимает все семь статусов. При переходе в skipped записывается `expiresAt=сейчас+90 суток`; повтор того же статуса не продлевает срок. При переходе в любой другой статус `expiresAt` очищается.

Для `expiresAt` объявлен TTL-индекс с `expireAfterSeconds:0` и фильтром `status=skipped`. MongoDB удаляет документы в фоне, а не точно в момент истечения. Просроченная запись уже не возвращается кратким QUERY-чтением, не редактируется через PATCH (404) и не мешает созданию новой записи. DELETE может удалить её до TTL-очистки. Библиотечные и blocked-записи TTL не затрагивает. Внутренний отбор кандидатов рекомендаций уже исключает blocked и только непросроченные skipped; публичного HTTP-маршрута рекомендаций пока нет.

## Изменение личных полей

PATCH `/userItems/:id` принимает одно или несколько полей `status`, `rating`, `isFavorite`, `note`; пропущенные сохраняются. Пустое тело, неизвестные поля и null в status/isFavorite отклоняются. Оценка — целое число 1–10 либо null для очистки; заметка — строка либо null, пробелы по краям удаляются, пустая строка становится null. Проверяется итоговое состояние всей записи: совместимую очистку личных полей и переход в skipped можно передать одним PATCH, но попытки этим маршрутом удалить нельзя. Отдельных PATCH-маршрутов личных полей нет; владельца, itemId, expiresAt и массив attempts через него менять нельзя.

## Попытки просмотра

Попытка содержит `id`, `isCompleted`, nullable `progress`, `unit`, nullable `startedAt`, nullable `completedAt`. Собственного status больше нет. `isCompleted=true` означает полный просмотр, а не просто прекращение попытки. По умолчанию false. Дата завершения не предшествует началу; даты могут быть неизвестны и не выставляются автоматически.

`progress` — неотрицательное безопасное целое число либо null. `unit` — minute (по умолчанию), percent или episode; для percent допустимы только 0–100. В episode прогресс означает число полностью просмотренных серий сезона. Смена unit не конвертирует прогресс; валидируется итоговая пара unit/progress. Полный просмотр не выводится автоматически из прогресса и не устанавливает его автоматически.

Для конечных игр критерий прохождения и процентный прогресс определяет пользователь. completed и isCompleted=true не требуют progress=100; отдельной цели или режима прохождения в запросе и схеме нет. Эти отметки не подтверждают прохождение всего необязательного контента. Текущая реализация уже сохраняет независимость прогресса и завершённости.

Единица episode допустима только для Item типов series, animatedSeries и animeSeries. Если итоговая история содержит такую попытку, сервис проверяет тип Item в той же транзакции; отсутствие Item или другой тип дают 400. Мягко удалённый сезон остаётся допустимым. Общая схема попытки разрешает единицу episode, но междокументное ограничение типа проверяет сервис. Значения episodeCount и releasedEpisodeCount для ограничения личного прогресса сейчас не загружаются. Например, `{ "unit": "episode", "progress": 5 }` задаёт пять полностью просмотренных серий; это не номер последней открытой серии.

Для Item типа game с прямым тегом `hasDefinedEndFalse` группы `hasDefinedEnd` возвращается 409 при создании записи со статусом completed, явной установке этого статуса через PATCH, создании/установке isCompleted=true у попытки, создании/установке unit=percent или вводе числового progress в существующую процентную попытку. Проверка использует TagItemRepository.checkHasTagKeys: прямой TagItem должен ссылаться на Tag с нужными group и key. Родительские теги не подставляются. Отсутствие определения/значения не приравнивается к false; для других типов Item это ограничение не применяется.

Для сезонов типов series, animatedSeries и animeSeries с прямым тегом releaseStatusAnnounced или releaseStatusOngoing группы releaseStatus возвращается 409 при создании UserItem со статусом completed, явной установке completed через PATCH и создании/установке isCompleted=true у попытки. Проверка ищет прямые TagItem сезона с Tag группы releaseStatus и одним из указанных ключей. Отсутствующее определение/значение, нераспознанный статус, released и cancelled не блокируют ручную отметку завершения. Числа серий не используются для вывода состояния выпуска; процентный прогресс этим правилом не ограничивается. Другие статусы UserItem сохраняют прежние условия применимости.

Проверки в PATCH и POST attempts выполняются внутри существующей транзакции; при создании UserItem проверка предшествует удалению просроченного skipped и вставке новой записи. Старые значения не очищаются автоматически. Изменение оценки, заметки, других статусов или дат попытки, сброс isCompleted в false, очистка progress через null и переход с percent на minute не блокируются этим правилом. Обычные ограничения статусов и попыток сохраняются, включая запрет новых попыток в planned/blocked.

Для `inProgress`, `onHold`, `completed`, `dropped` нужна хотя бы одна попытка. При создании записи или установке такого статуса, если попыток нет, создаётся первая с неизвестными датами и прогрессом. При установке completed последняя по порядку массива попытка получает isCompleted=true. Смена на другой статус не сбрасывает завершённость прежних попыток. Если история уже есть, смена статуса не создаёт новую попытку.

В planned и blocked существующая история сохраняется и редактируется, но добавление новой попытки запрещено (409). В skipped история запрещена целиком. Повторный просмотр добавляется через POST attempts после выбора одного из четырёх статусов, допускающих попытки.

POST attempts принимает необязательные `isCompleted`, `progress`, `unit`, `startedAt`, `completedAt`; PATCH — любое непустое подмножество этих полей. Nullable только progress и даты. Создание и редактирование попыток не меняют статус UserItem. Порядок массива — порядок добавления; изменение дат не переупорядочивает историю. Массив целиком не заменяется; удаления отдельной попытки в текущем API нет.

Все PATCH и создание попытки читают и обновляют запись в MongoTransactionService с проверкой владельца. Схема процента проверяет верхнюю границу дополнительно к endpoint-валидации. Полные правила сочетания статуса и истории контролируются сервисом, а не MongoDB-ограничением.

## Совместимость и история проверок

Поддержка единицы episode, ограничений hasDefinedEnd и проверки releaseStatus сезона добавлена после проверок, перечисленных ниже. Новый запуск unit- и интеграционных тестов для них не выполнялся; исторические результаты не подтверждают новое поведение.

25 октября 2026 года прошли 103 проверки UserItemController с подменённым сервисом и 118 HTTP-интеграционных тестов UserItemController и CollectionReadController на одноразовых MongoDB 8.0.17 и Redis 8.2.3. Проверены создание исключений, конфликты, ограничения skipped, срок и фактическое TTL-удаление, сохранность blocked/библиотеки, попытки и проценты, авторизация, откат, конкурентные изменения и личные фильтры карточек коллекций. TypeScript-проверка с тестами и ESLint изменённых тестов прошли. Это локальная проверка, а не подтверждение состояния рабочей БД или её миграции.

Реализация находится в [модуле эндпоинтов](../../../../src/endpoints/userItem/userItem.module.ts). Создание, удаление, update и операции с попытками сохраняют UserItem и его метрики одной MongoDB-транзакцией. Обязательный путь обновления статистики — UserItemStatsService.update: снимок до изменения, снимок после изменения и та же session. Для создания previous=null, для удаления next=null. Сервис применяет разницу к ItemStats и, при изменении оценки, к SiteStats.ratings. ratingAverage рассчитывается из десяти счётчиков распределения; без оценок она null. Завершённые попытки считаются без ограничения; сохранённые реакции blocked учитываются. Статусы учитываются только для planned/inProgress/onHold/completed/dropped. Заметка, даты, прогресс и неизменные входные значения не меняют метрики. Skipped не содержит личных данных и попыток и не участвует в счётчиках, поэтому его TTL-удаление не требует обновления. Прямые записи в UserItem обязаны вызывать сервис метрик в своей транзакции; generic repository не заменяет этот контракт. Фоновые задачи и периодический пересчёт метрик удалены; ratingScore вычисляется только при ранжировании.

Старая подсистема рекомендаций и фоновые taste-задачи удалены. Журнал действий этими операциями не обновляется; учёт показов не реализован.

Только если отдельно решено сохранять старые данные, нужно проверить прежние документы: перенести `attempt.status=completed` в `isCompleted=true`, остальные прежние статусы — в false, затем удалить attempt.status. Записи без обязательной попытки необходимо согласовать с новым инвариантом. Если в прежней UserRecommendationState есть данные, отдельно определить перенос исключений и временных пропусков; активное исключение соответствует blocked, но конфликт с существующей библиотечной записью требует осознанного выбора, поскольку теперь статус один. Исходники не удаляют старую коллекцию в БД и не выполняют миграции автоматически. Проверить применение TTL-индекса отдельно; наличие объявления не доказывает его развёртывание.
