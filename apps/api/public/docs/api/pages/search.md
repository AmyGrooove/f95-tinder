## Реализованный общий поиск

[SearchController](../../../../src/endpoints/search/controllers/searchController/core/search.controller.ts) и [SiteSearchService](../../../../src/endpoints/search/services/siteSearchService/core/siteSearch.service.ts) подключены через SearchEndpointModule в AppModule.

`QUERY /search` принимает JSON-объект и возвращает `Accept-Query: application/json`, `Cache-Control: no-store`. К маршруту применяются общая защита от частых запросов и CSRF-проверка QUERY.

```json
{
  "search": "космос",
  "limit": 20,
  "types": { "anyOf": ["items", "collections"] },
  "items": {
    "types": ["movie", "series"],
    "tags": { "allOf": ["507f1f77bcf86cd799439011"] },
    "rating": { "min": 7 },
    "sort": { "type": "rating", "direction": "desc" }
  },
  "collections": {
    "types": { "noneOf": ["tag"] },
    "sort": { "type": "title", "language": "ru" }
  }
}
```

- `search` обязателен, 1–200 символов после обрезки пробелов. `limit` принимает 10, 20 или 50, по умолчанию 20 на группу.
- Верхнеуровневое `types` выбирает группы `items`, `collections`, `users`. Включаются все группы из `allOf` и `anyOf`. Если оба поля отсутствуют, исходный набор включает все три группы. `noneOf` исключает группы из этого набора. Фильтры и сортировки исключённых групп не участвуют в поиске.
- `items.types` выбирает любой из переданных типов. Допустимы `movie`, `series`, `animatedMovie`, `animatedSeries`, `animeSeries`, `animeMovie`, `game`. `items.tags` фильтрует по ID тегов. `items.rating` задаёт включительные `min` и/или `max` от 1 до 10, причём `min ≤ max`. При активном диапазоне произведения без оценки исключаются.
- `collections.types` фильтрует по типам `custom`, `franchise`, `tag`, `feature`. `collections.authorIds` фильтрует по ObjectId авторов. В фильтрах коллекций и тегов `allOf` требует все значения, `anyOf` — хотя бы одно, `noneOf` — отсутствие каждого. У коллекции один тип и максимум один автор, поэтому несколько значений в `allOf` по одному атрибуту дают пустой результат. Коллекции без автора проходят `noneOf` по авторам. Переданный список содержит хотя бы одно уникальное значение. Для списков ObjectId максимум 100 значений, регистр не учитывается.
- `sort` содержит обязательный `type` и необязательный `direction` (`asc` или `desc`). Для произведений доступны `relevance`, `title`, `releaseDate`, `rating`; для коллекций — `relevance`, `title`, `updatedAt`; для пользователей — `relevance`, `displayName`. По умолчанию `relevance desc`. Для `title` и `displayName` направление по умолчанию `asc`, для остальных — `desc`. Сортировка по названию использует `sort.language` (`ru` по умолчанию или `en`) и второй перевод при отсутствии выбранного. Неизвестные даты релиза и оценки остаются в конце. При равенстве явной сортировки используется ID.
- Для продолжения отправляется то же тело с `cursor` из предыдущего `nextCursor`. Курсор привязан к тексту, лимиту, выбранным группам, действующим фильтрам и сортировкам. Для нового поиска поле опускается.

Ответ `200` всегда содержит три массива карточек и курсор:

```json
{
  "items": [],
  "collections": [],
  "users": [],
  "nextCursor": null
}
```

| Группа          | Поля карточки                                                  |
| --------------- | -------------------------------------------------------------- |
| `items[]`       | `id`, `type`, `title: {ru,en}`, `media: [{src,language,type}]` |
| `collections[]` | `id`, `type`, `title: {ru,en}`, `media: [{src,language,type}]` |
| `users[]`       | `id`, `username`, `displayName`, `avatarUrl: string \| null`   |

UI показывает секции в порядке `items → collections → users` и сохраняет порядок карточек внутри секций. В каждой активной группе дополнительное поисковое совпадение определяет наличие следующей порции. Доступны до 10 000 совпадений на группу. Исчерпанные и исключённые группы возвращают пустой массив. `nextCursor` — строка, пока хотя бы у одной группы есть продолжение, иначе `null`. Если карточка исчезла из MongoDB, массив может быть короче лимита или пустым при наличии курсора.

Meilisearch ищет произведения по названиям RU/EN, aliases и описаниям RU/EN, коллекции — по названиям и описаниям RU/EN, пользователей — по username и displayName. Явная сортировка применяется перед правилами текстовой релевантности. Допуск опечаток включается с пяти символов, второй опечатки — с девяти. Обратная релевантность обходит индекс пакетами по 500 ID и выбирает порцию по возрастанию `_rankingScore`, затем по ID. Этот путь может быть значительно дороже обычной выдачи.

Ошибки сохраняют формат `{error:{code,message,details,requestId}}`. `400 BAD_REQUEST` означает некорректное тело, фильтр или курсор, `403 FORBIDDEN` — отклонение CSRF-проверкой, `429 TOO_MANY_REQUESTS` — ограничение частоты, `503 HTTP_503` — отсутствие отметки готовности или сбой зависимости. Ошибка активной группы завершает весь запрос.

Синхронизация BullMQ запускается при старте и раз в пять минут с дедупликацией. MongoDB возвращает актуальные публичные карточки в порядке найденных ID. Между запросами нет единого снимка, поэтому обновления и удаления в индексе могут менять состав и порядок следующих порций.

## Правила каталога и рекомендаций

Анонсы по умолчанию участвуют в обычном каталоге. Личные статусы и «Не рекомендовать» не исключают произведения без явно выбранного условия. Скрытые коллекции также доступны по умолчанию, пользовательские коллекции участвуют в прямом поиске без условия допуска на главную. В рекомендательном режиме исключение «Не рекомендовать» обязательно.
