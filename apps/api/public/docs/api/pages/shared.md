# Общие операции страниц

[Индекс покрытия](readme.md) · [Требования интерфейса](../../product/pages/shared.md)

## Реализовано

Все восемь операций [UserItemController](../../../../src/endpoints/userItem/controllers/userItemController/core/userItem.controller.ts) вызывают [UserItemService](../../../../src/endpoints/userItem/services/userItemService/core/userItem.service.ts):

| Маршрут                                    | Покрываемое действие                                                                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `QUERY /userItems`                         | Краткие собственные записи по 1–60 ID UserItem в JSON-теле { ids }; без заметки и попыток |
| `POST /userItems`                          | Создать библиотечную запись по `{ itemId, status }`                                       |
| `POST /userItems/skip`                     | Создать skipped на 90 дней по `{ itemId }`                                                |
| `POST /userItems/block`                    | Создать blocked по `{ itemId }`                                                           |
| `PATCH /userItems/:id`                     | Сохранить переданные статус, оценку, избранное и заметку одной операцией                  |
| `DELETE /userItems/:id`                    | Удалить запись вместе с попытками и личными полями                                        |
| `POST /userItems/:id/attempts`             | Добавить попытку, в том числе повторный просмотр                                          |
| `PATCH /userItems/:id/attempts/:attemptId` | Изменить isCompleted, прогресс и даты попытки                                             |

PATCH `/userItems/:id` принимает одно или несколько полей; пропущенные сохраняются. Оценка — целое число 1–10 или `null` для очистки; заметку также можно очистить через `null`.

`:id` — ID UserItem, а не Item. Все семь изменяющих операций возвращают 204 без тела, включая создание и работу с попытками. Прогресс измеряется в минутах, процентах 0–100 или числе полностью просмотренных серий (episode только для сериальных типов). Доступ ограничен владельцем. Оценка, избранное и заметка требуют созданной записи; `POST` принимает статус явно. Planned и blocked сохраняют историю, но не допускают новых попыток; skipped требует пустых личных полей и истории. Подробности — в [контракте библиотеки](../contracts/librarySpec.md).

Регистрация, вход, восстановление и refresh уже реализованы; точные маршруты перечислены в [настройках и формах доступа](settings.md). Отдельного backend для окна входа, предупреждения об уходе или состояния загрузки не требуется.

## Дальнейшая работа

[Задачи и вопросы](../../todos/pages/shared.md#shared)

Для гостя личные действия требуют входа. Операция выполняется только после явного действия пользователя.

Исключения хранятся в [UserItem](../../../../src/entities/userItem/schemas/userItem.schema.ts): skipped действует 90 дней, blocked бессрочный и может сохранять прежние данные. Просроченный skipped исключается из чтения до фоновой TTL-очистки. UserRecommendationState удалён из кода; показы не записываются. UserItemService обновляет ItemStats и связанные счётчики оценок SiteStats в одной транзакции с личной записью. Профиль вкусов и журнал действий не обновляются; HTTP-выдача статистики остаётся в [задачах произведения](../../todos/pages/item.md#item), история — в [задачах профиля](../../todos/pages/accountAndLibrary.md#profile).

## Какие ID хранит клиент

| ID              | Где используется                                             |
| --------------- | ------------------------------------------------------------ |
| Item            | Карточка каталога, создание UserItem, включение в Collection |
| UserItem        | Изменение личной записи, попытки, краткое QUERY-чтение       |
| Collection      | Метаданные, состав и реакция на подборку                     |
| Блок Collection | PATCH структуры и указание группы включения                  |

Эти ID не взаимозаменяемы. Сейчас POST /userItems не возвращает созданный ID, а QUERY /userItems принимает только уже известные ID UserItem. Поэтому клиент с одним Item ID не может замкнуть сценарий «создать → прочитать → редактировать» через существующие ответы. Недостающее чтение по Item относится к LIB-01; его контракт ещё предстоит определить.
