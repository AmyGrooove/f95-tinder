## Текущее покрытие

| Сценарий                               | Контракт                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Источник — коллекция                   | [`QUERY /collections/:id/items`](../contracts/collectionsSpec.md#выдача-item) доступен гостю и вошедшему зрителю, в том числе для ранее скрытой им коллекции.            |
| Источник — своя библиотека по статусам | [`QUERY /users/:id/library`](../contracts/librarySpec.md#публичный-список-библиотеки) принимает ID владельца и фильтр `statuses`.                                        |
| Краткий просмотр                       | Карточки источников содержат базовые данные кандидата. Дополнительные сведения доступны через [`GET /items/:id`](../requestFlows/catalog.md#item).                       |
| Сравнение и итог                       | Клиент сравнивает кандидатов по правилу «победитель остаётся» и показывает итог. Состояние хранится на клиенте. Сравнения не записываются в библиотеку или рекомендации. |

При чтении коллекции клиент по умолчанию передаёт `isItemStatusFilteringEnabled: true`. Для вошедшего зрителя API исключает `completed`, `dropped` и `blocked` до пагинации. Чтобы отключить исключения, клиент передаёт `false` или опускает поле. `isPersonalFilteringEnabled` для Баттла опускается.

Для продолжения клиент повторяет параметры запроса и передаёт `nextCursor` предыдущей страницы как `cursor`. Перед стартом он фиксирует два или более уникальных ID в порядке выдачи. Изменение источника после старта не меняет этот набор.
