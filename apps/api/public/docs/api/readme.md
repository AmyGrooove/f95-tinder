## Как проходит запрос

[«Эндпоинты API»](endpoints.md) — каталог продуктовых и служебных маршрутов с доступом и ссылками на отдельные схемы, примеры и ошибки. Наглядный формат, общие обозначения и правила актуализации описаны в разделе [«Как проходят запросы»](requestFlows/readme.md). Обновляйте каталог и затронутые схемы вместе с маршрутами и общими фоновыми обработчиками.

В [AppModule](../../../src/app/app.module.ts) подключены AuthModule, AccountModule, UserItemEndpointModule, CollectionEndpointModule, SearchEndpointModule и TagEndpointModule. Контроллер определяет метод и путь, принимает DTO и cookie, вызывает сервис и формирует HTTP-ответ. Глобальный [ValidationPipe](../../../src/app/functions/configureApplication/core/configureApplication.ts) преобразует входные DTO и отклоняет неизвестные поля. Составные сегменты путей пишутся в camelCase; у этих маршрутов нет общего префикса или выбранной версии.

Сервисы `endpoints/*/services` выполняют пользовательскую операцию: проверяют доступ и бизнес-правила, координируют репозитории и транзакции, явно отображают результат в response DTO. Репозитории `entities/*/services` работают со своей моделью MongoDB. Они экспортируются модулем сущности; репозиторий не определяет HTTP-ошибки и не открывает транзакцию вместо вызывающего сервиса.

Защищённые операции используют cookie `__Host-accessToken`, проверку JWT и серверной сессии; проверки выполняются в сервисах конкретных операций. Наличие JWT само по себе не заменяет проверку сессии. Обновление токенов использует `__Host-refreshToken` и атомарное сравнение сохранённого хеша. Cookie изменяются через SecurityCookieService. Отдельный Bearer AccessTokenGuard не заменяет эту схему. Подробности — в [контракте](contracts/accountAndAuthSpec.md#токены-и-проверка-доступа) и [security context](../../../agents/security.md).

Многодокументные изменения подборки и изменения библиотеки с чтением и обновлением попыток выполняются через MongoTransactionService. Его session явно передаётся участвующим запросам. Удаление UserItem физически удаляет запись вместе с попытками; удаление Collection только выставляет deletedAt. Единого автоматического поведения удаления для всех сущностей нет.

## Как связаны данные

`Item` — единая карточка произведения; EItemType содержит семь типов видео и игр. Точные характеристики хранятся в общих полях и блоках movie/series/game. Tag задаёт справочник категорий, TagItem — связь тега с конкретным Item. Полный список полей и связей — в [сущностях](entities.md).

`UserItem` — личная запись пользователя о произведении: статус, оценка, избранное, заметка и история попыток. Пара пользователь/Item уникальна. Семь статусов включают skipped на 90 дней и бессрочный blocked, вне обычной библиотеки. Попытки содержат isCompleted вместо status; их изменения не меняют статус UserItem. Установка completed отмечает последнюю попытку завершённой. QUERY /userItems возвращает краткие собственные записи по ID UserItem; чтения по Item и полного чтения библиотеки пока нет.

`Collection` — публичная подборка. Пользовательские подборки имеют ручной состав; сайтовые подборки тегов автоматически следуют прямым назначениям TagItem. Она хранит метаданные и порядок блоков group/text; ItemCollection отдельно хранит Item, groupId, позицию и заметку включения. UserCollection хранит реакции на саму подборку. Состав подборки и библиотека UserItem независимы: включение фильма в подборку не добавляет его в библиотеку.

При редактировании подборки клиент передаёт version. Сервис проверяет автора, итоговые блоки и ссылки на группы; репозиторий условно обновляет документ с совпавшей версией, а изменения состава выполняются в той же транзакции. Устаревшая версия даёт 409. Чтение состава публичное и возвращает порцию Item в сохранённом порядке вместе с блоками текущей порции, без ID групп и позиций включений. Курсор привязан к ID и версии подборки.

## Рекомендации

[RecommendationsService](../../../src/endpoints/recommendations/services/recommendationsService/index.ts) подключён как внутренний сервис, без HTTP-контроллера рекомендаций. Полная персонализация остаётся в [плане реализации](../todos/recommendations/implementationPlan.md).

| Операция в коде                     | Назначение и границы                                                                                        |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| readPopularItemIds / readNewItemIds | ID одного типа, по умолчанию до 20; общий отбор по тегам, библиотеке, рейтингу и запретам                   |
| readFallbackItemIds                 | До 100 ID на выбранный тип, целевое смешивание 60% популярных и 40% новинок, без дублей; чередование типов  |
| readFallbackItems                   | Краткие карточки по fallback-списку, только постеры в media                                                 |
| readFallbackPage                    | Продолжение по Redis-списку: limit 10/20/50, по умолчанию 20, TTL 10 минут без продления |

Эти методы принимают access-токен; сервис проверяет действующую сессию и пользователя, страну берёт из сессии. Тип будущего find содержит sessionId, но такого метода пока нет; readFallbackPage принимает отдельно токен и только cursor/filter/limit. Это внутренние типы, не готовые транспортные DTO.

Изменения библиотеки сохраняют текущий список и его курсоры до окончания TTL. При чтении каждой порции повторно проверяются текущие ограничения и доступность карточек; позиционные границы порции сохраняются. Запрос без курсора собирает новый список по актуальным данным.

CF/ALS, trainer, хранение моделей, ручные предпочтения и публичный endpoint не реализованы. Старые UserTasteProfile и content-pipeline удалены.

### Как понимать источники и фильтры

- «Популярное» здесь означает рейтинг с поправкой на число оценок: `(n × R + 20 × C) / (n + 20)`, где C — средняя оценка сайта, при её отсутствии 5,5. Нужна хотя бы одна оценка. Это не популярность по недавней активности.
- «Новинка» — Item.releaseDate за последние 90 дней, не в будущем. Оценки не обязательны. Для сезона используется дата первой серии, а не последнего вышедшего эпизода или добавления карточки в каталог.
- Без library-фильтра выбираются произведения вне обычной библиотеки. Явное library={} снимает это ограничение; blocked и действующий skipped исключаются всегда.
- Условия групп тегов соединяются через И; внутри группы allOf/anyOf/noneOf действуют одновременно. Проверяются прямые назначения, родители автоматически не разворачиваются. anyOf=[] означает отсутствие совпадений, а не отсутствие фильтра.
- Границы rating относятся к обычному ItemStats.ratingAverage, а не к ratingScore; нужны сохранённые оценки. Глобальные и совпадающие со страной ItemBan также исключают произведение.

Конец ограниченного fallback-списка не означает конец каталога. Например, старое произведение без оценок не попадает ни в популярное, ни в новинки; при таком каталоге fallback может оказаться пустым. Автоматического третьего источника, ослабляющего эти правила, сейчас нет.
