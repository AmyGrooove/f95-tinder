## Документация API в OpenAPI

Начать с примеров запросов и связей между операциями.

- [ ] Добавить именованные `examples` для `QUERY /users/{id}/library`: первая страница, фильтр по статусу и запрос следующей страницы с курсором.
- [ ] Описать через `links` переход к следующей странице библиотеки: `nextCursor` из ответа передаётся как `cursor` в следующий запрос, если курсор есть.
- [ ] Разложить варианты результатов поиска по `oneOf`, если их структуры различаются. Привязать варианты через `discriminator` к полю `type`, если оно есть в контракте.
- [ ] Добавить примеры ответов с ошибками и описать действия клиента. Начать с истёкшего курсора: показать фактический ответ API и указать, что запрос нужно повторить с первой страницы.
- [ ] Определить иерархию тегов через `parent`, например «Профиль → История». Назначать операциям тег подгруппы. Текущий Swagger UI на `/docs` показывает плоский список, поэтому для дерева проверить поддержку `parent` в интерфейсе документации.
- [ ] Проверить отображение тегов с `kind: badge` и использовать их для операций, которым подходят метки `Beta` или `Admin`. Метка `Admin` дополняет описание требований доступа.
- [ ] Если появится SSE или JSONL, описать каждое сообщение потока через `itemSchema`. Для потока статуса задачи предусмотреть примеры `progress`, `completed` и `failed`.

[Спецификация OpenAPI 3.2.1](https://spec.openapis.org/oas/v3.2.1.html) · [Вложенные теги в Swagger UI](https://github.com/swagger-api/swagger-ui/issues/10897)
