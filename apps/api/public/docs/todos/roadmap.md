# Этапы backend

## Согласованный порядок следующих этапов

1. Реализовать пользовательские эндпоинты каталога: список фильмов без обязательного поискового запроса, [публичную карточку Item](catalog/itemDetails.md), фильтры и справочники тегов и характеристик.
2. Реализовать личную библиотеку: статусы «Запланировано», «В процессе», «Отложено», «Завершено», «Брошено»; независимые оценку, избранное и заметку, а также прогресс просмотра. Маршруты изменения этих данных и попыток уже реализованы; GET-маршруты чтения библиотеки ещё не добавлены.
3. Реализовать стартовые и простые персональные рекомендации, сохранение показов, пропусков и действия «Не предлагать».
4. Реализовать наполнение каталога: сбор фильмов Kodik в S3, формат подготовленного JSON-пакета, проверку и импорт без дублей, согласования, сохранение ручных исправлений и отчёт.

Порядок выбран 21 октября 2026 года. До реализации импорта для разработки и проверки пользовательских сценариев нужен небольшой набор фильмов и связанных справочников в БД, который можно подготовить вручную. На таком наборе можно проверить поведение рекомендаций; оценка их качества требует достаточного объёма реальных данных.

Стандартные разделы библиотеки формируются по статусам. Публичные ручные подборки реализованы отдельным [контрактом](../api/contracts/collectionsSpec.md); приватные списки он не определяет. Полная админка, расписания сбора и embedding также требуют выбора объёма согласно [границам MVP](../product/mvpScope.md). Порядок этапов не заменяет детальные контракты их реализации.

## Возможности, этап реализации которых ещё не определён

В целевых основах предусмотрены следующие возможности, но их полный объём не был отдельно включён в первую версию:

- Сбор новых и изменённых данных из API по расписанию и вручную, а также полный сбор.
- Админка для выгрузок, загрузки подготовленных файлов, согласований и отчётов.
- Генерация и использование embedding произведений. Общее прежнее указание «embeddings отложены» больше не описывает целевую систему; включение этой возможности в первый этап требует выбора объёма этапа.
- Произвольные пользовательские списки.

Эти пункты уточняются при выборе ближайшего законченного этапа после сверки текущей реализации. Их наличие в основах не означает, что весь объём должен быть реализован одновременно.

## Последующие направления

За пределами сохраняемого стартового объёма остаются другие типы Item, автоматический вызов AI API, OAuth, автоматические парсеры сайтов, социальные функции, геймификация и оплата.

## Уточнения по импорту

Конкретные источники, расписания, правила допуска для каждого нового типа Item, формат пакетов JSON, способ передачи контекста нейронке и устройство экранов админки определяются отдельно. Состав входных данных для embedding вынесен в [отдельный вопрос](#входные-данные-embedding).

## Входные данные embedding

Точный состав входных данных для embedding пока не выбран. Он может включать общее описание, теги, алиасы и подходящие поля конкретного типа произведения.

Теги не являются обязательным условием построения embedding. Решение об их включении принимается по тому, насколько они дополняют описание и улучшают результаты сравнения произведений.

## Устройство расширений

Конкретная организация модулей, интерфейсов получения данных, настроек и экранов админки определяется при реализации.
