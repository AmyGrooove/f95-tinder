## Редактор коллекции

- [x] `EDITOR-01`: загрузка обложки автором через [`PUT /collections/:id/poster`](../../api/requestFlows/collections.md#poster).
- [ ] `EDITOR-02`: согласовать сценарий загрузки/редактирования постраничного состава и обработки 409. Подтверждённый пробел: публичный `/items` не возвращает ID блоков, groupId и position включений. GET метаданных содержит ID блоков, но одинаковые или безымянные группы нельзя надёжно сопоставить с порциями состава. Определить минимальное чтение для редактора, сохранив единый PATCH.

Поиск добавляемых произведений — зависимость `SEARCH-01/02`, а не новый поиск внутри редактора. Для превью выбранного произведения нужны публичные данные `ITEM-01`.

### Вопросы API

Выбор типа коллекции, работа с RU/EN, требования к обложке, сохранение формы при конфликте версии и при частично загруженном составе. Очерёдность локальных действий, кнопка сохранения и предупреждение об уходе относятся к клиенту; сервер уже выполняет единый PATCH атомарно. Управление официальными коллекциями обычному автору не предоставляется.

### Проверка результата

Проверять сохранение перестановок и переносов без потери незагруженных включений, конфликты version, уникальность Item, удаление группы и отсутствие изменений библиотеки.

## Коллекция

| ID                    | Состояние | Пробел                                                                                                                                   |
| --------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| COLLECTION-01         | Частично  | Шапка возвращает `author` с публичными данными или `null` для подборки сайта. Общие оценки, избранное и размер состава в ответ не входят |

| Запуск Баттла         | Частично  | Источник состава есть; подготовка набора и остальная ответственность описаны в `BATTLE-01/02`                                            |

- [ ] `COLLECTION-01`: определить расчёт, обновление и чтение общей статистики и полного числа доступных произведений. Публичное представление автора уже возвращается в [GET /collections/:id](../../api/contracts/collectionsSpec.md#реализованное-чтение-подборки).
- [ ] `COLLECTION-02`: определить и реализовать полный личный прогресс X/Y, учитывая удалённые произведения. Не рассчитывать его по одной странице или выдаче с активными фильтрами.

### Вопросы API

Формулы статистики, правила X/Y при удалённых Item, пустые состояния и переход в настройку Баттла. В модели официальность определяется `author=null`; публичный DTO также возвращает null при отсутствующем User, поэтому явный признак официальности требует уточнения контракта. обычные пользовательские маршруты не управляют коллекциями сайта. Административные операции не входят в задачу страницы.

### Проверка результата

Проверять неизменность X/Y и общей статистики при смене страницы/фильтров, гостевое чтение, независимость реакций от библиотеки и отсутствие запрета прямого чтения после скрытия.

### Вопросы интерфейса

При подготовке недостающих контрактов уточняются расчёт общей статистики и личного прогресса, учёт удалённых произведений в X/Y, представление пустых состояний и переход в настройку Баттла. Новые показатели страницы не считаются уже реализованными на основании существующих маршрутов.

### Требования, ещё не покрытые чтением состава

Фильтры, поиск по составу и переключение grouped/flat описаны на [продуктовой странице](../../product/pages/collection.md), но QUERY /collections/:id/items сейчас принимает только cursor и limit. Перед реализацией нужно определить объём этих возможностей и их влияние на курсор, текстовые блоки и общий прогресс. Наличие внутренних фильтров репозитория не означает готового HTTP-контракта.
