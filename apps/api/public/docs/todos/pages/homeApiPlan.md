# Главная Bisky — план разбора API

## Поведение главной

1. «Продолжить просмотр» показывается вошедшему пользователю. Бэкенд одним чтением выбирает первый непустой статус в порядке `inProgress → onHold → planned` среди доступных произведений выбранных типов. Фронт запрашивает порцию этого статуса через то же публичное чтение библиотеки, что и профиль другого пользователя. При `status: null` блок пропускается.
2. «Рекомендации» запрашиваются только после входа. У гостя первый блок — «Новинки».
3. «Новинки» и «Популярное» используют `QUERY /search` без поля `search`, с фильтром типов Item и сортировкой. В новинки попадают фильмы и сериалы, включая сериалы с недавно вышедшей серией. Для фильма дата берётся из `releaseDate`, для сериала — из `series.lastReleasedEpisodeAt` с запасным вариантом `releaseDate`. Учитываются состоявшиеся релизы. Популярное использует текущий `ratingScore`, а при равенстве — число оценок и ID. `QUERY /search` уже имеет совпадающую сортировку `items.sort = "rating"`.
4. После фиксированных блоков идёт дневная лента: факт → 3 коллекции → фича → 3 коллекции → факт → 3 коллекции → фича → 3 коллекции → факт → 3 коллекции. Целевой набор — 15 разных коллекций, 3 факта и 2 фичи. Берём непустые коллекции сайта (`author = null`), типы `tag` и `feature`. Жанровые участвуют в общем пуле. При нехватке отдаём меньше блоков с сохранением порядка и без повторов.
5. Ночной запуск сохраняет один упорядоченный набор на день для всех пользователей. Рабочее время запуска — 03:00 по `Europe/Moscow`. Фронт держит полученный массив до обновления страницы и подгружает содержимое коллекций и фактов по мере необходимости. Для фич бэкенд хранит редактируемый статический массив ID, например `pick`, `battle`, `rating`. Фронт сопоставляет ID с компонентом.
6. Личные скрытия применяются к содержимому блоков главной. Главная передаёт `isPersonalFilteringEnabled: true`. Для вошедшего пользователя обычные блоки исключают `completed`, `dropped` и `blocked`, а скрытая им коллекция пропускается целиком. Дневной массив ID общий. Гостевой просмотр обходится без личных условий. При выключении флага обычные блоки видны полностью. Правила исключения `blocked` и действующих `skipped` в рекомендациях сохраняются. В Search и чтении состава коллекции личные фильтры включаются явно.

## Операции для отдельных чатов

| Метод и путь | Статус и предмет разбора |
| --- | --- |
| `GET /account/library/continue` | Маршрут подключён. [Согласованный контракт](../../api/requestFlows/account.md#library-continue) описывает access cookie, повторяемый `types`, выбор статуса и ошибки. Для первого запроса карточек в `LIB-02` нужны тот же набор типов и те же условия доступности Item |
| `QUERY /users/:id/library` | [Публичный список главной и профиля](../../api/contracts/librarySpec.md#публичный-список-библиотеки). После continue передай полученный статус в `statuses.anyOf` и сохрани тот же набор `types`. Краткий прогресс и ID UserItem доступны владельцу |
| `QUERY /recommendations` | [Маршрут подключён](../../api/requestFlows/catalog.md#recommendations). Карточка включает общую и личную оценки и личный статус. Положение переключателя передаётся через `filter.statuses`. Истёкший снимок даёт `410 HTTP_410` |
| `QUERY /search` | [Публичный поиск](../../api/contracts/searchSpec.md#search) без обязательного текста. Главная выбирает `entities.anyOf: ["items"]` и передаёт `items.sort: "latestReleaseDate"` или `items.sort: "rating"`. Оба запроса используют карточки с оценками и статусом зрителя |
| `GET /home/feed` | [Публичный маршрут подключён](../../api/requestFlows/catalog.md#home-feed). MongoDB хранит единую последовательность на день с границей 03:00 МСК. Крон и первый запрос после простоя используют одну операцию создания. На фронте остаётся подключить загрузку, сопоставление фич и пропуск блоков, чьё содержимое больше недоступно |
| `QUERY /collections/:id/items` | [Публичное чтение состава](../../api/contracts/collectionsSpec.md#выдача-item). Главная выбирает типы, явно включает личную фильтрацию и запрашивает двуязычные метаданные. Скрытая коллекция возвращает `isHidden: true`. Карточки включают общую и личную оценки и статус |
| `GET /facts/:id` | Новый публичный маршрут подключён в рабочем дереве. При валидном ObjectId отвечает `200 {id, text: {ru, en}, sourceUrl}` с `Cache-Control: no-store`. Ключи обоих переводов присутствуют, каждое значение и `sourceUrl` допускают `null`. Некорректный ID даёт 400, отсутствующий факт — 404. Для ленивой загрузки из ленты достаточно текущего чтения. Зафиксировать ответы, включая объявленные 429/500, обработку 404 на фронте и синхронизацию каталога маршрутов и покрытия |

Пути и названия новых полей в этом плане используются для обсуждения. Действующее поведение устанавливается по исходникам, включая локальные изменения. В [описании главной](../../product/pages/home.md) пока описаны гостевые рекомендации, два независимых переключателя скрытия и прежний состав блоков. Для этих разборов действует поведение из пп. 1–6. Один `isPersonalFilteringEnabled` выражает совместное переключение условий. Если фронту по-прежнему нужны смешанные состояния (например, показывать завершённое, но скрывать заблокированное), это отдельное решение для согласования в контрактах поиска и состава коллекции. В общий дневной массив личные условия не входят.

## Результат каждого отдельного чата

Изучить текущий код, применимые [правила API](../../../../AGENTS.md), [контекст эндпоинтов](../../../../agents/endpoints.md), нужные инструкции Amy Agents Guidelines и потребителей своего маршрута. Изучить и переиспользовать подходящие объекты из [`src/shared/functions/checks`](../../../../src/shared/functions/checks) и [`src/infrastructure`](../../../../src/infrastructure). Следовать существующему кодстайлу и формату API, текущим именам, структуре контроллеров, сервисов и DTO, формату ошибок, Swagger, сессиям, проверкам и курсорам проекта.

В ответе по-русски коротко показать:

1. Полный запрос. Метод и путь, параметры пути и строки запроса, тело, относящиеся к контракту заголовки и cookie, доступ. Для всех полей указать типы, обязательность, ограничения и значения по умолчанию.
2. Полный ответ. Все поля, включая вложенные, значения `null`, пустые результаты, пагинация, относящиеся к контракту заголовки и ошибки. Для доработки раскрыть все существующие поля и ветви, в том числе обычный ответ вне главной. Для карточек сверить проекцию с требованиями к общей и личной оценкам и статусу, указать источник недостающих данных.
3. Короткие примеры HTTP-запроса и ответа. Для изменяемого маршрута показать обычный сценарий и сценарий главной, если они различаются.
4. Какие дополнительные правки нужны и зачем. Указать связанные модули, данные, фоновые задачи, индексы, открытые вопросы и документацию только по существующим зависимостям. Отметить, что подтверждено кодом и что предлагается.

Отдельные чаты готовят контракт и список изменений для согласования. Работа в этих чатах ограничена чтением production-кода и документации своего маршрута. Правила API требуют отдельного разрешения даже для просмотра тестов и Storybook. Согласование конкретного контракта предшествует реализации.
