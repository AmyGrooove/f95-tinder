# Кодик — распределение данных по модели каталога

Проект распределения всех 59 полей из [fields.md](fields.md). Названия и смысл входных полей взяты из предоставленного пользователем списка; API независимо не проверялся. Текущие поля и enum сверены с исходниками `apps/api`.

Документ не реализует импорт и не расширяет этап до сериалов. Новые поля и группы ниже являются предложениями, а не уже внесёнными изменениями схем.

## Общие правила

- Произведение хранится в `Item` с `type: movie`. Отдельная сущность Movie не создаётся.
- В movie входят только фильмы, включая документальные. Сериалы, мини-сериалы и другие многосерийные произведения, включая документальные сериалы, исключаются. Мультфильмы, анимационные фильмы и аниме также исключаются, в том числе полнометражные. Их исключение из этого типа не является постоянным запретом на импорт с будущим подходящим типом.
- Внешнее обозначение movie недостаточно для допуска. До применения данных проверяется соответствие этой границе; неоднозначная классификация остаётся на разборе и не публикуется автоматически как movie.
- Тег обозначает понятие; назначение произведению хранится в `TagItem`. Feature определяет характеристику, тип и единицу; значение произведения хранится в `ItemFeature`.
- Группа классифицирует Tag или Feature, но не хранит значение и не заменяет связь между сущностями.
- Каждый факт имеет одно основное место хранения. Его исходное представление отдельно сохраняется в выгрузке источника в S3.
- Пропуски не заменяются нулём, пустой строкой или выдуманным переводом. Отсутствующее значение не стирает ранее известное.
- Ручные исправления сохраняются. Неразрешённые расхождения попадают в отчёт.
- Язык определяется до заполнения RU/EN. Название поля `title_en` само по себе не подтверждает язык текста.
- Назначаются существующие канонические теги и features. Новые определения и изменения иерархии требуют согласования по [основам](../../product/foundations/catalogWorkflow.md).

## Теги

| Поле Kodik                       | Группа ETagGroup                                             | Назначение                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `material_data.countries`        | `COUNTRY = country`                                          | Канонические страны; соответствия названий разрешаются через справочник                                                              |
| `material_data.genres`           | По смыслу: `GENRE`, `FORMAT`, `STYLE`, `AUDIENCE`, `KEYWORD` | Нормализация понятий вместо буквального копирования классификации источника; для жанров и поджанров предлагается единая группа genre |
| `material_data.all_genres`       | Те же группы                                                 | Дополнительные кандидаты; совпадения с genres не создают повторные назначения                                                        |
| `material_data.drama_genres`     | Те же группы                                                 | Для допущенного фильма                                                                                                               |
| `material_data.mydramalist_tags` | Преимущественно `KEYWORD = keyword`; другие группы по смыслу | Например, темы и сюжетные мотивы; новый термин не создаётся автоматически                                                            |

Существующие значения enum: `genre`, `subgenre`, `keyword`, `format`, `style`, `audience`, `country`, `originalLanguage`. Целевое упрощение — объединить genre и subgenre в группу genre: более узкое понятие определяется отношением к другому жанру через `Tag.parents`. Код enum этим документом не изменён; перед удалением subgenre нужно проверить существующие записи и потребителей. Новая группа для этого списка не требуется. Язык оригинала не выводится из языка названия.

Иерархия жанров задаётся через `Tag.parents`, а не одним значением group. Один канонический тег назначается произведению один раз, даже если пришёл из нескольких списков. Правило заполнения обязательного `TagItem.relevanceScore` определяется отдельно; источник не предоставил оценку релевантности в этом списке.

## Features

После объединения Feature с Tag целевая модель описана в [полях Item и правилах тегов](../../product/foundations/catalogKeys.md). Таблицы ниже сохраняют прежние имена характеристик как материал для будущего импортёра: releaseDateWorld соответствует Item.releaseDate, minimalAge — нормализованному Item.ageRestriction, длительности и счётчики — блокам movie/series/game, releaseStatus и hasDefinedEnd — тегам. Это не действующий импортёр; окончательное сопоставление, нормализация и наполнение вынесены в TODO.

| Поле Kodik                     | Ключ Feature       | Группа EFeatureGroup    | valueType | unit              | Правило                                                                                     |
| ------------------------------ | ------------------ | ----------------------- | --------- | ----------------- | ------------------------------------------------------------------------------------------- |
| `year`                         | `releaseYear`      | `RELEASE = release`     | `number`  | `null`            | Кандидат на год выпуска                                                                     |
| `material_data.year`           | `releaseYear`      | `RELEASE = release`     | `number`  | `null`            | То же значение, не отдельная feature; расхождения разрешаются явно                          |
| `material_data.premiere_world` | `releaseDateWorld` | `RELEASE = release`     | `date`    | `null`            | Единый целевой ключ для мировой премьеры; равнозначная releaseDate параллельно не создаётся |
| `material_data.duration`       | `duration`         | `TECHNICAL = technical` | `number`  | `MINUTE = minute` | Продолжительность фильма в минутах                                                          |
| `material_data.minimal_age`    | `minimalAge`       | `null`                  | `number`  | `null`            | Возраст в годах; не смешивается с балльным рейтингом и не выводится из MPAA                 |
| `material_data.all_status`     | `releaseStatus`    | `RELEASE = release`     | `string`  | `null`            | После согласования внутреннего набора статусов и проверки смысла источника                  |
| `material_data.drama_status`   | `releaseStatus`    | `RELEASE = release`     | `string`  | `null`            | Кандидат для допущенного фильма                                                             |

Существующие группы: `release`, `technical`, `financial`, `production`. Последние две для выбранных выше значений не нужны. Группа не задаёт валидацию: импорт должен отдельно проверять соответствие значения `Feature.valueType`, допустимые диапазоны и формат дат. Для дат без времени требуется единое правило хранения, исключающее смещение календарного дня.

`releaseYear` сохраняется отдельно: год может быть известен без точной даты. Если источник передал только год, полная дата не выдумывается. Перед использованием уже существующей releaseDate проверяются её определение и данные: если она обозначает мировую премьеру, выбирается один ключ с явным переносом существующих ссылок; если другой факт — значения не объединяются.

## Выбор значений и объединение кандидатов

Правила ниже задают проектное поведение нормализации, а не гарантии API Kodik. Сначала сохраняется ручное исправление, затем используются данные выбранного источника; AI не подменяет отсутствующие факты. Применять приоритеты можно только к записям, сопоставленным с одним произведением.

| Данные          | Правило выбора                                                                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Название RU     | Первый подходящий по языку и смыслу кандидат: material_data.title → title. Альтернативные корректные варианты сохраняются в aliases. Если значения указывают на разные произведения, выбор откладывается и создаётся конфликт        |
| Название EN     | Проверенный material_data.title_en; при отсутствии — однозначный английский кандидат из other_titles_en, title_orig или других названий. Несколько равноправных кандидатов не выбираются по случайному порядку                       |
| Алиасы          | Объединение всех подходящих вариантов названия, удаление пустых значений, повторов и точных совпадений с принятыми title. Оригинальное написание сохраняется; транслитерация и перевод не создаются автоматически                    |
| Описание        | Используется material_data.description после определения языка. Отсутствующее описание остаётся незаполненным; содержательные противоречия попадают в отчёт                                                                          |
| Год             | Совпадающие year и material_data.year дают одно значение releaseYear. При расхождении текущее значение сохраняется, для нового Item значение остаётся незаполненным до разрешения конфликта                                          |
| Статус          | После проверки семантики все применимые поля приводятся к одному внутреннему набору releaseStatus. До такой проверки остаются в исходных данных. Противоречащие статусы не выбираются по расположению поля                           |
| Жанры и темы    | Подходящие списки объединяются через канонические соответствия; каждый Tag назначается один раз. Противоречащие назначения отражаются в отчёте, новые определения проходят согласование                                              |
| Основной постер | Ручной выбор сохраняется. Иначе среди проверенных подходящих изображений: poster_url → drama_poster_url для соответствующего фильма. Выбранный постер — первый элемент с type:poster в media; остальные пригодные постеры идут далее |
| Кадры           | Оба списка объединяются после проверки соответствия произведению; повторы URL удаляются. Кадры хранятся с type:screenshot и не участвуют в выборе постера                                                                            |

Приоритет поля служит правилом выбора кандидата, но не разрешает перезаписывать ручные исправления или игнорировать явные конфликты. Список media возвращается с сохранением порядка, иначе правило основного постера не будет работать. Отдельное поле primaryPoster сейчас не предлагается.

## Источники и внешние идентификаторы

`Source` описывает сервис, а `SourceItem` связывает его внешний объект с Item. Для всех строк ниже группы тегов и features не применяются.

| Поле Kodik      | Source.key    | Назначение                                                                                             |
| --------------- | ------------- | ------------------------------------------------------------------------------------------------------ |
| `id`            | `kodik`       | `SourceItem.externalId`, исходный ID целиком, включая префикс                                          |
| `kinopoisk_id`  | `kinopoisk`   | Отдельный SourceItem с внешним ID Кинопоиска                                                           |
| `imdb_id`       | `imdb`        | Отдельный SourceItem с ID IMDb, включая `tt`                                                           |
| `mdl_id`        | `mydramalist` | Отдельный SourceItem с ID MyDramaList                                                                  |
| `shikimori_id`  | `shikimori`   | Отдельный SourceItem с ID Shikimori                                                                    |
| `worldart_link` | `worldArt`    | Кандидат на SourceItem.externalUrl; до определения устойчивого externalId остаётся в исходной выгрузке |

Идентификаторы хранятся строками. Для World Art сначала определяется идентичность объекта с учётом раздела сайта и проверяется нормализация URL. Полный URL не закрепляется как окончательный externalId без этой проверки; SourceItem без обязательного externalId не создаётся. Источники сначала должны существовать в справочнике; сейчас в `import/sources` подготовлен только [Kodik](../../../../../import/sources/kodik.json).

`SourceItem.item` может быть null до сопоставления. Несколько записей Kodik могут относиться к одному Item. Совпадение названия само по себе не является основанием объединить карточки. Внешние ID не становятся тегами, features или полями Item.

Сам факт получения идентификатора IMDb через Kodik не означает прямого обращения к IMDb: происхождение сведений сохраняется в исходной выгрузке и будущем отчёте импорта. Текущая схема SourceItem отдельной цепочки происхождения не хранит.
