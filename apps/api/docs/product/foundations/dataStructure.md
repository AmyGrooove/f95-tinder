# 1. Структура данных

[Все основы проекта](../foundations.md) · [Следующий пункт: наполнение каталога](catalogWorkflow.md)

Документ фиксирует согласованные принципы, а не состояние их реализации.

Правила групп Tag, поля Item и ключи ItemRelationRole и Source и их применимость к типам Item зафиксированы в [справочнике ключей каталога](catalogKeys.md).

## Компоненты описания произведения

### Произведение — Item

Item — единая сущность произведения для всех типов контента. Название, описание, тип произведения и медиаматериалы хранятся в Item. Вид произведения задаётся полем `type`; отдельных сущностей Movie, Game или AnimeMovie нет.

Основные языки метаданных — русский и английский. Отсутствие перевода допустимо и не требует выдумывать значение.

Начальный перечень типов открыт для дальнейшего расширения:

| Тип              | Содержимое одного Item                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| `movie`          | Фильм, включая документальный; анимационные фильмы и аниме сюда не входят                              |
| `series`         | Один сезон сериала, включая документальные и мини-сериалы; мультсериалы и аниме-сериалы сюда не входят |
| `animatedMovie`  | Мультфильм или анимационный фильм, кроме аниме                                                         |
| `animatedSeries` | Один сезон мультсериала, кроме аниме                                                                   |
| `animeSeries`    | Один сезон аниме-сериала                                                                               |
| `animeMovie`     | Аниме-фильм                                                                                            |
| `game`           | Одна игра для всех платформ; DLC пока считаются её частью и не создают отдельных Item                  |

Каждый сезон имеет собственные статус, оценку, избранное и попытки просмотра через UserItem. Общий Item на весь сериал не создаётся. Сезоны объединяются через Collection типа `franchise` и CollectionItem. Франшиза может содержать произведения разных типов; её состав сам по себе не определяет, какой Item является следующим сезоном.

Продолжения, приквелы, спин-оффы и другие смысловые связи сезонов задаются существующей Relation. Каждая её сторона ссылается на Item и роль из ItemRelationRole; роль описывает соответствующее произведение относительно другого. Для определения следующего сезона используется прямая связь продолжения между соседними сезонами, а для ответвления — соответствующая роль спин-оффа. Collection объединяет франшизу, Relation уточняет связь конкретных произведений. first и second не задают направление хронологии сами по себе. Наличие связи не устанавливает обязательный порядок потребления автоматически.

Роли группируются как `all` (общие для видео и игр, например сиквел), `video` или `game`; `null` означает, что группа не указана. Группа роли не ограничивает типы Item, участвующие в Relation.

DLC не имеют отдельных пользовательских статусов и оценок. Отдельный учёт прохождения и оценки DLC в текущий объём не входит.

Версии одной игры для разных платформ объединяются в один Item. Статус, оценка, избранное и попытки прохождения относятся к игре целиком, без отдельных записей для платформ.

### Характеристики конкретного типа

Характеристики, зависящие от типа произведения, хранятся в блоках Item и тегах. Продолжительность фильма находится в movie.duration в минутах, а страна — в тегах соответствующей группы.

### Теги

Смысловые признаки без отдельных значений: киберпанк, одиночество, нелинейный сюжет.

Одному смыслу соответствует один канонический Tag независимо от типа Item. Например, одна и та же тема одиночества в фильме и игре использует общий тег, а не отдельные теги для каждого типа контента. Название само по себе не определяет тождество: совпадающие названия с разным смыслом относятся к разным Tag. Смысл уточняется описанием; алиасы обозначают то же понятие.

Общий Tag позволяет связывать содержательные признаки разных типов произведений, но не задаёт одинаковый вес этих признаков в рекомендациях. Специфические свойства типов сохраняют собственный смысл; совпадение названий жанров не делает их автоматически сопоставимыми.

ItemTag связывает произведение с тегом. Его `relevanceScore` от 0 до 1 задаёт выраженность признака в произведении: 0 означает нулевую выраженность, 1 — максимальную. Это свойство произведения, а не уверенность разметчика, вероятность правильности связи или предпочтение пользователя. Отсутствие ItemTag означает отсутствие зафиксированной связи и само по себе не доказывает отсутствие признака.

Единые правила получения и калибровки промежуточных значений ещё предстоит определить. Одинаковые числа у разных тегов или типов Item не считаются автоматически сопоставимыми. Для платформ тег фиксирует доступность игры на соответствующей платформе с `relevanceScore=1`.

Доступные платформы игры задаются тегами группы `platform`, например PC, PlayStation 5 и Xbox Series X/S. Каждая платформа — отдельный Tag, связанный с игрой через ItemTag; у одной игры может быть несколько платформ. Эти теги описывают доступность игры, а не наличие устройств у пользователя.

### Точные поля Item и теги

Feature и ItemFeature удалены из production-кода. Общие releaseDate и ageRestriction находятся в Item; nullable-блок movie содержит duration, series — episodeCount, releasedEpisodeCount, episodeDuration и nextEpisodeAt, game — mainStoryDuration и fullCompletionDuration. Типы movie/animatedMovie/animeMovie используют блок movie, три сериальных типа — series, игры — game. Документная валидация запрещает несовместимые блоки и releasedEpisodeCount выше известного episodeCount.

Оценки времени игры относятся к базовой игре без DLC. Неизвестные поля внутри блока отсутствуют, а неизвестные или неприменимые блоки равны null. Нулевое releasedEpisodeCount — известный факт, а не неизвестное значение. Счётчики относятся к отдельному сезону и не описывают личный прогресс.

Категории и диапазоны представлены Tag/ItemTag. Состояние выпуска использует releaseStatus: announced, ongoing, released, cancelled. Конечность игры — hasDefinedEnd: true или false, без значения по умолчанию. Год может быть известен без даты и представлен releaseYear. Возраст нормализуется в EAgeRestriction: 0, 6, 12, 16, 18; преобразование исходных рейтингов требует отдельного согласования.

Для диапазонов и фиксированных значений стабильный Tag.key задан в TAG_GROUP_RULES. Числовые границы не копируются в БД. Точная длительность и производный диапазон — один исходный факт и категория для подбора; в профиль вкуса входит только Tag, без отдельного числового предпочтения. При изменении точного значения будущий импортёр должен заменить производный тег; синхронизация ещё не реализована.

UserItemService сохраняет ограничения библиотеки через прямые теги hasDefinedEndFalse, releaseStatusAnnounced и releaseStatusOngoing. Проверка выполняется в той же транзакции, что и пользовательское действие. Неизвестные метаданные не запрещают ручное завершение; исторические флаги не переписываются.

### Embedding

Производное векторное представление произведения для поиска похожих произведений и рекомендаций. Оно строится на основе содержательных данных произведения и может пересчитываться при изменении данных или способа построения.

## Жанры, алиасы и иерархия

Одному понятию соответствует один канонический жанр с постоянным идентификатором и основным отображаемым названием.

Алиасы — альтернативные названия того же понятия. Например, у жанра «Научная фантастика» могут быть алиасы Sci-Fi, Science Fiction и НФ. Пользователю отображается основное название; алиасы помогают поиску, нормализации данных из разных источников и распознаванию общих признаков для рекомендаций.

Произведение связывается с каноническим жанром по его идентификатору. Алиасы принадлежат жанру и не создают дополнительные признаки или дополнительный вес в рекомендациях.

Поджанр является отдельным, более узким понятием со связью с более широким жанром. Например, внутри классификации Bisky можно использовать цепочку «Фантастика → Научная фантастика → Киберпанк». Это пример внутренней классификации, а не требование повторять структуру внешнего источника.

Определение жанра помогает отличать новое понятие от синонима существующего. Нейронка может предлагать новые жанры и связи в иерархии; их применение требует согласования, как описано в [процессе наполнения](catalogWorkflow.md#согласование-изменений).

Связь с более широким жанром позволяет учитывать его при поиске без отдельного назначения произведению всех предков. Рекомендации должны учитывать зависимость этих признаков, чтобы несколько уровней одной ветки не давали случайного многократного усиления.

## Правила

- Ключи справочников остаются расширяемыми строковыми идентификаторами. Для ключей, которые явно обрабатывает программная логика, используются именованные enum в коде; они не задают закрытый перечень допустимых записей БД.
- Каждый факт имеет одно основное место хранения. Точные значения хранятся в Item; производные диапазонные теги определяются только из этих значений. Их синхронизация обязательна при импорте и изменении метаданных.
- Неполные данные допустимы. Описание произведения можно постепенно обогащать; неизвестное значение не заменяется нулём.
- Исходные данные сохраняются отдельно от embedding. Использование этих данных при его построении не считается дублированием фактов в модели.
- Теги и поля Item доступны поиску и рекомендациям напрямую, независимо от embedding.
- Точные ограничения, например «фильм до двух часов», проверяются по соответствующим полям Item.

## Что уточняется позднее

Точный состав входных данных для embedding пока не выбран. Он может включать общее описание, теги, алиасы и подходящие поля конкретного типа произведения.

Теги не являются обязательным условием построения embedding. Решение об их включении принимается по тому, насколько они дополняют описание и улучшают результаты сравнения произведений.

Для новых характеристик выбирается представление через тег или feature, сохраняя правило единственного места хранения факта. Добавление типа произведения не требует отдельной сущности для его карточки.
