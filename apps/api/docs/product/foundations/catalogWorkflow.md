# 2. Наполнение и автономная работа каталога

[Все основы проекта](../foundations.md) · [Предыдущий пункт: структура данных](dataStructure.md) · [Следующий пункт: система рекомендаций](recommendations.md)

Документ фиксирует согласованный процесс, а не состояние его реализации. Конкретные источники и технические форматы выбираются отдельно.

## Общий процесс

1. К каждому типу Item подключаются подходящие источники данных.
2. Сборщик получает данные из API источников и сохраняет исходные ответы в S3.
3. Нейронка получает исходные данные вместе с нужным контекстом существующего каталога, нормализует и сопоставляет их, предлагает дополнения и исправления.
4. Результатом обработки становится пакет подготовленных JSON-файлов: произведения с точными полями Item, теги, источники, связи и необходимые изменения.
5. Приложение проверяет пакет, применяет автоматические изменения и выделяет действия, требующие согласования.
6. После применения данных приложение создаёт или пересчитывает embedding по принятому составу входных данных и формирует отчёт.

Пока AI-обработка запускается вручную: пользователь получает исходные данные, передаёт их нейронке и загружает подготовленные JSON в приложение. В дальнейшем этот шаг автоматизируется через API с сохранением того же формата обмена.

## Сбор данных

Нужны два режима:

- Регулярный сбор новых и изменённых записей, если источник позволяет получать такие изменения.
- Полный сбор для инициализации каталога и периодической актуализации всех данных.

Оба режима доступны по расписанию и вручную. Интервалы могут зависеть от типа произведений и источника. Еженедельный сбор обновлений и ежегодный полный сбор обсуждались как примеры, а не фиксированные требования.

Исходные данные сохраняются отдельно от нормализованного результата, вместе с информацией об источнике.

## Контекст и задачи нейронки

Вместе с исходными данными передаётся подходящая часть текущего каталога: существующие произведения с точными полями Item, привязки к источникам, теги, алиасы и связи. Передавать весь каталог при каждой обработке необязательно.

Согласованные теги находятся в [групповых JSON-словарях](../../research/tagDictionary). Их формат `{group,tags,tagRelations}`, смысловые границы и известные расхождения с production описаны в [справочнике ключей](catalogKeys.md#словари-тегов). Это готовый контекст для нормализации, но не реализованный формат всего импортного пакета. Служебные исследовательские блоки удалены; решения и соответствия источников нельзя восстанавливать из отсутствующих provenance/mappings/approval. Наличие JSON не означает загрузку Tag в БД или готовность импортёра.

Нейронка использует контекст, чтобы узнавать существующие понятия и произведения, сохранять канонические названия и дополнять каталог без создания повторных сущностей.

Порядок нормализации:

1. Применить известные соответствия и простые преобразования форматов и единиц измерения.
2. Разобрать новые и неоднозначные случаи: синонимы, смысловые различия, признаки произведений и противоречия источников.
3. При отсутствии подходящего понятия предложить новый тег в соответствующей группе; для нового точного факта определить поле Item. Для иерархических тегов определить смысл и родительские связи.
4. Сохранить принятые соответствия для последующих обработок.

Фактические значения сохраняют привязку к источнику; выводы нейронки должны быть отличимы от данных источника. Неизвестные факты остаются незаполненными.

## Импорт и повторная загрузка

Нейронка подготавливает данные и предлагает сопоставления. Приложение отвечает за проверку формата, ссылок и применение изменений к коллекциям.

Повторная загрузка одного пакета не создаёт дублирующие произведения или повторные изменения.

Неподтверждённый новый тег не должен останавливать добавление подходящего произведения с уже известными признаками. Зависимые от согласования изменения применяются после решения пользователя. Перед будущей загрузкой словарей необходимо разрешить расхождения `releaseYear` и `gameMode` с текущими правилами; конкретное изменение кода здесь не утверждено.

## Согласование изменений

| Действие                                                                  | Правило       |
| ------------------------------------------------------------------------- | ------------- |
| Добавление подходящего произведения                                       | Автоматически |
| Назначение существующих согласованных тегов                               | Автоматически |
| Создание связи между произведениями, например «продолжение» или «приквел» | Автоматически |
| Создание нового тега в любой группе                                       | Согласовать   |
| Изменение смысла тега или его родительских связей                         | Согласовать   |
| Добавление нового точного поля Item                                       | Согласовать   |
| Объединение карточек произведений                                         | Согласовать   |

Связь между произведениями и объединение карточек — разные операции. Для автоматически созданной связи сохраняются её основание, источник или вывод нейронки и возможность исправления либо удаления через админку.

Изменения иерархии тегов и объединения должны иметь историю и возможность отмены. Связь `parent` задаёт `first=child`, `second=parent`, не подменяет синонимы и не должна образовывать циклы; хранение JSON не реализует эти требования импортного процесса.

## Противоречия и обновления

Базовый порядок выбора данных: ручное исправление → данные выбранного источника → вывод нейронки.

- Ручное исправление закрепляется за конкретным полем и сохраняется при автоматических обновлениях.
- Для типа произведений выбирается основной источник. При необходимости для отдельных полей используется другой источник.
- Дополнительные источники заполняют пробелы и дополняют данные.
- Нейронка разбирает смысловые различия, разные форматы и несовпадение определений. Выбор фактического значения должен иметь основание в данных источников.
- Неразрешённое противоречие не останавливает обработку остальных данных: текущее значение сохраняется, а для новой карточки поле может остаться незаполненным. Конфликт попадает в отчёт.
- Отсутствующее значение в новой выгрузке само по себе не стирает уже известное.

## Допуск произведений в каталог

Правила допуска определяются при подключении нового типа Item и затем автоматически применяются к поступающим произведениям. Классификация источника сама по себе не гарантирует соответствия этим правилам.

В тип `Item.type = movie` входят только фильмы, включая документальные. Сериалы, мини-сериалы и другие многосерийные произведения, включая документальные сериалы, исключены. Мультфильмы, анимационные фильмы и аниме также не импортируются в этот тип, независимо от продолжительности и обозначения movie во внешнем источнике. Типы для этих произведений определяются отдельно; исключение из movie не означает запрет на их будущее добавление в каталог с подходящим типом.

Дополнительные исключения для фильмов: реклама, проморолики, трейлеры, тизеры, отдельные сцены и технические заглушки карточек.

Самостоятельные короткометражки, малоизвестные и низкобюджетные фильмы допускаются. Продолжительность, популярность и полнота карточки сами по себе не являются достаточным основанием для исключения.

Исключённые записи и причины исключения отражаются в отчёте.

## Удаление и исчезновение из источников

Исчезновение произведения из одного источника само по себе не означает его удаление из каталога. Меняется состояние соответствующей привязки; произведение может оставаться доступным в других источниках.

Произведение, признанное подлежащим удалению, помечается удалённым и исключается из общего каталога, поиска и рекомендаций. В существующих пользовательских библиотеках сохраняются карточка и пользовательские данные.

Физическое удаление карточки допускается, когда на неё нет пользовательских и необходимых системных ссылок.

После физического удаления исключённого произведения сохраняется минимальная отметка запрета повторного импорта: внешние идентификаторы и причина исключения. Следующая выгрузка не должна автоматически возвращать исключённый проморолик или другое неподходящее произведение.

## Админка и отчёты

Админка позволяет запускать оба режима сбора вручную, видеть новые исходные выгрузки, получать пакет для нейронки, загружать подготовленные JSON и принимать решения по изменениям, требующим согласования.

Отчёт показывает добавленные, обновлённые, связанные, объединённые, исключённые и удалённые произведения, ошибки, неразрешённые конфликты и ожидающие согласования изменения.

## Что уточняется при реализации

Конкретные источники, расписания, правила допуска для каждого нового типа Item, формат пакетов JSON, способ передачи контекста нейронке и устройство экранов админки определяются отдельно. Состав входных данных для embedding описан как открытый вопрос в [структуре данных](dataStructure.md#что-уточняется-позднее).
