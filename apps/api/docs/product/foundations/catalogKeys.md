# Ключи справочников каталога

[Структура данных](dataStructure.md) · [Наполнение каталога](catalogWorkflow.md)

Документ фиксирует согласованный начальный набор ключей для семи типов Item. Это контракт наполнения справочников, а не подтверждение наличия записей в БД или готовности импортёров.

Поля key у Tag, Relation и Source остаются строковыми идентификаторами с проверкой camelCase и уникальности. Enum в коде именуют ключи, которые явно обрабатывает программная логика, и не ограничивают весь словарь. Добавление новых понятий проходит согласование по правилам наполнения каталога.

## Словари тегов

Согласованное наполнение хранится в едином [tags.json](../../../import/tags/tags.json): 21 группа, 1184 тега и 216 связей `parents`. Корень файла — массив объектов `{group,tags}`; группа задана один раз для своего массива тегов. Запись тега содержит `key`, `name:{ru,en}`, `description:{ru,en}` с кратким смысловым определением и `aliases:string[]` и `parents:string[]` с ключами непосредственных родителей (пустой массив, если их нет). Алиасы обозначают синонимы; точные повторы названий из них удалены. `weightModifier=1` в JSON не хранится: это default схемы Tag.

Массив `parents` допускает несколько непосредственных родителей без повторов и самоссылок. Родитель может находиться в другой группе; при загрузке ключи потребуется разрешить в ObjectId для Tag.parents. Дети и полный список предков отдельно не хранятся. Иерархия не должна содержать циклов. Исследовательские provenance, mappings, approval, review, summary, validation и другие служебные блоки ранее удалены без переноса в архив; справочник не хранит историю согласования и не задаёт формат всего импортного пакета.

Платформы и 45 тегов годов находятся в группах `platform` и `releaseYear` единого файла. Прежние групповые файлы из `docs/research/tagDictionary` перенесены в него без изменения записей; независимых копий словаря нет. Нормализация названий и словарных ключей сохраняет ключи, используемые production-логикой.

### Расхождения с production

JSON фиксирует согласованный словарь, но не доказывает готовность его импорта. Текущая проверка `checkIsTagKeyAllowed` с `TAG_GROUP_RULES` принимает все 1184 записи:

- `releaseYear` в коде — `integer` от 1 до 9999 с четырьмя разрешёнными диапазонами: `releaseYear1To1930` (1–1929), `releaseYear1930To1950` (1930–1949), `releaseYear1950To1980` (1950–1979), `releaseYear1980To1990` (1980–1989). С 1990 года используются отдельные годы, предсозданные до 2030 включительно. Год 0 недопустим; 2030 — граница подготовленного словаря, а не максимальный год в коде.
- Группа `gameMode` содержит шесть тегов; production `values` допускает все шесть: `singlePlayer`, `cooperativeMultiplayer`, `competitiveMultiplayer`, `multiplayer`, `playerVsEnvironment`, `splitScreen`.
- Сохраняется расхождение по составу: в production ETagGroup и TAG_GROUP_RULES дополнительно есть `gameLength` с `shortGame` и `longGame`; этой группы в согласованном словаре нет. При объединении она не добавлялась.

Способ устранения расхождений здесь не утверждается. Подготовка словарей не выполняет импорт в БД, миграцию, синхронизацию TagItem или runtime-проверку.

## Правила групп тегов — TAG_GROUP_RULES

[TAG_GROUP_RULES.ts](../../../src/entities/tag/static/TAG_GROUP_RULES.ts) — типизированный справочник правил для каждой группы Tag. Формат записи определён в [TTagGroupRule.ts](../../../src/entities/tag/types/TTagGroupRule.ts).

Справочник отвечает на вопрос «какие теги этой группы допустимы у произведения и как их интерпретировать». Он не содержит полный каталог тегов и не является схемой MongoDB.

### Группа, тег и связь с произведением

- `ETagGroup` перечисляет группы, например `genre` и `duration`.
- `TAG_GROUP_RULES` описывает правила каждой группы.
- `Tag` хранит конкретное понятие с ключом, названием, переводами и группой, например жанр «Комедия» или диапазон «90–120 минут».
- `TagItem` связывает конкретный Tag с конкретным Item и хранит выраженность признака в relevanceScore.

Например, `duration` — группа, «90–120 минут» — конкретный тег этой группы, а связь фильма с этим тегом — запись TagItem. Само добавление диапазона в TS-файл не создаёт ни Tag, ни TagItem.

### Общие поля правила

| Поле                 | Значение                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `kind`               | Способ определения допустимых значений: словарь, фиксированный набор, целое число или диапазоны                                                  |
| `itemTypes`          | Типы Item, которым разрешена группа; `Object.values(EItemType)` означает все текущие типы                                                        |
| `cardinality`        | `one` — не более одного тега группы на Item; `many` — несколько разных тегов группы                                                              |
| `isUsedForTaste`     | Разрешено ли использовать группу при расчёте вкуса; false не запрещает отображение и фильтрацию                                                  |
| `isApprovalRequired` | Новые значения и изменения справочника требуют согласования; известное утверждённое значение не требует повторного согласования для каждого Item |
| `description`        | Описание смысла группы и ограничений, которые нельзя выразить остальными полями                                                                  |

`one` не делает тег обязательным: если значение неизвестно, у Item может не быть ни одного тега группы. Нулевой вес вкуса и неизвестные метаданные — разные состояния. Отсутствие тега не доказывает отсутствие свойства.

### Четыре вида правил

| `kind`       | Как определяется значение                               | Пример                                                              |
| ------------ | ------------------------------------------------------- | ------------------------------------------------------------------- |
| `dictionary` | Конкретное понятие из согласованного словаря            | Жанр, страна, игровая механика                                      |
| `enum`       | Одно значение из фиксированного списка `values`         | Статус выпуска, наличие конечного прохождения, возрастная категория |
| `integer`    | Целое число между `min` и `max` включительно            | Год выпуска от 1 до 9999                                            |
| `range`      | Один из диапазонов `ranges`, выбранный по числу из Item | Длительность фильма, количество серий                               |

Для `dictionary` отсутствие `values` означает, что код не ограничивает ключи этой группы списком, а не разрешение создавать произвольные теги: наполнение задаётся согласованными JSON-словарями. Если `values` указан, текущая документная проверка принимает только этот набор смысловых идентификаторов. Его расширение тоже требует согласования.

Для `enum` список `values` содержит записи {key,value}: key совпадает с Tag.key, value задаёт смысловое значение, например false для hasDefinedEndFalse. Возраст берётся из общего строкового EAgeRestriction: "0", "6", "12", "16", "18", "18++". В Tag нет дополнительного поля value или копии границ: соответствие определяется стабильным key из справочника. Для integer используется ключ группы с числом, например releaseYear2026.

### Как читать диапазонное правило

Сокращённый фрагмент правила длительности:

```ts
{
  kind: "range",
  cardinality: "one",
  isUsedForTaste: true,
  sourceField: "movie.duration",
  unit: EUnit.MINUTE,
  bounds: "[)",
  ranges: [
    { key: "duration90To120", from: 90, to: 120 },
    { key: "duration120To150", from: 120, to: 150 },
  ],
}
```

`sourceField` — путь к исходному полю внутри Item. Строка `movie.duration` обозначает `Item.movie.duration`, но сама не читает поле и не запускает обработку.

`bounds: "[)"` означает, что нижняя граница включена, верхняя исключена: `from <= значение < to`. Поэтому 110 минут относятся к `[90, 120)`, а ровно 120 минут — к `[120, 150)`. `to: null` означает отсутствие верхней границы, например 180 минут и более.

После подключения будущего обработчика фильм длительностью 110 минут должен получить один тег «90–120 минут». При изменении длительности до 125 минут обработчик должен заменить его тегом «120–150 минут». Если длительность неизвестна, тег не назначается. Точное число сохраняется в Item, а тег обозначает только категорию и не даёт второго независимого вклада от того же числа в рекомендации.

Для episodeCount интервал `[7, 14)` соответствует подписи «7–13 серий», поскольку количество серий — целое число. Все границы времени прохождения в TS записаны в минутах: 300 означает 5 часов. Границы с нулём не разрешают нулевую длительность: исходные числовые поля проверяются отдельно схемой Item.

### Дополнительные поля

| Поле                       | Где используется                      | Значение                                                                                                          |
| -------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `sourceField`              | `range`, `integer`, возрастной `enum` | Исходное поле Item; для releaseYear год извлекается из releaseDate                                                |
| `unit`                     | `range`                               | Единица числовых границ: минуты или серии                                                                         |
| `ranges`                   | `range`                               | Упорядоченные диапазоны с нижней и верхней границами                                                              |
| `bounds`                   | `range`                               | Общее правило включения границ `[)`                                                                               |
| `isDefinedEndRequired`     | Диапазоны времени прохождения игр     | Применение требует известного наличия конечного прохождения базовой игры                                          |
| `values`                   | `enum`, некоторые `dictionary`        | Допустимые значения или начальные словарные идентификаторы                                                        |
| `min`, `max`               | `integer`                             | Допустимые границы целого значения                                                                                |
| `isYearWithoutDateAllowed` | `releaseYear`                         | Разрешает тег известного года без выдуманной точной даты; при появлении точной даты год должен соответствовать ей |

### Что уже работает и что ещё предстоит

`satisfies Record<ETagGroup, TTagGroupRule>` проверяет при компиляции TypeScript, что для каждой группы есть правило и его структура соответствует типу. Например, диапазонное правило должно содержать ranges, единицу и исходное поле. Эта проверка не доказывает отсутствие пересечений диапазонов и не проверяет данные MongoDB.

Tag использует TAG_GROUP_RULES при документной валидации key/group: для enum и range ключ должен присутствовать в определениях, integer должен соответствовать допустимому году, dictionary с values принимает ключи из этого набора. Для словарей без values проверка согласованного смысла остаётся процессом наполнения, а не автоматической валидацией. Query/bulk-операции не гарантируют документные проверки. Флаги не включают рекомендации автоматически, cardinality не запрещает несколько тегов на уровне БД, а isApprovalRequired не создаёт процесс согласования. Description также не исполняется как проверка. Существующий уникальный индекс TagItem запрещает только повтор одной пары Item/Tag, а не нескольких разных Tag одной группы.

Далее потребуются устранение расхождений словаря с production-контрактом, создание Tag с определёнными ключами, обработка неизвестных значений, синхронизация производных тегов и подключение правил к импорту и расчёту вкуса. Задачи импорта и расчёта записаны в [TODO](../../TODO.md). Feature и ItemFeature удалены из production-кода вместе с потребителями и featurePreferences. Подготовленные JSON сами по себе не выполняют миграцию или наполнение БД.

## Поля Item и теги вместо Feature

Общие поля: releaseDate (точная дата первого выпуска) и ageRestriction (EAgeRestriction). Полнометражное видео использует movie.duration. Сезоны используют series.episodeCount, releasedEpisodeCount, episodeDuration и nextEpisodeAt. Игры используют game.mainStoryDuration и fullCompletionDuration; время в минутах, без DLC.

releaseDate, ageRestriction и блоки movie/series/game имеют default null. Поля внутри существующего блока необязательны без defaults. releaseYear и seasonNumber как поля Item отсутствуют; год может храниться тегом без точной даты, номер сезона не входит в текущий набор.

releaseStatus и hasDefinedEnd представлены тегами, ESRB/PEGI сводятся к общей группе ageRestriction по отдельно согласуемым правилам. Стабильные ключи диапазонов и фиксированных значений определены в TAG_GROUP_RULES; согласованное наполнение хранится в групповых JSON с указанными выше расхождениями. Программно используемые ключи ограничений библиотеки именуются ETagKey.

Точные фильтры коллекций используют EItemField: releaseDate, ageRestriction, movie.duration, series.episodeCount, series.releasedEpisodeCount, series.episodeDuration, series.nextEpisodeAt, game.mainStoryDuration, game.fullCompletionDuration. Границы точного фильтра включительны и проверяются по Item, независимо от диапазонных тегов.

## Tag.key

Один смысл имеет один канонический Tag независимо от Item.type. Совпадающие названия с разным смыслом относятся к разным тегам. Применимость ниже показывает, где признаки особенно полезны, а не устанавливает запрет их использования у других типов.

### Общие содержательные признаки

| Tag.group               | Ключи                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `genre`                 | `drama`, `comedy`, `horror`, `scienceFiction`, `fantasy`                                       |
| `keyword` — темы        | `loneliness`, `friendship`, `revenge`, `familyRelationships`, `moralDilemmas`, `survivalTheme` |
| `style` — повествование | `darkHumor`, `nonlinearNarrative`, `slowNarrativePacing`, `surrealism`                         |
| `style` — атмосфера     | `darkAtmosphere`, `tenseAtmosphere`, `cozyAtmosphere`, `melancholicAtmosphere`                 |

### Дополнения по типам

| Item.type        | Ключи и группы                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| `movie`          | `documentary`, `mockumentary` — format; `foundFootage` — style                                             |
| `series`         | `anthology` — format; `episodicNarrative`, `continuousNarrative` — style                                   |
| `animatedMovie`  | `twoDimensionalAnimation`, `threeDimensionalAnimation`, `stopMotion` — style                               |
| `animatedSeries` | Те же техники анимации — style; `anthology` — format; `episodicNarrative`, `continuousNarrative` — style   |
| `animeMovie`     | Те же техники анимации — style; `mecha`, `isekai`, `schoolLife` — keyword                                  |

| `game`           | `rolePlayingGame`, `firstPersonShooter`, `strategyGame`, `platformer`, `puzzleGame`, `visualNovel` — genre |

Техники анимации в таблице обозначают один общий набор ключей; отдельных копий тегов для мультфильмов и аниме не создаётся.

### Игровые механики и режимы

| Tag.group      | Ключи                                                                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `style`        | `branchingNarrative`                                                                                                                                     |
| `gameMechanic` | `meaningfulChoices`, `exploration`, `stealth`, `crafting`, `baseBuilding`, `resourceManagement`, `survivalGameplay`, `turnBasedCombat`, `realTimeCombat` |
| `gameMode`     | `singlePlayer`, `cooperativeMultiplayer`, `competitiveMultiplayer`, `multiplayer`, `playerVsEnvironment`, `splitScreen`                                  |

survivalTheme описывает тему выживания, survivalGameplay — игровую механику. Эти понятия не объединяются по совпадению названия. Аналогично сюжетный экшен не приравнивается автоматически к жанру игрового экшена. branchingNarrative может использоваться у другого типа, если описывает тот же смысл.

### Фактические признаки

| Tag.group          | Начальные ключи                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| `country`          | `countryJapan`, `countryUnitedStates`, `countryRussia`                                            |
| `originalLanguage` | `languageJapanese`, `languageEnglish`, `languageRussian`                                          |
| `platform`         | `platformWindows`, `platformLinux`, `platformMacos`, `platformPlayStation5`, `platformXboxSeries` |

Списки стран, языков и платформ расширяются по данным каталога после согласования. `country` описывает страны производства. `originalLanguage` описывает язык оригинала, а не доступные переводы или локаль интерфейса: `languageTagalog` не означает Filipino, `languageMandarin` не охватывает всю китайскую языковую семью. Платформы игры хранятся несколькими TagItem одного Item, без отдельных карточек игры на каждую платформу. Для платформ relevanceScore=1 фиксирует наличие выпущенной версии или режима на платформе; магазины, владение устройством и способ ввода этим не обозначаются.

Общие содержательные теги дают основу сопоставления разных типов контента. Их наличие не задаёт одинаковый вес или автоматически сопоставимую шкалу relevanceScore между типами.

## Relation.key

Ключи задают роли двух сторон ItemRelation, а не отдельное поле ItemRelation.type. Положение first/second само по себе не задаёт хронологию.

| group   | Роль одной стороны  | Роль другой стороны | Значение                                 |
| ------- | ------------------- | ------------------- | ---------------------------------------- |
| `all`   | `previousPart`      | `sequel`            | Предыдущая часть и прямое продолжение    |
| `all`   | `prequelBase`       | `prequel`           | Произведение и его приквел               |
| `all`   | `mainWork`          | `spinOff`           | Основное произведение и ответвление      |
| `all`   | `adaptationSource`  | `adaptation`        | Основа и адаптация                       |
| `video` | `recapSource`       | `recap`             | Исходное произведение и его пересказ     |
| `video` | `compilationSource` | `compilation`       | Исходное произведение и фильм-компиляция |

Роли all применимы ко всем семи типам Item, video — к шести видеотипам. Группа является классификацией словаря, а не проверкой типов сторон ItemRelation. Специальные ключи только для game в начальном наборе не требуются; общие продолжения, ответвления и адаптации уже покрыты группой all.

Для следующего сезона используется прямая связь соседних сезонов. Франшиза задаётся Collection и не заменяет смысловую связь произведений. Связь сама по себе не устанавливает обязательный порядок потребления.

DLC и порты не получают отдельных ролей в этом наборе: они входят в Item игры. Роли для ремейков и ремастеров требуют отдельного решения о границах самостоятельного Item.

## Source.key

Согласованные кандидаты для внешних привязок:

| Item.type        | Ключи                                       |
| ---------------- | ------------------------------------------- |
| `movie`          | `kodik`, `kinopoisk`, `imdb`                |
| `series`         | `kodik`, `kinopoisk`, `imdb`, `mydramalist` |
| `animatedMovie`  | `kodik`, `kinopoisk`, `imdb`                |
| `animatedSeries` | `kodik`, `kinopoisk`, `imdb`                |
| `animeMovie`     | `kodik`, `shikimori`, `kinopoisk`, `imdb`   |
| `animeSeries`    | `kodik`, `shikimori`, `kinopoisk`, `imdb`   |
| `game`           | `igdb`, `steam`                             |

Source описывает сервис, SourceItem — его внешний объект и привязку к Item. Таблица не гарантирует покрытие каждого произведения источником. Совпадение названий само по себе не устанавливает идентичность.

Для игр igdb рассматривается как источник каталожных данных, steam — как привязка по App ID. Основания: [документация IGDB](https://api-docs.igdb.com/) и [модель приложений Steam](https://partner.steamgames.com/doc/store/application?l=english). Выбор основных поставщиков, условия использования и импорт требуют отдельной проверки; наличие Source не означает готовый клиент.

## Граница реализации

В коде ETagKey именует hasDefinedEndFalse, releaseStatusAnnounced и releaseStatusOngoing; ESourceKey — kodik. Эти имена уже используются сервисами. Остальные согласованные ключи здесь задают контракт справочников и не означают расширение enum, создание записей БД или реализацию новых импортёров.

Схемы и текущее состояние реализации описаны в [сущностях API](../../api/entities.md); правила пользовательской завершённости — в [контракте библиотеки](../../api/librarySpec.md).
