# Data access

Read for persistence, pagination, Redis cache or Meilisearch changes. Configuration is described in [runtime](runtime.md).

## MongoDB

[DatabaseModule](../../src/infrastructure/database/database.module.ts) creates the Mongoose connection with `autoIndex: true` and registers global [timestamp](../../src/infrastructure/database/functions/applyTimestampsPlugin/core/applyTimestampsPlugin.ts), [version-key](../../src/infrastructure/database/functions/applyVersionKeyPlugin/core/applyVersionKeyPlugin.ts) and [toJSON](../../src/infrastructure/database/functions/applyToJsonPlugin/core/applyToJsonPlugin.ts) plugins. The timestamp plugin enables timestamps only when the schema has no explicit setting, preserving `false` and custom timestamp options. The version-key plugin sets versionKey:false on every schema. Connection plugins also apply to child schemas. The JSON transform preserves a prior transform, enables virtuals, converts `_id` to string `id` and removes `_id` and `__v`. These are document serialization rules; do not assume every query result has already been serialized.

Connection options and plugin registration are shared with the integration-test bootstrap through [createDatabaseOptions](../../src/infrastructure/database/functions/createDatabaseOptions/index.ts).

Existing repository classes take a model and optional default sort through [MongoCoreRepository](../../src/infrastructure/database/services/mongoCore.repository.ts):

| Existing object                                                                                         | Public operations                                                        |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| [MongoReadRepository](../../src/infrastructure/database/services/mongoRead.repository.ts)               | `findById`, `findOne`, `findMany`, `checkIsExists`                       |
| [MongoWriteRepository](../../src/infrastructure/database/services/mongoWrite.repository.ts)             | `create`, `updateById`, `updateByFilter`, `deleteById`, `deleteByFilter` |
| [MongoPaginationRepository](../../src/infrastructure/database/services/mongoPagination.repository.ts)   | `findManyPaginated`                                                      |
| [MongoBulkRepository](../../src/infrastructure/database/services/mongoBulk.repository.ts)               | `createMany`, `updateMany`, `deleteMany`, `bulkWrite`                    |
| [MongoAggregationRepository](../../src/infrastructure/database/services/mongoAggregation.repository.ts) | `aggregate`                                                              |

These generic classes are not registered as model-specific providers by DatabaseModule. The 22 entity repositories compose them through public readonly `read`, `write`, `pagination`, `bulk` and `aggregation` properties, using one injected `Model<HydratedDocument<Entity>>` without a default sort; see [TagRepository](../../src/entities/tag/services/tag.repository.ts). Schema classes supply the raw data types; root classes extend [MongoEntity](../../src/infrastructure/database/types/MongoEntity.ts) to inherit `_id`, `createdAt` and `updatedAt` declarations without adding schema paths or defaults. `HydratedDocument<Entity>` supplies the document type required by the existing repository core. Derived `TCreate<Entity>` aliases live in schema files and use [TCreateEntity](../../src/infrastructure/database/types/TCreateEntity.ts) to omit generated fields, make explicitly listed defaulted fields optional and replace explicitly listed nested field types. The helper omits generated fields only from MongoEntity-compatible root types; child types retain their own fields, including explicit updatedAt. All-optional child create types remain `Partial<Child>`. Nested overrides are removed from the original shape before being merged, preserving nested create defaults without duplicating storage interfaces. Reuse the entity boundary rather than creating another persistence client. Reads and single-document mutations can return `null`. `updateById` and `updateByFilter` request the updated document unless the caller supplies `options.new`. `MongoReadRepository.findMany` uses the configured default sort only when no caller sort is supplied.

[UserRepository.createNew(options?)](../../src/entities/user/services/user.repository.ts) generates a lowercase username and camelCase displayName with three trailing digits from entity-owned word lists, a 24-byte random base64url access code and its SHA-256 hash, and creates the user with schema defaults. It returns `{ user, accessCode }`; expose only an explicit response allowlist. [SessionRepository.createNew(props, options?)](../../src/entities/session/services/session.repository.ts) accepts a preassigned session ID, user ID, refresh token and optional userAgent, computes the SHA-256 token hash and 120-day expiry, and returns the created document. Both forward the caller's transaction session; neither starts a transaction nor issues JWTs. AuthService owns registration orchestration and username-collision retries.

[UserRepository](../../src/entities/user/services/user.repository.ts) also owns `findByAccessCode`, `reissueAccessCode` and `replacePassword`. Access-code operations use SHA-256 and require an account without a password; reissue returns `{ user, accessCode }`, with a nullable user when the old code or account state no longer matches. Password replacement matches user ID, email and the previous password hash before updating. Mutations accept the caller's transaction session and return documents or null without HTTP exceptions.

[SessionRepository](../../src/entities/session/services/session.repository.ts) owns `findActive`, `findActiveByUser`, `deleteActive`, `deleteOthers`, `deleteByUser` and `updateRefreshToken`. Single-session operations require both session and owner ObjectIds; active operations explicitly check expiresAt. The list selects device/date fields and sorts newest first. Refresh updates hash the new token, extend expiry by 120 days and record lastRefreshedAt. Supplying currentRefreshToken additionally requires its SHA-256 hash to match in the same atomic update; SessionService.refresh always supplies it. Reissue of the access code updates an already authenticated session without that extra filter. Transaction ownership, JWT issuance, HTTP errors and response mapping remain in endpoint services.

`updateByFilter` and `deleteByFilter` each execute one `findOneAndUpdate` or `findOneAndDelete`, accepting schema-typed filters and options through the existing `entityRepository.write`. Endpoint services supply verified ownership to entity operations rather than trusting body/query ownership or using read-then-write by ID. They map missing/foreign records to the endpoint's declared HTTP error. Repositories do not decide authorization, start transactions or create HTTP exceptions.

`updateById`, `updateByFilter` and `updateMany` default `runValidators` to true while preserving explicit false, session and other caller options. Update validators cover supported operators and changed paths only: `$inc`, array operators and pipelines do not guarantee whole-document invariants. `bulkWrite` updates and update pipelines remain trusted low-level APIs without full schema validation. Future endpoints must construct allowed updates from validated DTOs, never accept client MongoDB filters, operators, projections or QueryOptions, and validate business invariants in their application-service.

[AppModule](../../src/app/app.module.ts) imports 22 entity modules. Each registers its own model and exports its repository; SourceModule additionally exports its reusable collection/client/writer services. Consumers import the owning module. AuthModule, AccountModule, UserItemEndpointModule and CollectionEndpointModule provide HTTP use cases; catalogue import and ranking orchestration are not implemented.

[Item](../../src/entities/item/schemas/item.schema.ts) is the single catalogue entity for all content types and stores required type (currently EItemType.MOVIE), title={ru,en}, aliases:string[], description={ru,en}, media:MediaSrc[] and nullable deletedAt. Title requires at least one non-whitespace translation. Aliases and media default to []; description defaults to {ru:null,en:null}; deletedAt defaults to null. Aliases must contain non-whitespace text. TCreateItem makes aliases, description, media and deletedAt optional. MediaSrc reuses the shared embedded schema with src, nullable language and type; EMediaType defines POSTER, SCREENSHOT and TRAILER. Generated _id and timestamps follow the standard MongoEntity/connection-plugin setup. ItemModule is imported by AppModule and exports ItemRepository. No title uniqueness or search index is declared. Catalogue references are direct ObjectId references to Item: ItemFeature.item, ItemMetric.item, ItemTag.item, RelationSide.item, SourceItem.item, UserItem.item; SourceItem.item remains nullable. Their indexes use item (or first.item/second.item) instead of item.type/item.id. Separate Movie/Game entities are not part of the target model; type-specific characteristics use tags and features. Existing Movie documents, embedded references and database indexes were not migrated. deletedAt does not install a global query filter. Library creation and collection content reads explicitly require nondeleted Items; general catalogue search, import and merge/split orchestration are not implemented.

The source tree does not contain the former `data/movie_*.json` dictionaries. The current source seed is [import/sources/kodik.json](../../../../import/sources/kodik.json); a file does not establish that its records are loaded into MongoDB. [Kodik field mapping](../../../../docs/sources/kodik/mapping.md) describes proposed normalization and approval rules, not an implemented importer.

[LanguageText](../../src/entities/shared/schemas/languageText.schema.ts) stores nullable ru/en translations, each defaulting to null. Dictionary descriptions and RelationSide.roleNameOverride are bilingual objects defaulting to empty translations. Feature and ItemRelationRole keys use CAMEL_CASE_REGEX and unique indexes; group and unit fields are nullable where declared. Tag aliases are nonempty strings; its group enum currently retains GENRE and SUBGENRE separately. [TagRelation](../../src/entities/tagRelation/schemas/tagRelation.schema.ts) stores child=first, parent=second for type=parent. Document pre-validation rejects self-relations; query and bulk updates require operation-level checks, and existence/cycle checks are not implemented. [EUnit](../../src/entities/shared/schemas/EUnit.ts) defines MINUTE, USD and RUB; ItemAttempt permits only MINUTE. Child schemas disable _id/id/timestamps, while Embedding retains its explicit updatedAt. ItemAttempt has an explicit id field for library mutation routes. [ItemFeature](../../src/entities/itemFeature/schemas/itemFeature.schema.ts) accepts number/string/boolean/Date but does not check the referenced Feature.valueType; future import/application services must enforce that contract. Use [the entity inventory](../../../../docs/api/entities.md) for the complete storage map.

The current application registers 22 root entity schemas. Their collection names match schema class names. Source declarations do not establish deployment of collections or indexes.

CollectionItem and UserCollection reference Collection through the required ObjectId field `collectionId`. Their query filters, aggregation matches and compound indexes use this field. Existing documents with `collection` and indexes on that field require migration before using the updated API; no database migration was performed.

[Source](../../src/entities/source/schemas/source.schema.ts) uses a unique camelCase key and nullable logoUrl/baseUrl/apiUrl. [UserSourceAccount](../../src/entities/userSourceAccount/schemas/userSourceAccount.schema.ts) stores user, source and externalId with unique user/source and source/externalId pairs; external ownership verification is not implemented. [SourceItem](../../src/entities/sourceItem/schemas/sourceItem.schema.ts) permits item=null before matching, has unique(source,externalId) and allows multiple source records for one Item. [ItemMetric](../../src/entities/itemMetric/schemas/itemMetric.schema.ts) stores one aggregate per Item: completed attempts, recommendations, ratings, favorites, distribution and status counts. Its counters are nonnegative safe integers; recalculation is not implemented. Session declares refresh-hash uniqueness, a user/expiry lookup and sessionExpiryTtl with expireAfterSeconds:600. Refresh, code reissue and password change update lastRefreshedAt through SessionRepository.updateRefreshToken.

Raw artifact uploads are provided by SourceDataWriterService and StorageService. Import runs, approvals, provenance and publication checkpoints are not represented by current root entities; their application workflow remains to be implemented.

[BannedItem](../../src/entities/bannedItem/schemas/bannedItem.schema.ts) stores global import/recommendation bans by required Source ObjectId and exact externalId, with nullable reason. The unique pair index is named bannedItemSourceExternalIdUnique. BannedItemModule is imported by AppModule and exports BannedItemRepository. A ban does not require an Item or SourceItem to exist; future recommendation filtering can resolve Items through matching SourceItem records. Import and recommendation enforcement are not implemented. The index is declared in source only; no database migration or runtime verification was performed.
[UserTasteProfile](../../src/entities/userTasteProfile/schemas/userTasteProfile.schema.ts) stores one document per user with unique per-type profiles, nullable positive/negative embeddings, tag preferences and interactionsCount. Tags are unique within each profile, with a 4096-preference cap. Preference scores are finite; samples and interactionsCount are nonnegative safe integers. Algorithm versions, profile recalculation, recommendation snapshots and scoring services are not implemented.

[UserItem](../../src/entities/userItem/schemas/userItem.schema.ts) stores seven non-null statuses: five library statuses plus skipped and blocked, nullable integer rating 1..10, favorite, nullable trimmed note, nullable expiresAt and attempts with explicit ObjectId identifiers. Attempts contain isCompleted, nullable safe-integer progress, minute/percent unit and nullable dates; percent is capped at 100. The unique user/item pair covers library entries and exclusions. A partial expiresAt TTL index deletes only skipped records; the endpoint service forbids personal data/attempts for skipped and clears expiry on other statuses. At least one attempt is required for inProgress/onHold/completed/dropped by the endpoint contract. Blocked retains existing history. UserRecommendationState is removed; exposure history is not implemented. Existing attempt.status data needs explicit migration to isCompleted before deployment; no live data migration has been performed.

The [User schema](../../src/entities/user/schemas/user.schema.ts) trims and lowercases username/email; empty email becomes null. New usernames are normalized before storage; existing database records are not migrated automatically. External identifiers, hashes and dictionary keys retain exact comparison. The unique email partial filter is `{ email: { $type: "string" } }`; linked-account uniqueness uses `{ "linkedAccounts.provider": { $type: "string" }, "linkedAccounts.externalId": { $type: "string" } }`, allowing multiple users with null email or empty linkedAccounts. A whole-array validator rejects repeated providers within a user, which a unique multikey index alone does not prevent. Future account linking must replace the full array with `$set` and validators; `$push`, `$addToSet` and dotted updates do not enforce this whole-array contract. Lookup must use `linkedAccounts: { $elemMatch: { provider, externalId } }` to match both fields within one element. OAuth/linking is not implemented.

Uniqueness depends on deployed MongoDB indexes, not an availability precheck. Account services map relevant duplicate-key errors to HTTP 409. Source index declarations and autoIndex do not safely migrate conflicting existing indexes or normalize stored data. Session expiry is explicitly checked for authorization independently of TTL cleanup.

Code-only login queries User.accessCodeHash using a SHA-256 hex digest of the 24-byte random base64url code generated by UserRepository.createNew, with passwordHash required to be null. The partial unique userAccessCodeHashUnique index covers string accessCodeHash values and excludes null/missing values. Existing bcrypt-backed access codes are intentionally unsupported; no stored data was migrated and deployment of this index was not verified. Do not use password-style bcrypt comparison or scan users for this lookup.

[User](../../src/entities/user/schemas/user.schema.ts) normalizes username/email, stores nullable bcrypt passwordHash and SHA-256 accessCodeHash with select:false, and supports Google/Yandex linked-provider records. Before setup email/password are absent; setup conditionally sets both and clears accessCodeHash. UserSetting owns locale with RU/EN values and RU default. [Session](../../src/entities/session/schemas/session.schema.ts) stores user, refreshTokenHash, userAgent, expiresAt and lastRefreshedAt. See [security](security.md) for the implemented login, setup, recovery and session lifecycle.

User has a local toJSON transform removing passwordHash/accessCodeHash, composed with the global id transform. Session has no local hash-removal transform. select:false hides hashes from default reads, but explicit selections/create results can contain them; lean, aggregate and toObject do not provide an HTTP response allowlist. Endpoint DTOs map responses explicitly.

Source inspection does not prove data migrations, deployed unique indexes, transaction topology or external-service behavior. Check the intended runtime environment separately; documentation updates do not require starting the application or connecting to a database.

[MongoTransactionService.run](../../src/infrastructure/database/services/mongoTransaction.service.ts) accepts run(callback, options?), starts a session, passes the optional options to withTransaction and ends the session in finally. The options type is derived from the installed ClientSession.withTransaction; existing callers retain their behavior. New operation services can explicitly supply snapshot/majority/primary concerns; this does not configure or verify the actual MongoDB deployment. Pass the received session to participating repository operations; transaction scope alone does not attach it to arbitrary queries.

Pagination defaults to page 1 and limit 20, floors finite values and clamps explicit limits to 1–100 through [normalizePagination](../../src/shared/functions/pagination/normalizePagination/core/normalizePagination.ts). The paginated repository normalizes a non-empty caller sort through Mongoose Query.sort, otherwise uses a non-empty defaultSort, otherwise `{ _id: -1 }`. Object, string and tuple forms are supported without mutating caller/default sort objects. An absent `_id` is appended as the last descending tie-breaker; an explicit `_id` retains its direction and position. Equal sort values therefore have deterministic ordering, but offset pagination can still shift during concurrent writes. The repository runs items and count sequentially when a session is present, otherwise concurrently. [createPaginatedResult](../../src/shared/functions/pagination/createPaginatedResult/core/createPaginatedResult.ts) returns items, page, limit, total, pages and next/previous flags.

[MongoObjectIdHandler](../../src/infrastructure/database/handlers/mongoObjectId.handler.ts) validates 24-character hexadecimal route parameters and converts them to Types.ObjectId, returning 400 for invalid input. It is reusable at controller parameter boundaries and has no entity dependencies.

## Redis cache

[CacheModule](../../src/infrastructure/cache/cache.module.ts) provides cache-manager backed by Keyv Redis and an app-name namespace. [CacheService](../../src/infrastructure/cache/services/cache.service.ts) exposes `get`, `set` and `delete`, normalizing missing values to `null`.

[CacheEndpoint](../../src/infrastructure/cache/decorators/CacheEndpoint/core/CacheEndpoint.ts) installs the Nest CacheInterceptor and a TTL from `ttlMs` or the existing default constant. It is not a custom per-user cache key policy; inspect key behavior before applying it to personalized responses.

## Search

[SearchService](../../src/infrastructure/search/services/search.service.ts) exposes `ensureIndex`, `upsert`, `search`, `delete` and `clear`. `ensureIndex` creates missing indexes with primary key `id` and updates configured searchable, displayed, filterable, sortable attributes and ranking rules. Concurrent initialization of the same index shares a promise within the service instance; it is not a persistent or distributed lock.

Mutations and index initialization accept `waitForTask`, defaulting to false. Successful enqueueing does not prove that a document is already searchable. Search maps Meilisearch results into [ISearchResult](../../src/infrastructure/search/types/ISearchResult.ts). The current source has infrastructure APIs but no domain indexing/synchronization consumer.
