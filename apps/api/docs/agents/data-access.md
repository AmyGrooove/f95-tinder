# Data access

Read for persistence, pagination, Redis cache or Meilisearch changes. Configuration is described in [runtime](runtime.md).

## MongoDB

[DatabaseModule](../../src/infrastructure/database/database.module.ts) creates the Mongoose connection with `autoIndex: true` and registers global [timestamp](../../src/infrastructure/database/functions/applyTimestampsPlugin/core/applyTimestampsPlugin.ts) and [toJSON](../../src/infrastructure/database/functions/applyToJsonPlugin/core/applyToJsonPlugin.ts) plugins. The timestamp plugin enables timestamps only when the schema has no explicit setting, preserving `false` and custom timestamp options. Connection plugins also apply to child schemas. The JSON transform preserves a prior transform, enables virtuals, converts `_id` to string `id` and removes `_id` and `__v`. These are document serialization rules; do not assume every query result has already been serialized.

Existing repository classes take a model and optional default sort through [MongoRepositoryCore](../../src/infrastructure/database/services/mongoRepositoryCore.repository.ts):

| Existing object                                                                                         | Public operations                                                        |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| [MongoReadRepository](../../src/infrastructure/database/services/mongoRead.repository.ts)               | `findById`, `findOne`, `findMany`, `checkIsExists`                       |
| [MongoWriteRepository](../../src/infrastructure/database/services/mongoWrite.repository.ts)             | `create`, `updateById`, `updateByFilter`, `deleteById`, `deleteByFilter` |
| [MongoPaginationRepository](../../src/infrastructure/database/services/mongoPagination.repository.ts)   | `findManyPaginated`                                                      |
| [MongoBulkRepository](../../src/infrastructure/database/services/mongoBulk.repository.ts)               | `createMany`, `updateMany`, `deleteMany`, `bulkWrite`                    |
| [MongoAggregationRepository](../../src/infrastructure/database/services/mongoAggregation.repository.ts) | `aggregate`                                                              |

These generic classes are not registered as model-specific providers by DatabaseModule. The 17 entity repositories compose them through public readonly `read`, `write`, `pagination`, `bulk` and `aggregation` properties, using one injected `Model<HydratedDocument<Entity>>` without a default sort; see [TagRepository](../../src/entities/tag/services/tag.repository.ts). Schema classes supply the raw data types; root classes extend [MongoEntity](../../src/entities/shared/MongoEntity/index.ts) to inherit `_id`, `createdAt` and `updatedAt` declarations without adding schema paths or defaults. `HydratedDocument<Entity>` supplies the document type required by the existing repository core. Derived `TCreate<Entity>` aliases live in schema files and use [TCreateEntity](../../src/entities/shared/TCreateEntity/index.ts) to omit generated fields, make explicitly listed defaulted fields optional and replace explicitly listed nested field types. The helper also supports child classes without MongoEntity inheritance; all-optional child create types remain `Partial<Child>`. Nested overrides are removed from the original shape before being merged, preserving nested create defaults without duplicating storage interfaces. Reuse the entity boundary rather than creating another persistence client. Reads and single-document mutations can return `null`. `updateById` and `updateByFilter` request the updated document unless the caller supplies `options.new`. `MongoReadRepository.findMany` uses the configured default sort only when no caller sort is supplied.

`updateByFilter` and `deleteByFilter` each execute one `findOneAndUpdate` or `findOneAndDelete`, accepting schema-typed filters and options through the existing `entityRepository.write`. Future endpoint-services must build `{ _id: id, user: authenticatedUserId }` from verified authentication context for owned records, rather than trusting body/query ownership or using read-then-write by ID. A `null` result must map to the same HTTP 404 for missing and foreign records. Repositories do not decide authorization, start transactions or create HTTP exceptions; these endpoint behaviors remain unimplemented.

`updateById`, `updateByFilter` and `updateMany` default `runValidators` to true while preserving explicit false, session and other caller options. Update validators cover supported operators and changed paths only: `$inc`, array operators and pipelines do not guarantee whole-document invariants. `bulkWrite` updates and update pipelines remain trusted low-level APIs without full schema validation. Future endpoints must construct allowed updates from validated DTOs, never accept client MongoDB filters, operators, projections or QueryOptions, and validate business invariants in their application-service.

[AppModule](../../src/app/app.module.ts) imports entity modules for Relation, ItemRelationRole, Tag, ItemTag, TagRelation, Feature, ItemFeature, Source, SourceItem, ItemMetric, User, UserSetting, UserItem, UserSourceAccount, Session, UserTasteProfile and UserRecommendationState. Each module registers its own model and exports only its repository. Modules are not global: a future consumer must import the corresponding entity module. Imports use direct paths such as `@entities/tag/tag.module`, `@entities/tag/schemas/tag.schema` and `@entities/tag/services/tag.repository`. All 13 enum files live in their owner's `schemas` directory. Entity folders have no `index.ts`, `types` or `enums` directories.

[LanguageText](../../src/entities/shared/schemas/languageText.schema.ts), [Embedding](../../src/entities/shared/schemas/embedding.schema.ts) and [ItemId](../../src/entities/shared/schemas/itemId.schema.ts) export reusable child classes and schemas without models or collections. All three reusable schemas and `EItemType` live under `entities/shared/schemas`; other child schemas stay with their entity owner. Children disable `_id`, virtual `id` and automatic timestamps; explicit `itemId.id` and `embedding.updatedAt` remain stored fields. Root schemas use explicit collection names, timestamps, strict mode and no version key. See [entitiesSpec.md](../entitiesSpec.md) for the full field contract; its original file-layout and no-additional-index instructions have been superseded by the current structure and indexes described here.

The 17 root schemas declare 27 named indexes: 20 unique and seven non-unique, retaining their existing names and key order. Unique constraints cover dictionary keys, User username/email/linked accounts, one UserSetting/UserTasteProfile per user, UserItem/UserRecommendationState per user and item, ItemMetric per item, ItemTag/ItemFeature/TagRelation links, both SourceItem mappings, both UserSourceAccount mappings and Session refresh-token hashes. A user has at most one account per Source, and each Source external account belongs to at most one user. Non-unique indexes cover both Relation sides, reverse ItemTag/ItemFeature/TagRelation/UserItem lookup and Session user/expiry. Item references use dotted `item.type` and `item.id` keys; compound prefixes cover owner-only lookups without redundant indexes. See [endpoint readiness](../entitiesEndpointReadinessSpec.md) for exact constraints; it supersedes only the specified requirements of the older entities specification. No business query consumers exist yet, so this remains a schema-based access baseline, not a measured workload optimization.

The [User schema](../../src/entities/user/schemas/user.schema.ts) trims and lowercases username/email; empty email becomes null. External identifiers, hashes and dictionary keys retain exact comparison. The unique email partial filter is `{ email: { $type: "string" } }`; linked-account uniqueness uses `{ "linkedAccounts.provider": { $type: "string" }, "linkedAccounts.externalId": { $type: "string" } }`, allowing multiple users with null email or empty linkedAccounts. A whole-array validator rejects repeated providers within a user, which a unique multikey index alone does not prevent. Future account linking must replace the full array with `$set` and validators; `$push`, `$addToSet` and dotted updates do not enforce this whole-array contract. Lookup must use `linkedAccounts: { $elemMatch: { provider, externalId } }` to match both fields within one element. OAuth/linking is not implemented.

Uniqueness depends on deployed MongoDB indexes, not a preliminary `findOne`. Future endpoint-services must map duplicate-key errors to HTTP 409 without exposing raw DB errors, hashes or internal values. Existing non-unique indexes with the same names require a separately managed rollout: check duplicates including normalized username/email and repeated linked providers, agree old-data normalization, then replace affected indexes with concurrency controls and verify the result. `autoIndex: true` does not safely migrate those indexes. This preparation does not connect to the external database or apply migrations. No TTL indexes are declared; `expiresAt` does not delete documents. Source declarations do not prove deployment, concurrent uniqueness or query performance.

`EItemType` currently supports movies and linked accounts support Google. User type defaults to temporary; empty dictionaries remain empty enums with string fields. Nullable fields default to null, arrays to empty arrays and counters to zero. Non-nullable fields with defaults are required after defaults apply. Password, temporary-code and refresh-token hashes retain `select: false`; explicit projections and create results can still contain hashes inside the document. Entity-owned User/Session `toJSON` transforms remove those hashes from document JSON and compose with the global id transform. This protection does not apply to `lean`, aggregate or `toObject`, and can be bypassed by caller serialization options. Future endpoint-owned response DTOs must use explicit allowlist mapping, convert id/references to strings, and omit hashes; never return documents directly or spread document/`toObject` into HTTP responses. Those DTOs and endpoints are not implemented. No business transitions, aggregate recalculation or recommendation logic is implemented.

[MongoTransactionService.run](../../src/infrastructure/database/services/mongoTransaction.service.ts) starts a session, executes `withTransaction` and ends the session in `finally`. Pass the received session to participating repository operations; transaction scope alone does not attach it to arbitrary queries.

Pagination defaults to page 1 and limit 20, floors finite values and clamps explicit limits to 1–100 through [normalizePagination](../../src/shared/functions/pagination/normalizePagination/core/normalizePagination.ts). The paginated repository normalizes a non-empty caller sort through Mongoose Query.sort, otherwise uses a non-empty defaultSort, otherwise `{ _id: -1 }`. Object, string and tuple forms are supported without mutating caller/default sort objects. An absent `_id` is appended as the last descending tie-breaker; an explicit `_id` retains its direction and position. Equal sort values therefore have deterministic ordering, but offset pagination can still shift during concurrent writes. The repository runs items and count sequentially when a session is present, otherwise concurrently. [createPaginatedResult](../../src/shared/functions/pagination/createPaginatedResult/core/createPaginatedResult.ts) returns items, page, limit, total, pages and next/previous flags.

## Redis cache

[CacheModule](../../src/infrastructure/cache/cache.module.ts) provides cache-manager backed by Keyv Redis and an app-name namespace. [CacheService](../../src/infrastructure/cache/services/cache.service.ts) exposes `get`, `set` and `delete`, normalizing missing values to `null`.

[CacheEndpoint](../../src/infrastructure/cache/decorators/CacheEndpoint/core/CacheEndpoint.ts) installs the Nest CacheInterceptor and a TTL from `ttlMs` or the existing default constant. It is not a custom per-user cache key policy; inspect key behavior before applying it to personalized responses.

## Search

[SearchService](../../src/infrastructure/search/services/search.service.ts) exposes `ensureIndex`, `upsert`, `search`, `delete` and `clear`. `ensureIndex` creates missing indexes with primary key `id` and updates configured searchable, displayed, filterable, sortable attributes and ranking rules. Concurrent initialization of the same index shares a promise within the service instance; it is not a persistent or distributed lock.

Mutations and index initialization accept `waitForTask`, defaulting to false. Successful enqueueing does not prove that a document is already searchable. Search maps Meilisearch results into [ISearchResult](../../src/infrastructure/search/types/ISearchResult.ts). The current source has infrastructure APIs but no domain indexing/synchronization consumer.
