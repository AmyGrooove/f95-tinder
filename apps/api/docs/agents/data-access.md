# Data access

Read for persistence, pagination, Redis cache or Meilisearch changes. Configuration is described in [runtime](runtime.md).

## MongoDB

[DatabaseModule](../../src/infrastructure/database/database.module.ts) creates the Mongoose connection with `autoIndex: true` and registers global [timestamp](../../src/infrastructure/database/functions/applyTimestampsPlugin/core/applyTimestampsPlugin.ts), [version-key](../../src/infrastructure/database/functions/applyVersionKeyPlugin/core/applyVersionKeyPlugin.ts) and [toJSON](../../src/infrastructure/database/functions/applyToJsonPlugin/core/applyToJsonPlugin.ts) plugins. The timestamp plugin enables timestamps only when the schema has no explicit setting, preserving `false` and custom timestamp options. The version-key plugin sets versionKey:false on every schema. Connection plugins also apply to child schemas. The JSON transform preserves a prior transform, enables virtuals, converts `_id` to string `id` and removes `_id` and `__v`. These are document serialization rules; do not assume every query result has already been serialized.

Existing repository classes take a model and optional default sort through [MongoRepositoryCore](../../src/infrastructure/database/services/mongoRepositoryCore.repository.ts):

| Existing object                                                                                         | Public operations                                                        |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| [MongoReadRepository](../../src/infrastructure/database/services/mongoRead.repository.ts)               | `findById`, `findOne`, `findMany`, `checkIsExists`                       |
| [MongoWriteRepository](../../src/infrastructure/database/services/mongoWrite.repository.ts)             | `create`, `updateById`, `updateByFilter`, `deleteById`, `deleteByFilter` |
| [MongoPaginationRepository](../../src/infrastructure/database/services/mongoPagination.repository.ts)   | `findManyPaginated`                                                      |
| [MongoBulkRepository](../../src/infrastructure/database/services/mongoBulk.repository.ts)               | `createMany`, `updateMany`, `deleteMany`, `bulkWrite`                    |
| [MongoAggregationRepository](../../src/infrastructure/database/services/mongoAggregation.repository.ts) | `aggregate`                                                              |

These generic classes are not registered as model-specific providers by DatabaseModule. The 26 entity repositories compose them through public readonly `read`, `write`, `pagination`, `bulk` and `aggregation` properties, using one injected `Model<HydratedDocument<Entity>>` without a default sort; see [TagRepository](../../src/entities/tag/services/tag.repository.ts). Schema classes supply the raw data types; root classes extend [MongoEntity](../../src/infrastructure/database/types/MongoEntity.ts) to inherit `_id`, `createdAt` and `updatedAt` declarations without adding schema paths or defaults. `HydratedDocument<Entity>` supplies the document type required by the existing repository core. Derived `TCreate<Entity>` aliases live in schema files and use [TCreateEntity](../../src/infrastructure/database/types/TCreateEntity.ts) to omit generated fields, make explicitly listed defaulted fields optional and replace explicitly listed nested field types. The helper omits generated fields only from MongoEntity-compatible root types; child types retain their own fields, including explicit updatedAt. All-optional child create types remain `Partial<Child>`. Nested overrides are removed from the original shape before being merged, preserving nested create defaults without duplicating storage interfaces. Reuse the entity boundary rather than creating another persistence client. Reads and single-document mutations can return `null`. `updateById` and `updateByFilter` request the updated document unless the caller supplies `options.new`. `MongoReadRepository.findMany` uses the configured default sort only when no caller sort is supplied.

`updateByFilter` and `deleteByFilter` each execute one `findOneAndUpdate` or `findOneAndDelete`, accepting schema-typed filters and options through the existing `entityRepository.write`. Future endpoint-services must build `{ _id: id, user: authenticatedUserId }` from verified authentication context for owned records, rather than trusting body/query ownership or using read-then-write by ID. A `null` result must map to the same HTTP 404 for missing and foreign records. Repositories do not decide authorization, start transactions or create HTTP exceptions; these endpoint behaviors remain unimplemented.

`updateById`, `updateByFilter` and `updateMany` default `runValidators` to true while preserving explicit false, session and other caller options. Update validators cover supported operators and changed paths only: `$inc`, array operators and pipelines do not guarantee whole-document invariants. `bulkWrite` updates and update pipelines remain trusted low-level APIs without full schema validation. Future endpoints must construct allowed updates from validated DTOs, never accept client MongoDB filters, operators, projections or QueryOptions, and validate business invariants in their application-service.

[AppModule](../../src/app/app.module.ts) imports 26 entity modules. Each module registers its own model and exports only its repository; consumers import that entity module. Direct paths follow the existing TagModule/TagRepository pattern; no layer-wide entity barrel was introduced. P1 added Movie, SourceArtifact, SearchIndexState, RecoveryChallenge, RecommendationSnapshot, RecommendationRequest, RecommendationProjectionState, UserAction and RecommendationExposure. Business endpoints, import/auth/ranking orchestration remain absent.

Movie retains its existing revision. Shared ItemId={type,id} references remain unchanged and identify the corresponding type-specific document. [LanguageText](../../src/entities/shared/schemas/languageText.schema.ts) is {ru,en}, with each translation nullable and defaulting to null. Dictionary names are single objects; Feature.description, ItemRelationRole.description, Source.description and Tag.description are required LanguageText objects defaulting to {ru:null,en:null}. RelationSide.roleNameOverride replaces specRoleName and is a required LanguageText object defaulting to {ru:null,en:null}; it is optional in TCreateRelationSide. Tag.aliases is a string array defaulting to []; each alias must contain non-whitespace text, without a locale field. Tag.key uses CAMEL_CASE_REGEX with unique index tagKeyUnique. Tag.group is nullable with default:null; group, description, aliases and embedding are optional in TCreateTag. Movie.descriptions retains an array of bilingual entries. LocalizedTitle and Movie.titles have been removed from the persistence schemas. Origin, OriginEvidence, OriginInput and MovieFieldOrigin have been removed, along with their embedded origin/definitionOrigin/fieldOrigins fields. StorageRef and SnapshotRef are metadata references, not proof that bytes exist. Child schemas disable _id/id/timestamps; explicit ItemId.id and Embedding.updatedAt remain stored. Root collections use the exact schema class names. Redundant strict:true and timestamps:true declarations were removed; strict mode remains the Mongoose default and timestamps come from the connection plugin. Version keys are disabled by a connection plugin for all schemas. Feature no longer stores applicableTypes, valueConstraints, scope, tasteTransfer, transferTypes, revision or definitionOrigin; group and unit are nullable with default:null and optional in TCreateFeature; their enum values remain undefined. Feature.key and ItemRelationRole.key use shared CAMEL_CASE_REGEX for lower camel case ASCII identifiers. Their unique indexes are named featureKeyUnique and itemRelationRoleKeyUnique respectively. ItemRelationRole.group is nullable with default:null; group and description are optional in TCreateItemRelationRole. ItemFeature indexes are named itemFeatureUnique (unique item/feature pair) and featureItemLookup (feature-first lookup). Index names changed in source only; existing database indexes were not migrated. ItemFeature no longer stores featureRevision. Earlier [MVP design](../../../../docs/mvpDesign.md) and [P1 report](../../../../docs/mvpImplementationPlan.md#отчёт-p1--8-октября-2026-года) contracts must be reconciled with these later source changes.

UserSourceAccount stores only user, source and externalId plus generated fields; username and profileUrl were removed. [ItemMetric](../../src/entities/itemMetric/schemas/itemMetric.schema.ts) stores one current aggregate per Item with unique(item.type,item.id), named itemMetricUnique. ItemMetric.recommendationsCount replaces views and counts recommendation occurrences, including repeated recommendations to the same user; all root and embedded metric counters are nonnegative safe integers. Aggregate recalculation and consistency checks are deferred to a future cron task, which is not implemented. Relation has first/second item-role lookup indexes named relationFirstLookup and relationSecondLookup; the unique tupleKey index was removed because its field is absent from the current schema. Session declares a single-field expiresAt TTL index named sessionExpiryTtl with expireAfterSeconds:600 (10 minutes after expiresAt), configured by entity-owned SESSION_EXPIRY_GRACE_SECONDS, plus sessionRefreshTokenHashUnique and sessionUserExpiryLookup. [SourceArtifact](../../src/entities/sourceArtifact/schemas/sourceArtifact.schema.ts) uses ref={backend:s3,bucket,key}, hash/size and immutable metadata. [UserAction](../../src/entities/userAction/schemas/userAction.schema.ts) has a typed kind/payload union, exact-key payload validator, receipt, before/after changes and frozen feature basis. minimize:false preserves empty command payloads. RecommendationExposure links one accepted actionEventId=exposureId, request/result/issued identity/versions/basis. UserItem stores rating as an integer 1..10 or null and retains attempts with at most one active IN_PROGRESS/ON_HOLD entry. UserItem.note is trimmed and blank strings become null. UserItem indexes are named userItemUnique (unique user/item pair) and itemUsersLookup. ItemAttempt.progress uses isInt plus shared isNonNegativeSafe, preserving null and min:0. Date and status transition rules remain deferred to future operations and cron consistency checks. Lineage, conflicts, revision/checkpoint and removed attempt IDs were removed; attempts no longer have UUIDs, sequence fields or lineage and retain minute-only nullable safe-integer progress. UserRecommendationState retains no-show null dates and exclusion, without lastSkippedAt, policyVersion, revision/checkpoint or lineage. Its shownCount and skippedCount use isInt plus shared isNonNegativeSafe. Its unique user/item index is named userRecommendationStateUnique. The record is temporary: expiresAt is its nullable retention deadline, distinct from nextEligibleAt (recommendation cooldown). No TTL or cleanup job is implemented for this entity; consistency checks remain deferred. IdentityBasis and its embedded identityBasis/identity fields have been removed from the persistence schemas. Semantic transitions, owner/receipt correctness across collections, atomic sequence/counter changes and append-only application behavior belong to P4. Generic repositories remain trusted low-level APIs, including write/delete; immutable paths are not database WORM guarantees.

The [User schema](../../src/entities/user/schemas/user.schema.ts) trims and lowercases username/email; empty email becomes null. External identifiers, hashes and dictionary keys retain exact comparison. The unique email partial filter is `{ email: { $type: "string" } }`; linked-account uniqueness uses `{ "linkedAccounts.provider": { $type: "string" }, "linkedAccounts.externalId": { $type: "string" } }`, allowing multiple users with null email or empty linkedAccounts. A whole-array validator rejects repeated providers within a user, which a unique multikey index alone does not prevent. Future account linking must replace the full array with `$set` and validators; `$push`, `$addToSet` and dotted updates do not enforce this whole-array contract. Lookup must use `linkedAccounts: { $elemMatch: { provider, externalId } }` to match both fields within one element. OAuth/linking is not implemented.

Uniqueness depends on deployed MongoDB indexes, not a preliminary `findOne`. Future endpoint-services must map duplicate-key errors to HTTP 409 without exposing raw DB errors, hashes or internal values. Existing non-unique indexes with the same names require a separately managed rollout: check duplicates including normalized username/email and repeated linked providers, agree old-data normalization, then replace affected indexes with concurrency controls and verify the result. `autoIndex: true` does not safely migrate those indexes. This preparation does not connect to the external database or apply migrations. Session declares an expiresAt TTL index; its declaration does not prove deployment. Authorization must check expiry independently of document cleanup. Source declarations do not prove deployment, concurrent uniqueness or query performance.

EItemType is still movie-only. User.username uses /^[a-z0-9_]+$/ after existing lowercase/trim normalization and unique index userUsernameUnique. User.displayName uses trim without uniqueness or a custom whitespace validator. Email and linked-account indexes are named userEmailUnique and userLinkedAccountUnique; their partial filters are unchanged. User.toJSON removes passwordHash and accessCodeHash, composed with the global JSON plugin; lean, aggregate and toObject output still require a transport allowlist. User retains accessCodeHash and has no credentialVersion, revision/actionSequence, accessCodeChangedAt, catalogPermissions or locale; EUserType and temporaryCodeHash were removed from source without migrating old data. LinkedAccount supports Google and Yandex. PasswordHash is retained as an inactive existing field. Session stores user, refreshTokenHash, userAgent, expiresAt and lastRefreshedAt; rotation, currentRefreshJti, refreshIssuedAt, revision, revoke fields and rotationReceipt were removed. UserSetting owns required locale with ELocale.RU/EN and default:ELocale.RU; locale is optional in TCreateUserSetting. Its unique user index is named userSettingUnique. RecoveryChallenge (including durable delivery ref) provides persistence only; provider verification, encryption, mail delivery, recovery and rolling expiry arithmetic require P3.

Credential hashes/ciphertext use select:false where declared. User and Session no longer define local toJSON transforms; select:false still excludes their hashes from default reads, but explicit selections/create results are not scrubbed by the global id transform. This protection does not apply to lean, aggregate or toObject, and explicit projections/create results can still contain sensitive values. Future response DTOs must map an allowlist and never return documents directly.

autoIndex:true remains enabled in DatabaseModule. Starting an application context can write index declarations; do not target an existing database with new P1 schemas without an separately agreed inventory/backup/normalization/index rollout. No external database was connected and no migration or index operation was executed. Before runtime acceptance select isolated Mongo/Redis/S3/queue/search namespaces and verify deployed unique indexes and transaction topology.

[MongoTransactionService.run](../../src/infrastructure/database/services/mongoTransaction.service.ts) accepts run(callback, options?), starts a session, passes the optional options to withTransaction and ends the session in finally. The options type is derived from the installed ClientSession.withTransaction; existing callers retain their behavior. New operation services can explicitly supply snapshot/majority/primary concerns; this does not configure or verify the actual MongoDB deployment. Pass the received session to participating repository operations; transaction scope alone does not attach it to arbitrary queries.

Pagination defaults to page 1 and limit 20, floors finite values and clamps explicit limits to 1–100 through [normalizePagination](../../src/shared/functions/pagination/normalizePagination/core/normalizePagination.ts). The paginated repository normalizes a non-empty caller sort through Mongoose Query.sort, otherwise uses a non-empty defaultSort, otherwise `{ _id: -1 }`. Object, string and tuple forms are supported without mutating caller/default sort objects. An absent `_id` is appended as the last descending tie-breaker; an explicit `_id` retains its direction and position. Equal sort values therefore have deterministic ordering, but offset pagination can still shift during concurrent writes. The repository runs items and count sequentially when a session is present, otherwise concurrently. [createPaginatedResult](../../src/shared/functions/pagination/createPaginatedResult/core/createPaginatedResult.ts) returns items, page, limit, total, pages and next/previous flags.

## Redis cache

[CacheModule](../../src/infrastructure/cache/cache.module.ts) provides cache-manager backed by Keyv Redis and an app-name namespace. [CacheService](../../src/infrastructure/cache/services/cache.service.ts) exposes `get`, `set` and `delete`, normalizing missing values to `null`.

[CacheEndpoint](../../src/infrastructure/cache/decorators/CacheEndpoint/core/CacheEndpoint.ts) installs the Nest CacheInterceptor and a TTL from `ttlMs` or the existing default constant. It is not a custom per-user cache key policy; inspect key behavior before applying it to personalized responses.

## Search

[SearchService](../../src/infrastructure/search/services/search.service.ts) exposes `ensureIndex`, `upsert`, `search`, `delete` and `clear`. `ensureIndex` creates missing indexes with primary key `id` and updates configured searchable, displayed, filterable, sortable attributes and ranking rules. Concurrent initialization of the same index shares a promise within the service instance; it is not a persistent or distributed lock.

Mutations and index initialization accept `waitForTask`, defaulting to false. Successful enqueueing does not prove that a document is already searchable. Search maps Meilisearch results into [ISearchResult](../../src/infrastructure/search/types/ISearchResult.ts). The current source has infrastructure APIs but no domain indexing/synchronization consumer.
