# Security

Read for authentication, roles, token creation or rate limits. HTTP/CORS configuration is in [runtime](runtime.md).

[SecurityModule](../../src/infrastructure/security/security.module.ts) exports `SecurityJwtService`, `SecurityCookieService`, `AccessTokenGuard` and `RolesGuard`. [MovieImportModule](../../src/endpoints/movieImport/movieImport.module.ts) imports it and protects its controller with `AccessTokenGuard`, then `RolesGuard`, and `@Roles(EUserRole.ADMIN)`. None of these guards is configured as the global application authentication guard.

[SecurityCookieService.setAuthCookies(reply, tokens)](../../src/infrastructure/security/services/cookie.service.ts) uses Nest's HttpAdapterHost to set `__Host-accessToken` and `__Host-refreshToken` with HttpOnly, Secure, SameSite=Strict and Path=/. Max-Age values reuse the JWT expiration constants in seconds. Controllers pass the native response through `@Res({ passthrough: true })` and an IAuthTokens object; the service does not issue tokens or create server sessions.

`SecurityCookieService.clearAuthCookies(reply)` clears both auth cookies through the same adapter with matching Path=/, HttpOnly, Secure and SameSite=Strict options. [AuthController.logout](../../src/endpoints/auth/controllers/auth.controller.ts) calls it only after successful server-session deletion.

[SecurityJwtService](../../src/infrastructure/security/services/jwt.service.ts) signs/verifies access and refresh tokens using separate configured secrets and HS256. Access expiration is 600 seconds (10 minutes); refresh expiration is 10,368,000 seconds (120 days). Both expiration constants use seconds and are shared with registration cookie lifetimes. Issuer is the app name and audience is `<appName>-api`. Access payloads carry `sub`, `sessionId`, a single `role: string` and `type: "access"`; refresh payloads carry `sub`, `sessionId`, `type: "refresh"` and are rejected if they contain `role` or the legacy `roles` field. Verification checks token type and payload field types and converts failures into UnauthorizedException.

[AccessTokenGuard](../../src/infrastructure/security/guards/accessToken.guard.ts) requires a single Bearer token and stores `{ id, sessionId, role }` on `request.authPrincipal`. [CurrentUser](../../src/infrastructure/security/decorators/CurrentUser/core/CurrentUser.ts) reads this principal. These objects do not query a user/session database or establish refresh rotation, logout or revocation semantics.

[Roles](../../src/infrastructure/security/decorators/Roles/core/Roles.ts) sets metadata consumed by [RolesGuard](../../src/infrastructure/security/guards/roles.guard.ts). Method metadata takes priority over controller metadata. Empty/missing roles permit access; otherwise the principal's single role must be included in the allowed role list. Access JWTs carrying only the former `roles` array are rejected; callers need a newly issued access token. Run the access guard before the roles guard for a protected endpoint.

Password helpers already exist as [hashValue](../../src/infrastructure/security/functions/hashValue/core/hashValue.ts) and [compareHash](../../src/infrastructure/security/functions/compareHash/core/compareHash.ts); inspect them before adding another hashing implementation.

[ThrottlingModule](../../src/infrastructure/throttling/throttling.module.ts), unlike SecurityModule, is imported by AppModule and registers a global `ThrottlerGuard` with Redis storage. Its [default](../../src/infrastructure/throttling/static/THROTTLE_DEFAULTS.ts) is 100 requests per 60,000 ms. Health routes currently have no local throttling exemption.

## MVP persistence boundary

`POST /auth/login/code` is handled by [AuthController.loginByCode](../../src/endpoints/auth/controllers/auth.controller.ts) and [AuthService.loginByCode](../../src/endpoints/auth/services/auth.service.ts). [LoginCodeBodyDto](../../src/endpoints/auth/dto/body/loginCode.body.ts) accepts only the case-sensitive 32-character base64url access code; no username is required. The service finds the User by the code's SHA-256 hex digest with passwordHash required to be null and selects only id and role. Registration generates 24 random bytes and stores the same SHA-256 digest in accessCodeHash. User declares the partial unique userAccessCodeHashUnique index for string hashes. Previously issued bcrypt-backed codes are unsupported; no data migration or deployed-index verification was performed. Wrong codes and accounts with a password return the same 401; malformed, missing or extra input fields return 400. Success creates a new Session with userAgent through SessionRepository.createNew, preserves other sessions, sets both auth cookies and returns 204 without a body with Cache-Control:no-store. Tokens and hashes are not returned in JSON. The route allows 5 requests per 60,000 ms per the existing IP-based throttling; global CSRF protection applies.

`GET /account/whoami` is handled by [AccountController](../../src/endpoints/account/controllers/account.controller.ts) and [AccountService](../../src/endpoints/account/services/account.service.ts). Nest's built-in `@Cookies` extracts `__Host-accessToken` without an extra cookie plugin. The service verifies the access JWT, validates ObjectId claims, requires a Session matching both sessionId and user with expiresAt greater than the current time, and requires an existing User. Authorization is local to this use case; it does not use the Bearer guard or establish a shared session guard. The response explicitly maps `user: { id, username, displayName, avatarUrl, role }` and `session: { id, expiresAt }`, with the role read from the current User and the expiry serialized as ISO 8601. Successful responses use Cache-Control:no-store. Missing or invalid credentials, users or sessions produce 401. Swagger declares the `accessCookie` security scheme in bootstrap. No tokens or hashes are returned.

[User](../../src/entities/user/schemas/user.schema.ts) retains accessCodeHash and passwordHash with select:false; credentialVersion, revision/actionSequence, accessCodeChangedAt, catalogPermissions and locale were removed. [Session](../../src/entities/session/schemas/session.schema.ts) retains user, refreshTokenHash (select:false), userAgent, expiresAt and lastRefreshedAt; rotation/jti/issuedAt/revision/revoke/receipt fields were removed. UserSetting owns required ELocale.RU/EN with default:ELocale.RU; locale is optional in TCreateUserSetting. Its unique user index is named userSettingUnique. Linked providers remain Google and Yandex; source changes do not migrate stored documents.

RecoveryChallenge/durable delivery reference is a schema/repository only. The OAuthAttempt entity was removed from the MVP; OAuth state storage and reauth binding must be designed when implementing authentication. Encrypted metadata holds ciphertext/iv/authTag/keyVersion; no crypto implementation, provider call, token issuance, recovery mail, HTTP endpoint or live-session guard was introduced. User has a local toJSON transform removing passwordHash and accessCodeHash, composed with the global JSON plugin. Session has no local hash-removal transform; select:false affects default queries only. Lean, aggregate, toObject and raw document fields still need an explicit transport allowlist.

`PATCH /auth/session/refresh` is handled by [AuthController](../../src/endpoints/auth/controllers/auth.controller.ts) and [AuthService.refresh](../../src/endpoints/auth/services/auth.service.ts). It takes only `__Host-refreshToken`, verifies the refresh JWT and ObjectId claims, loads the current User role, and atomically replaces the Session hash using a filter on sessionId, user, old SHA-256 refresh hash and expiresAt greater than now. The same Session is extended by 120 days and lastRefreshedAt is recorded. Refresh JWT signing adds a random UUID `jti`, so successive tokens differ even within one second. A concurrent/replayed old token gets 401 without setting or clearing cookies; clients must coordinate refresh across tabs. Success returns 204 with no body, Cache-Control:no-store and both auth cookies. No valid access token is required. The existing global CSRF protection and throttling apply. Bootstrap declares the `refreshCookie` Swagger scheme. Session lifecycle belongs to the auth endpoint layer, not the security infrastructure guards.

`POST /auth/logout` is handled by `AuthController.logout` and [AuthService.logout](../../src/endpoints/auth/services/auth.service.ts). It verifies `__Host-accessToken` and ObjectId claims, then atomically deletes only the Session matching sessionId, user and expiresAt greater than now. Success clears both auth cookies and returns 204 without a body with Cache-Control:no-store. Missing/invalid/expired access credentials or a missing/expired Session return 401 without changing cookies, including repeated logout; an expired access token requires refresh first. Other sessions are preserved. Global CSRF protection and throttling apply. Deletion prevents subsequent whoami and refresh authorization for that Session; the separate Bearer-only AccessTokenGuard still does not query sessions.
