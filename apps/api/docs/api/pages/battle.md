## Текущее покрытие

| Сценарий                               | Состояние                            | Что есть / чего не хватает                                                                                                              |
| -------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Источник — коллекция                   | Частично                             | `QUERY /collections/:id/items` даёт постраничный состав с поиском, фильтрами и личными данными; это ещё не зафиксированный набор Баттла |
| Источник — своя библиотека по статусам | Нет                                  | Нужен `LIB-02`                                                                                                                          |
| Данные пары и краткий просмотр         | Частично                             | Карточки состава содержат id/type/title/media и часть личных данных, но не полный набор сведений инструмента; нужен `ITEM-01/03`        |
| «Победитель остаётся», итог            | Нет отдельного контракта инструмента | Механика может выполняться на клиенте; необходимость серверных шагов и сохранения не выбрана                                            |
| Сохранение относительных предпочтений  | Уточнить                             | Сценарий записи сравнений для рекомендаций ещё не определён                                                                             |

Код источника коллекции: [CollectionReadController](../../../src/endpoints/collection/controllers/collectionRead.controller.ts), [CollectionContentService](../../../src/endpoints/collection/services/collectionContent.service.ts).

## Осталось

- [ ] `BATTLE-01`: определить и обеспечить получение полного набора кандидатов из библиотеки или коллекции: условия, порядок, объём и поведение при изменении источника во время сравнения. Переиспользовать `LIB-02` и существующее чтение коллекций; отдельный endpoint создавать только при необходимости выбранного контракта.
- [ ] `BATTLE-02`: определить границу клиентского состояния и backend; реализовать выбранные серверные операции восстановления/сравнений, если они входят в этап. Если серверная часть не нужна, закрыть пункт со ссылкой на принятое решение и контракт источника.

## Уточнить

Минимум два кандидата и исключение completed/dropped/«Не рекомендовать» по умолчанию для коллекции пока являются предложениями. Требуют решения фильтры и их изменение, порядок, лимит набора, шаг назад, восстановление, доступ гостя и запись сравнений как относительных предпочтений.

Победа и поражение не меняют статус библиотеки и числовую оценку. Для них нельзя использовать мутации UserItem как замену отдельному сигналу предпочтений. Открытие информации не выбирает победителя. Запуск со страницы коллекции передаёт источник в настройку, а не автоматически изменяет личные данные.

## Проверка результата

Проверять соответствие набора источнику, отсутствие потери кандидатов из-за пагинации, механику «победитель остаётся», итог и отсутствие побочных изменений библиотеки. Runtime-проверки не выполнялись.
