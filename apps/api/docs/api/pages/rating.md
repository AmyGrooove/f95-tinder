# Оценка: покрытие API

[Индекс покрытия](readme.md) · [Требования страницы](../../product/pages/rating.md) · [Общие операции](shared.md)

## Текущее покрытие

| Сценарий                            | Состояние                   | Что есть / чего не хватает                                                                      |
| ----------------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------- |
| Поставить оценку                    | Реализовано                 | `PATCH /userItems/:id` принимает поле `rating`: целое 1–10 или null; инструмент использует 1–10 |
| Очередь completed без личной оценки | Нет                         | Нет GET-выдачи библиотеки с нужным отбором                                                      |
| Карточка и краткий просмотр         | Нет самостоятельного чтения | Нужны публичные данные произведения `ITEM-01/03`                                                |
| Пропуск, порядок и восстановление   | Уточнить                    | Пока не определены правила очереди и необходимость серверного хранения                          |

Код сохранения: [UserItemController](../../../src/endpoints/userItem/controllers/userItem.controller.ts) и [UserItemService](../../../src/endpoints/userItem/services/userItem.service.ts). Мутация рейтинга сама по себе не ограничена completed: это условие источника инструмента, а не повод менять общий контракт оценки.

## Осталось

- [ ] `RATING-01`: через `LIB-02` обеспечить очередь только собственных completed с `rating=null`, ID UserItem для записи и данными кандидата. Исключать уже оценённые, не заполнять ими исчерпанную очередь.
- [ ] `RATING-02`: определить порядок, пропуски, длину и восстановление; реализовать необходимую backend-часть. Отдельный маршрут для каждого действия не требуется автоматически.

## Уточнить

Когда повторно показывать пропущенное, как получать следующего кандидата после изменения библиотеки в другой вкладке и хранить ли очередь на сервере. После успешного сохранения клиент переходит дальше; ошибка оставляет кандидата. Инструмент не создаёт UserItem, не меняет статус и не пересматривает существующие оценки.

## Проверка результата

Проверять completed + отсутствие оценки, сохранение по ID UserItem, отсутствие записи при пропуске, окончание очереди и сохранение текущего кандидата при ошибке. Runtime-проверки не выполнялись.
