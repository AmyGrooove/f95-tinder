## Как проходит запрос

Публичные данные одного произведения описаны в [контракте GET /items/:id](pages/item.md) и реализованы в [модуле item](../../src/endpoints/item/item.module.ts).

В [AppModule](../../src/app/app.module.ts) подключены AuthModule, AccountModule, UserItemEndpointModule, CollectionEndpointModule, ItemEndpointModule и SearchEndpointModule. Контроллер определяет метод и путь, принимает DTO и cookie, вызывает сервис и формирует HTTP-ответ. Глобальный [ValidationPipe](../../src/app/functions/configureApplication/core/configureApplication.ts) преобразует входные DTO и отклоняет неизвестные поля. Составные сегменты путей пишутся в camelCase; у этих маршрутов нет общего префикса или выбранной версии.

Сервисы `endpoints/*/services` выполняют пользовательскую операцию: проверяют доступ и бизнес-правила, координируют репозитории и транзакции, явно отображают результат в response DTO. Репозитории `entities/*/services` работают со своей моделью MongoDB. Они экспортируются модулем сущности; репозиторий не определяет HTTP-ошибки и не открывает транзакцию вместо вызывающего сервиса.

Защищённые операции используют cookie `__Host-accessToken`, проверку JWT и серверной сессии; проверки выполняются в сервисах конкретных операций. Наличие JWT само по себе не заменяет проверку сессии. Обновление токенов использует `__Host-refreshToken` и атомарное сравнение сохранённого хеша. Cookie изменяются через SecurityCookieService. Отдельный Bearer AccessTokenGuard не заменяет эту схему. Подробности — в [контракте](accountAndAuthSpec.md#токены-и-проверка-доступа) и [security context](../../agents/security.md).

Многодокументные изменения подборки и изменения библиотеки с чтением и обновлением попыток выполняются через MongoTransactionService. Его session явно передаётся участвующим запросам. Удаление UserItem физически удаляет запись вместе с попытками; удаление Collection только выставляет deletedAt. Единого автоматического поведения удаления для всех сущностей нет.

## Как связаны данные

`Item` — единая карточка произведения; EItemType содержит семь типов видео и игр. Точные характеристики хранятся в общих полях и блоках movie/series/game. Tag задаёт справочник категорий, ItemTag — связь тега с конкретным Item. SourceItem сопоставляет внешний идентификатор источника с Item. Полный список полей и связей — в [сущностях](entities.md).

`UserItem` — личная запись пользователя о произведении: статус, оценка, избранное, заметка и история попыток. Пара пользователь/Item уникальна. Семь статусов включают skipped на 90 дней и бессрочный blocked, вне обычной библиотеки. Попытки содержат isCompleted вместо status; их изменения не меняют статус UserItem. Установка completed отмечает последнюю попытку завершённой. QUERY /userItems возвращает краткие собственные записи по ID UserItem; чтения по Item и полного чтения библиотеки пока нет.

`Collection` — публичная ручная подборка. Она хранит метаданные и порядок блоков group/text; CollectionItem отдельно хранит Item, groupId, позицию и заметку включения. UserCollection хранит реакции на саму подборку. Состав подборки и библиотека UserItem независимы: включение фильма в подборку не добавляет его в библиотеку.

При редактировании подборки клиент передаёт version. Сервис проверяет автора, итоговые блоки и ссылки на группы; репозиторий условно обновляет документ с совпавшей версией, а изменения состава выполняются в той же транзакции. Устаревшая версия даёт 409. Чтение состава публичное, поддерживает grouped/flat, одну пагинацию по Item и публичные фильтры, включая общую оценку. UserItem не загружается и не возвращается; cookie авторизации не проверяется.

| Каталог      | GET /items/:id; QUERY /search по названиям, aliases и описаниям всех типов Item; чтение в подборке | Каталог без запроса, справочники фильтров, импорт                                                                |
| Источники    | KodikService, PageCollectorService, SourceDataWriterService                                        | Законченный сценарий сбора фильмов, запуск и статус через административный API, применение подготовленных данных |
| Рекомендации | Схемы UserTasteProfile, ItemMetric; исключения skipped/blocked в UserItem                          | Выдача рекомендаций с применением исключений, история показов и пересчёт производных данных                      |

Публичный [QUERY /search](pages/search.md#реализованный-общий-поиск) возвращает три группы — произведения, пользователи и подборки — через Meilisearch с фоновой синхронизацией индексов. Фильтры и сортировки текстового поиска реализованы; общий каталог без запроса и справочники фильтров остаются отдельной задачей. Действующие операции и будущие требования следует сверять по отдельным контрактам.
