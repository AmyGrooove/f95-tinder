# Старый Swagger: сопоставление с экранами

[Навигатор](readme.md) · [Исходный список](swagger.md) · [Проверенные desktop](screensDesktop.md) · [Применение к новому Bisky](newBiskyReferenceApplication.md)

Все 100 записей сохранены по одному разу в исходном порядке. Связи — аналитические кандидаты, не наблюдение HTTP-запросов. 24 октября просмотрены все 187 локальных PNG: desktop, mobile, модальные окна и меню. Отсутствие отдельного маршрута не доказывает отсутствие функции в старом приложении. JSON содержит те же записи, текущие desktop-пути и поле screenshots для всех уже сопоставленных групп. Полнота просмотра изображений не означает полноту связей каждой страницы с API.

Таблицы ниже отражают исходный Swagger, включая его неизвестные параметры и расхождения с кодом. Подтверждённые позже query, проверки доступа, DTO и frontend-потребители вынесены в [сверку реализации](implementation.md). В частности, код использует `/anime/:ID/userAnimeReactions`, ограничивает поисковые типы и не подтверждает все архивные маршруты главной. Исходные записи и JSON не заменяются контрактами другой ревизии.

## Сценарии без однозначного API

Дружба; уведомления; сезон/задания/награды AnimePass; календарь активности; история правок карточки; написанные пользователем комментарии; чтение предложений; сохранение/отмена раундов; фактический показ рекомендаций. Неподписанный переключатель просмотра не задаёт новый маршрут.

Точная привязка полей к base/mini/additional, DTO, фильтры, пагинация и права неизвестны. POST /bannedAnime не приравнивается к персональному «Не предлагать», лицензии или территориальной недоступности. Общие реакции могут использоваться несколькими страницами; старый набор частных и общих операций не переносится автоматически.
