# Endpoint implementation routes

Read when changing HTTP use cases under `src/endpoints`. The [API overview](../public/docs/api/readme.md) explains implemented behavior; the linked specifications own detailed route contracts. Verify facts against production code before changes.

## Request flow diagrams

The human-facing [endpoint catalog](../public/docs/api/endpoints.md) links to individual operation flows in [docs/api/requestFlows](../public/docs/api/requestFlows/readme.md). They render in `/knowledge/`, grouped into auth, account, catalog, userItems, collections and service pages. Each operation has a stable anchor, example, diagram, consistency/error notes and source references. Follow the guide, update the catalog and link each area page from [the knowledge sidebar](../public/knowledge/sidebar.md) for navigation and search.

Maintain an existing diagram in the same change whenever its endpoint's access checks, branches, called services, entity reads/writes, transaction boundaries, events, jobs, external calls or HTTP-response timing change. Changes to shared/background handlers require checking diagrams that reference those handlers. Adding, renaming or removing a route also requires updating the catalog, route counts, headings and links. Internal refactoring that preserves the depicted behavior needs no redraw. Verify controller/module wiring, actual call sites and job/event handlers; an import graph is not an execution trace. Keep simple action labels and entity names in the diagram, and source links and implementation details below it. Show only real events, distinguish awaited enqueueing from background execution, and document failures that can happen after a committed transaction. Do not present planned operations or static inspection as observed runtime behavior.

Use Mermaid `flowchart TD` blocks with `accTitle`/`accDescr`, the guide's shapes and shared semantic classes; do not duplicate palette definitions or per-diagram configuration. Verify rendering and navigation in knowledge when possible, and explicitly report a browser-verification limit otherwise. Read [runtime context](runtime.md) when changing the renderer, local assets or palette.

## Ownership and composition

Read DTOs compose [QueryFieldsDto](../src/entities/shared/dto/query/queryFields.dto.ts) with Swagger PickType and [createSortDto](../src/entities/shared/functions/createSortDto/index.ts). [ValueFilterProperty](../src/entities/shared/decorators/ValueFilterProperty/index.ts) validates nested filters and declares the per-use OpenAPI schema.

Authenticated [QUERY /recommendations](../public/docs/api/requestFlows/catalog.md#recommendations) is handled by [RecommendationsController](../src/endpoints/recommendations/controllers/recommendationsController/core/recommendations.controller.ts) in RecommendationsModule. The HTTP service maps public `filter.statuses` to internal eligibility and converts tag IDs and maps current poster cards with ItemStats and viewer UserItem fields. The cursor binds user, session country, filters and limit to a ten-minute Redis snapshot. A missing snapshot returns 410 with `HTTP_410`. A malformed or mismatched cursor returns 400. Follow `nextCursor` even if the current page is empty.

Optional `excludeItemIds` accepts up to 25 case-insensitively unique ObjectIds. A new snapshot excludes those IDs while interleaving ranked candidates from all sources. A continuation reads the original snapshot. Pick passes the IDs it already displayed when starting over after 410 and uses the `releaseStatusAnnounced` tag ID in `filter.tags[].noneOf`. [Pick integration](../public/docs/api/pages/pick.md)

[ItemEndpointModule](../src/endpoints/item/item.module.ts) provides public [GET /items/:id](../public/docs/api/requestFlows/catalog.md#item) with MongoObjectIdHandler and the global throttle. ItemService reads the nondeleted Item, ItemStats, direct tags and both sides of direct links via entity repositories. Stats default to null average and zero counts when absent. The service reads only public fields of nondeleted related Items and resolves each role from the related side, applying overrides per language. See [ITEM-01](../public/docs/todos/catalog/itemDetails.md) for the response boundary.

Authenticated [GET /items/:id/user](../public/docs/api/requestFlows/catalog.md#item-user) uses the Item ID. UserItemService shares cookie authentication, the current-entry filter and attempt mapping with library mutations. The read requires a nondeleted Item and returns the viewer's entry, including blocked and skipped with future expiry, or `{entry: null}`. Responses use `Cache-Control: no-store`.

[HomeEndpointModule](../src/endpoints/home/home.module.ts) provides public [GET /home/feed](../public/docs/api/requestFlows/catalog.md#home-feed). The daily schedule and the first read after a missed run use the same service and the Moscow date at the 03:00 boundary. CacheService stores the first list across replicas under the app-namespaced Redis key `home:feed:v1:<date>` for 24 hours. Losing the key allows regeneration within the same day. Redis failures propagate. The response contains only the date and typed block IDs, with no viewer filters or pagination.

[FactEndpointModule](../src/endpoints/fact/fact.module.ts) provides the public, unversioned [GET /facts/:id](../public/docs/api/requestFlows/catalog.md#fact). The controller validates the ID with MongoObjectIdHandler. FactService reads `_id`, `text` and `sourceUrl` by `_id` and maps them to FactResponseDto. Both translation keys and the source URL are nullable. A missing Fact returns 404. The global Redis throttle applies.

Public `QUERY /tags` is owned by [TagEndpointModule](../src/endpoints/tag/tag.module.ts). Its [contract](../public/docs/api/pages/search.md#справочник-тегов) covers filtering, search and pagination for Item tag selection. [SyncTagSearchJobHandler](../src/endpoints/tag/services/syncTagSearchJobHandler/core/syncTagSearchJob.handler.ts) refreshes the separate `site_tags` index from MongoDB weekly, with startup catch-up and a checkpoint after successful synchronization.

[AppModule](../src/app/app.module.ts) imports the HTTP endpoint modules and directly registers AppController for the status page and background routes. Controllers own HTTP bindings and DTO boundaries; endpoint services own authentication, business validation, transactions and response mapping. Entity modules export model-specific repositories. Import the owning module and reuse its repository instead of creating another persistence client. See [data access](data-access.md) for generic repositories and transaction semantics, [security](security.md) for cookies and session validation, and [runtime](runtime.md) for global HTTP setup.

[Account avatar routes](../public/docs/api/requestFlows/account.md#put-avatar) authenticate an owned session before the image upload interceptor runs. `PUT /account/avatar` processes one `avatar` file to WebP and replaces its public URL and private object key in one User update. `DELETE /account/avatar` clears both fields. Both operations attempt to delete the previous managed object using the key returned by the update. Existing avatars with a URL alone leave no object to delete through this change.

`QUERY /account/library/continue` uses [AccountService.readLibraryContinue](../src/endpoints/account/services/accountService/core/account.service.ts) to verify the access cookie, active session and current User. [UserItemRepository.readLibraryContinueStatus](../src/entities/userItem/services/userItemRepository/core/userItem.repository.ts) joins existing, nondeleted Items and returns the first matching status in `inProgress → onHold → planned` order, or `null`. Send a JSON object with an optional `types` array of `EItemType` values. Pass the status and the same types in the first library page request. [Continue request flow](../public/docs/api/requestFlows/account.md#library-continue)

[UserEndpointModule](../src/endpoints/user/user.module.ts) exposes [QUERY /users/:id/library](../public/docs/api/contracts/librarySpec.md#публичный-список-библиотеки). The path ID identifies the owner. UserLibraryService checks that the User exists and chooses the owner projection only for a matching access JWT and active owned session. UserItemRepository reads the selected library statuses and joins nondeleted Items and ItemStats using MongoDB. Guests and other viewers share the public projection with null progress and UserItem ID. Only `isFavorite: true` filters to favorites.

`isUnrated: true` requires a verified owner, returning 403 for other viewers. It matches null and missing ratings before pagination and combines with the status filter. The Rating page requests `completed`. This mode continues from the last returned `createdAt` and UserItem ID, sorted by date descending and ID ascending. Both this cursor and the ordinary offset cursor bind the owner, projection, effective filters, sort and limit, with a distinct scope for each mode.

[GET /users/:id](../public/docs/api/requestFlows/userItems.md#user-profile) exposes public identity fields, registration date and library counts. UserProfileService reads an explicit User projection. UserItemRepository counts the same five statuses and available Items as the unfiltered public library.

[QUERY /account/library/history](../public/docs/api/requestFlows/account.md#library-history) verifies the access cookie, active owned session and existing User. LibraryHistoryService paginates the owner's UserItemHistory events by descending createdAt and event ID with a cursor scoped to that owner and limit. It loads current titles and posters for the page in a single batch. An unavailable Item yields `item: null` and leaves its event visible. Responses use `Cache-Control: no-store`.

## Library invariants

UserItemService appends history in the same transaction as the mutation and metrics. A library creation writes `added`. A successful update writes one event per changed status, normalized rating or favorite value. Equal values and note- or attempt-only updates produce no events. DELETE currently leaves past events available to the owner. Retention and deletion policy are open.

All seven library mutations return HTTP 204 with an empty body.

UserItemEndpointModule imports ItemStatsModule and SiteStatsModule. Every contributing UserItem write must call UserItemStatsService.update with itemId, immutable previous/next metric states and the same active MongoDB transaction session. The service applies deltas to ItemStats and, when ratings change, SiteStats. Unchanged metric inputs do not write aggregates. Expired skipped cleanup has no metric effect. See [data access](data-access.md) for the write contract.

The seven `/userItems` mutations authenticate the access cookie, active owned session and existing User. The route `:id` is a UserItem ID. Ownership is part of repository read/write filters; foreign and absent records return 404 for mutations. Creation requires a nondeleted Item and maps duplicate user/item pairs to 409. Existing library records remain editable after their Item is soft-deleted.

PATCH `/userItems/:id` accepts one or more of status, rating, isFavorite and note, preserves omitted fields and rejects an empty body. There are no separate field PATCH routes. Rating and note can be cleared with null. Creation, deletion and mutations involving attempts use MongoTransactionService transactions. DELETE removes the UserItem and embedded attempts without changing collection membership. Metric-relevant changes update ItemStats counters/average and SiteStats rating totals synchronously through UserItemStatsService in the same transaction. The search sync job computes ratingScore from these aggregates for item rating sort.

`isCompletedAndUnratedRequired: true` requires an integer rating from 1 to 10. The conditional PATCH matches the owned record's current `completed` status and null or missing rating in the write filter. A state conflict returns 409 before calculating or persisting metric deltas. Missing and foreign records retain the ordinary 404 behavior.

UserItem has five library statuses plus skipped and blocked. POST /userItems accepts only library statuses; POST /userItems/skip and /block accept itemId and create exclusions, returning 409 for existing pairs. Skipped must have no rating, favorite, note or attempts and expires after 90 days through a partial TTL index. Expired skips are treated as absent by mutations; creation conditionally removes an expired skip. Blocked preserves prior personal data. Switching away from skipped clears expiresAt. InProgress/onHold/completed/dropped require an attempt, created only when none exists; completed marks the last attempt isCompleted=true. Attempts have no status; their create/update does not change the parent status. Planned/blocked retain editable history but forbid new attempts. Progress is nullable nonnegative safe integer minutes, integer percent 0..100, or a count of fully watched episodes. Minute remains the default; changing units does not convert progress or infer completion. When final attempts contain unit=episode, UserItemService checks Item type in the same transaction: only series, animatedSeries and animeSeries are accepted, including soft-deleted seasons; missing or other Items give 400. Item episode counts do not currently bound progress. Unknown dates remain null; completedAt cannot precede startedAt. See the library contract for compatibility/migration requirements. Episode support has not had a new unit/integration test run.

UserItemEndpointModule imports TagItemModule for completion checks. UserItemService.validateCompletion uses TagItemRepository.checkHasTagKeys with the existing transaction session and ETagKey constants. A game with the direct hasDefinedEndFalse tag rejects new completion and percent-unit/numeric percent-progress actions with 409. For season Items only direct releaseStatusAnnounced/releaseStatusOngoing tags reject new explicit completion; other and missing states preserve manual completion. Existing history is not rewritten and unrelated edits retain their prior behavior. Completion integration fixtures were updated to direct tags on 26 October 2026; execution remains blocked by the unavailable Docker runtime.

## Collection invariants

Collection stores metadata and ordered group/text blocks with stable ObjectId ids. ItemCollection stores membership, required groupId and position within the group. UserCollection stores independent reactions. All collections are public. Site tag collections have a Tag reference and automatic composition; franchises and user collections retain manual composition. An author of null means site ownership; the user routes grant no administrative override. GET /collections/:id returns version, blocks, itemCount, ratingAverage, ratingsCount and favoritesCount. ItemCollectionRepository counts existing nondeleted Items in current groups. UserCollectionRepository aggregates ratings and favorites without regard to personal hiding.

CollectionService.create assigns the verified user as author, validates unique block/item IDs and group references, checks nondeleted Items and creates metadata plus membership in one transaction. Update validates the final block set, exact supplied block order, conflicting changes and group references. CollectionRepository.updateVersioned atomically matches ID, author, deletedAt:null and expected version, then stores the next version. Missing stored version is supported as 0. Membership upserts and removals use the same transaction session; moves precede removal of remaining memberships in removed groups. Stale or exhausted versions return 409. DELETE conditionally sets deletedAt and retains membership, reactions and library data.

CollectionContentService loads the collection and its ordered group IDs, delegates card selection to [ItemCollectionRepository.readContentSlice](../src/entities/itemCollection/services/itemCollectionRepository/core/itemCollection.repository.ts) and maps the resulting rows to display blocks.

Public QUERY /collections/:id/items returns grouped blocks by default or a flat list with mode=flat. Group IDs match the metadata blocks across pages. It validates a supplied access cookie and hydrates viewer rating, library status and brief latest-attempt progress for cards. Literal title and alias search, types, overall rating range and enabled viewer status exclusions apply before pagination. Alternative ordering by title, release date or rating sorts within groups or across the flat list. The cursor scope binds the collection ID and version, effective filters and sort, mode, limit and viewer. Author order continues by group, position and membership ID. Alternative sorts use a scoped offset. Ordinary empty grouped pages can render text.

For a verified viewer, `isPersonalFilteringEnabled: true` enables both the hidden collection check and the completed, dropped and blocked status exclusions. Battle enables `isItemStatusFilteringEnabled: true` by itself to apply the status exclusions on direct reads of any available collection. Guests ignore both flags. The cursor distinguishes unfiltered, status-only and combined personal filtering.

PATCH /collections/:id/user updates only supplied reaction fields. Author-only PUT /collections/:id/poster accepts multipart file and saves a WebP in collections/<id>/poster/. POST /collections accepts JSON without media. PATCH /collections/:id uses separate blocks and items changes with add, update, move, and remove arrays. The service resolves anchors and persists collection metadata and membership in one version-checked transaction.

GET /collections/:id/user returns false/null/false for absent reactions, along with progress.completed and progress.total. Progress counts the viewer's completed UserItems among the same available Items as the public itemCount. Reaction writes update only the requested field by verified user/collection IDs, using defaults for the first insert. Concurrent first-insert duplicate-key races retry without upsert. A non-null rating of one's own collection returns 409; clearing it is allowed. Hiding does not restrict direct reads.

## Persistence boundaries

Use [the entity inventory](../public/docs/api/entities.md) to locate the 20 schemas and their relationships. Schema validators and declared indexes do not establish deployed indexes or enforce every cross-document invariant. Generic query/bulk writes bypass some document checks; endpoint services must validate the operation they construct. Current source does not establish migration of earlier records or live MongoDB transaction support.
