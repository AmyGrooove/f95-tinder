# 3. Система рекомендаций

[Все основы проекта](../foundations.md) · [Предыдущий пункт: наполнение каталога](catalogWorkflow.md) · [Следующий пункт: личная библиотека и списки](library.md)

Документ фиксирует согласованные принципы, а не состояние их реализации. Формулы, веса и конкретные алгоритмы определяются при реализации.

## Цель и место в приложении

Главная цель Bisky — сократить время от желания найти произведение до подходящего выбора. Хранение личной библиотеки и списков является самостоятельной ценностью приложения.

Каталог доступен для самостоятельного изучения. Рекомендации помогают выбирать с учётом вкуса, уже известных произведений и пользовательских данных.

АниПик, АниБаттл, «Выбрать сразу» и БыстрыйРейтинг являются инструментами приложения. Их конкретное поведение обсуждается при реализации каждого инструмента. Для разных способов подбора может использоваться общий механизм рекомендаций с разными условиями запроса.

## Сигналы пользователя

Профиль вкуса формируется постепенно по обычным действиям пользователя. Разные действия имеют разное значение.

| Действие | Смысл для системы |
| --- | --- |
| Оценка завершённого произведения | Явное отношение после знакомства с произведением |
| Добавление в избранное | Сильный положительный сигнал |
| Добавление в запланированное | Интерес без подтверждённой оценки качества |
| Завершение | Произведение знакомо пользователю; само по себе не означает положительную оценку |
| Статус «Бросил» | Неоднозначный сигнал, причина неизвестна |
| Временный пропуск | Предложение сейчас не подошло |
| Блокировка | Конкретное произведение больше не предлагается |
| Выбор в АниБаттле | Относительное предпочтение одного кандидата другому |

Основные предпочтения формируются прежде всего по оценкам и избранному. Косвенные действия учитываются осторожнее.

Проигрыш в сравнении не равен отрицательной оценке произведения. Пропуск не должен автоматически превращаться в постоянную неприязнь к жанру или теме.

Для блокировки не запрашивается причина. Она исключает конкретное произведение из будущих предложений; отношение ко всему жанру из неё не выводится.

## Профиль вкуса и подбор

- Профиль сохраняет несколько интересов одновременно. Например, любовь к лёгким комедиям и мрачным триллерам должна позволять подбирать подходящие произведения из обеих групп.
- Предпочтения из одного типа контента могут помогать находить произведения других типов. Например, интерес к киберпанковой атмосфере в играх может учитываться при подборе фильмов и аниме.
- Теги и features помогают находить конкретные закономерности во вкусе.
- Embedding дополняет структурированные признаки смысловой близостью произведений.
- История показов и пропусков помогает избегать постоянного повторения предложений.
- Личная библиотека, списки и статусы позволяют учитывать уже знакомое и запланированное. Конкретные правила использования этих данных зависят от запроса и инструмента.

Логика подбора включает проверку допустимости кандидатов, подбор по предпочтениям и формирование упорядоченного результата под условия запроса. Подробности реализации этих этапов пока не фиксируются.

Для нового пользователя доступна стартовая выдача по популярности и рейтингам, пока информации о его вкусе недостаточно. Оценивание знакомых произведений может предлагаться как необязательный способ улучшить подбор.

## Заменяемый механизм и версии

Механизм рекомендаций должен быть заменяемым и версионируемым. Для начала достаточно отдельных реализаций внутри приложения с общим форматом запроса и результата.

Механизм получает пользователя, условия подбора и доступные данные каталога. Возвращает упорядоченные идентификаторы произведений и, при необходимости, оценки соответствия и причины рекомендаций.

Инструменты работают с общим форматом результата. Смена алгоритма не должна требовать переделки каждого инструмента.

Активная версия выбирается настройкой. Предыдущие версии сохраняются для сравнения и возможности возврата. Будущая реализация через ИИ подключается на тех же основаниях и соблюдает общие ограничения.

Первая реализация может быть простой. Конкретный набор алгоритмов и схема нумерации версий пока не определены.

## Исходные данные и производные профили

Оценки, избранное, списки, показы, пропуски и другие пользовательские данные сохраняются независимо от версии алгоритма.

Профиль вкуса является производным представлением. Разным версиям механизма разрешается строить собственные профили из общих пользовательских данных и истории действий. Переход на новую версию допускает пересчёт профиля без потери накопленных данных.

Общий формат запроса и результата не должен навязывать всем алгоритмам одинаковое внутреннее устройство профиля.

## Общие ограничения и происхождение выдачи

Заблокированные и удалённые произведения исключаются независимо от выбранного алгоритма. Условия запроса обязательны для всех реализаций, включая будущий механизм через ИИ.

Временные пропуски и история показов учитываются при определении доступности предложений. Точные сроки и правила повторного показа определяются при реализации.

Для сформированной выдачи сохраняется информация о версии механизма и использованных настройках. Версия модели embedding учитывается отдельно, поскольку может изменяться независимо от алгоритма рекомендаций.

## Возможность визуализации вкуса

Предусматривается возможность впоследствии визуализировать профиль. Для этого полезны объяснимые сведения: обнаруженные интересы, уверенность системы в них и действия пользователя, повлиявшие на выводы.

Конкретный вид визуализации пока не выбран. Внутреннее представление профиля не привязывается к заранее выбранной диаграмме или экрану.

## Что уточняется при реализации

Формулы и веса сигналов, конкретные алгоритмы, представления профилей, сроки повторных показов, метрики качества, способы сравнения версий и визуализация определяются отдельно. Работа каждого инструмента также обсуждается при его реализации.

Основной ориентир при развитии механизма — помогать пользователю быстрее выбирать подходящие произведения.
