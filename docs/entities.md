# Сущности API

Описание текущего содержимого `apps/api/src/entities`: 23 самостоятельных сущностей. Список отсортирован по алфавиту. Инвентаризация выполнена 18 октября 2026 года; описания `User` и `Session`, состав модулей и границы реализации актуализированы по исходникам 21 октября 2026 года. Сущности подборок и состав модулей добавлены 22 октября 2026 года.

Документ описывает реализацию структур хранения. Целевые требования находятся в [основах проекта](projectFoundations.md), состав первого этапа — в [границах MVP](mvpScope.md).

Для самостоятельных сущностей объявлены отдельные MongoDB-коллекции с такими же именами, `_id`, `createdAt`, `updatedAt`, свой модуль и репозиторий. Временные метки включаются общим плагином `DatabaseModule`. Все 23 модуля подключены в `AppModule`; каждый регистрирует свою модель и экспортирует репозиторий.

В колонке «Связи» стрелка обозначает ссылку на другую сущность, а вложенные структуры указаны отдельно. Ссылки на произведения содержат ObjectId сущности `Item`; тип произведения хранится в самом `Item`.

## Связи с объектами каталога

Все произведения хранятся в коллекции `Item`. Поле `type` задаёт вид произведения; сейчас перечисление `EItemType` определяет `MOVIE = "movie"`. Отдельной сущности `Movie` и вложенной ссылки `ItemId` нет: `CollectionItem`, `ItemFeature`, `ItemMetric`, `ItemTag`, `RelationSide`, `SourceItem`, `UserItem` и `UserRecommendationState` ссылаются непосредственно на `Item` через ObjectId.

Название, описание, альтернативные названия и медиаматериалы хранятся в `Item`. Характеристики произведений задаются через теги и features согласно [структуре данных](projectFoundations/dataStructure.md#компоненты-описания-произведения). `deletedAt` хранит дату пометки удаления; само наличие поля не реализует исключение произведения из поиска и рекомендаций.

## Подборки: границы хранения

Для сайта предусмотрены автоматические подборки по каждому тегу: type=auto, ownership=site, rules.tags.all содержит ID соответствующего тега. Создание этих подборок по умолчанию и поддержание их при изменении справочника тегов ещё не реализованы; текущий этап добавляет только структуры хранения.

`CollectionRules` содержит itemTypes (пустой массив не ограничивает тип), теги all/any/exclude по ID, массив условий features, sort и необязательный положительный целый limit. Условие feature хранит ссылку, оператор eq/gt/gte/lt/lte и значение string/number/boolean/Date; упорядоченные сравнения допускают только число или дату. Сортировка задаётся по createdAt, updatedAt или _id с направлением asc/desc; по умолчанию createdAt desc. Будущая выборка должна добавлять _id для устойчивого порядка, если выбранное поле отличается от _id. Теги самой подборки не хранятся.

Проверки согласованности автора, принадлежности, rules и групп выполняются при документной валидации. Запрет перехода между ручными типами и auto должен проверяться будущими операциями API; сама схема проверяет согласованность type и rules, но не запрещает согласованную смену обоих полей. Общие query/bulk-операции не гарантируют межполевую согласованность: будущие операции должны проверять итоговое состояние. Проверки существования ссылок, Feature.valueType, принадлежности группы, запрет элементов у автоматической подборки и оценки автором своей подборки остаются для слоя операций. Удаление группы с переносом элементов и мягкое удаление с сохранением связей также требуют операций; deletedAt сам по себе не меняет generic delete/read. Собственные теги, прогресс, рейтинг и счётчики подборки не вычисляются.

## Отличия от целевых основ

- Структуры подборок представлены в `Collection`, `CollectionItem` и `UserCollection`; API управления и вычисление автоматического состава не реализованы. `UserItem` независимо хранит статус, оценку, избранное, заметку и попытки.
- `UserTasteProfile` хранит один документ на пользователя с фиксированными профилями по типам Item. Версия механизма рекомендаций в этой структуре не хранится; разные представления профиля по версиям ещё не отражены.
- В `Item` нет embedding произведения. Необязательный embedding в `Tag` относится к тегу и не заменяет представление произведения.
- `Source` и `SourceItem` описывают источники и внешние идентификаторы. Выгрузки в S3, пакеты AI-обработки, согласования и отчёты не представлены в этих корневых схемах.

Это различия текущих структур и целевых требований, а не перечень новых коллекций для автоматического создания. Способ реализации определяется отдельно.

В коде подключены модули аккаунта и авторизации со всеми 20 маршрутами [спецификации](accountAndAuthSpec.md), а также девять маршрутов изменения [личной библиотеки](projectFoundations/library.md#реализованные-операции-библиотеки). Для источников есть Kodik-клиент, сборщик страниц и запись артефактов в S3; сценарий сбора фильмов и импорт ещё не реализованы. Сущности рекомендаций пока не подключены к пользовательским операциям. Краткий статус находится в [навигаторе](readme.md).

Проверка была статической. Работающая база данных, фактическое создание индексов и поведение API не проверялись. Наличие схем и репозиториев само по себе не подтверждает реализацию соответствующего пользовательского процесса.
