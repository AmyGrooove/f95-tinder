# Bisky — спецификация аккаунта и авторизации

Согласовано 20 октября 2026 года. Документ фиксирует требования для реализации, а не состояние работающего API.

Связанные документы: [границы MVP](mvpScope.md), [полный замысел](productVision.md), [текущие сущности](entities.md). Для описанного здесь этапа эта спецификация уточняет прежний сценарий входа только по секретному коду: после первоначальной настройки используется пароль.

## Объём этапа

Регистрация, первоначальная настройка аккаунта, получение и изменение данных профиля, вход, восстановление пароля и управление сессиями. Всего 20 эндпоинтов.

OAuth и удаление аккаунта остаются в бэклоге. Процесс импорта каталога не входит в эту спецификацию.

Точные DTO, HTTP-статусы, ошибки, формат кодов, ограничения полей и технические детали определяются при написании кода с учётом существующей инфраструктуры проекта. Пути ниже описывают маршруты без возможного общего префикса или версии API.

## Состояния аккаунта и способы входа

### До первоначальной настройки

- Регистрация создаёт постоянный аккаунт без тела запроса.
- Пользователь получает автоматически сгенерированный логин и секретный код, открывается сессия.
- Код является стартовым способом доступа до установки пароля. Он не одноразовый и не является кодом из письма.
- Вход выполняется по логину и секретному коду.
- Код показывается только при регистрации или перевыпуске; в постоянном хранилище сохраняется только его хеш.
- Перевыпуск отменяет старый код.

### Первоначальная настройка

1. Авторизованный пользователь передаёт email и желаемый пароль в `POST /account/setup`, подтверждая действие текущим секретным кодом.
2. Приложение отправляет код подтверждения на предложенный email. В Redis сохраняются данные незавершённой настройки, включая email и хеш пароля; открытый пароль не сохраняется.
3. До подтверждения аккаунт продолжает работать по прежнему секретному коду. Новый email и пароль ещё не применены.
4. Пользователь подтверждает код через `PATCH /account/setup`.
5. Подтверждённый email и пароль устанавливаются вместе, секретный код удаляется. Не допускается частичное завершение с сохранением только части этих изменений.

Первоначально установить email и пароль по отдельности нельзя. Отдельного `POST /account/password` в этом этапе нет.

### После первоначальной настройки

- Вход выполняется по логину и паролю.
- Вход по секретному коду и его перевыпуск недоступны. Возврат к стартовому способу входа не предусмотрен этим этапом.
- Email и пароль можно изменять отдельными операциями.
- Восстановление пароля выполняется через подтверждённый email.

## Эндпоинты аккаунта

Все маршруты этого раздела требуют действующую сессию текущего пользователя.

| Метод и путь                 | Назначение                                                            |
| ---------------------------- | --------------------------------------------------------------------- |
| `GET /account/whoami`        | Текущая сессия и краткие данные пользователя для запуска приложения   |
| `GET /account`               | Полный профиль текущего пользователя для страницы аккаунта и настроек |
| `PATCH /account/username`    | Изменить логин                                                        |
| `PATCH /account/displayName` | Изменить отображаемое имя                                             |
| `POST /account/setup`        | Передать email и пароль, запросить код первоначальной настройки       |
| `PATCH /account/setup`       | Подтвердить код и завершить первоначальную настройку                  |
| `POST /account/email`        | Запросить изменение email после первоначальной настройки              |
| `PATCH /account/email`       | Подтвердить код и применить новый email                               |
| `PATCH /account/password`    | Изменить существующий пароль                                          |

### Ответы с данными аккаунта

`GET /account/whoami` вызывается при открытии сайта. Ответ содержит текущую сессию и краткие данные пользователя, включая имя и роль. Предлагаемая структура — отдельные объекты `user` и `session`; точный состав DTO определяется при реализации.

`GET /account` возвращает расширенные данные текущего пользователя, включая состояние email и способов входа. «Полный профиль» не означает выдачу документа MongoDB целиком: ответ формируется по явному списку разрешённых полей. Хеши, токены и другие секреты не возвращаются.

Вызов `whoami` не заменяет проверку авторизации остальных защищённых запросов.

### Изменение email и пароля

- Важные изменения подтверждаются действующим секретным кодом или паролем в зависимости от состояния аккаунта. Это относится к первоначальной настройке, смене email, перевыпуску секретного кода и изменению пароля.
- Запрос смены email ещё не изменяет текущий адрес. Новый адрес применяется после подтверждения кода, связанного с конкретным пользователем и предложенным адресом.
- Изменение существующего пароля требует текущий пароль.
- Самостоятельное удаление подтверждённого email в перечень операций этого этапа не входит.

## Эндпоинты авторизации

| Метод и путь                 | Назначение                                                                     | Доступ                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `POST /auth/register`        | Создать аккаунт без тела запроса, выдать логин и секретный код, открыть сессию | Без авторизации                                                             |
| `POST /auth/login/code`      | Войти по логину и секретному коду, создать сессию                              | Без авторизации; только до настройки                                        |
| `PATCH /auth/login/code`     | Перевыпустить секретный код                                                    | Действующая сессия и текущий код; только до настройки                       |
| `POST /auth/login`           | Войти по логину и паролю, создать сессию                                       | Без авторизации; после настройки                                            |
| `POST /auth/logout`          | Завершить текущую сессию и очистить cookies                                    | Текущая сессия; поведение при уже истёкших данных уточняется при реализации |
| `POST /auth/password/reset`  | Запросить код сброса пароля на подтверждённый email                            | Без авторизации                                                             |
| `PATCH /auth/password/reset` | Подтвердить код и установить новый пароль                                      | По действующему подтверждению сброса                                        |

Запрос сброса пароля возвращает одинаковый внешний ответ независимо от существования аккаунта с указанным email. Сброс пароля применяется к аккаунтам с уже установленным паролем; первоначальная настройка выполняется через `/account/setup`.

## Эндпоинты сессий

| Метод и путь                      | Назначение                                            |
| --------------------------------- | ----------------------------------------------------- |
| `GET /auth/session`               | Получить действующие сессии текущего аккаунта         |
| `DELETE /auth/session/others`     | Завершить все сессии текущего аккаунта, кроме текущей |
| `DELETE /auth/session/:sessionId` | Завершить выбранную собственную сессию                |
| `PATCH /auth/session/refresh`     | Заменить токены и продлить текущую сессию             |

Управление сессиями требует авторизацию; обновление выполняется по действующему refresh-токену и серверной сессии, без требования действующего access-токена.

Список сессий содержит безопасные сведения: идентификатор, сведения об устройстве, даты и признак текущей сессии. Точный набор определяется при реализации. Токены и их хеши в список не входят.

Удаление сессии ограничивается владельцем аккаунта. При удалении текущей сессии очищаются её cookies. Статический маршрут `/others` не должен обрабатываться как параметр `sessionId`.

## Токены и проверка доступа

- Access-токен действует 10 минут.
- Refresh-токен действует 120 дней. Выбран фиксированный срок вместо четырёх календарных месяцев.
- При успешном обновлении выдаётся новая пара токенов, та же сессия продлевается ещё на 120 дней. Старый refresh-токен перестаёт приниматься.
- Оба токена передаются только через cookies с `HttpOnly` и `Secure`. Передача токенов в теле ответа, URL или `Authorization: Bearer` не входит в целевой контракт этих операций.
- Для изменяющих запросов предусматривается защита от CSRF. Конкретный механизм, `SameSite`, область действия cookies и локальная конфигурация определяются при реализации.
- Каждый защищённый запрос проверяет JWT и существование неистёкшей серверной сессии, соответствующей пользователю и токену.
- Удаление сессии прекращает доступ по её токенам сразу при следующей проверке авторизации, без ожидания истечения access-токена. Уже выполняющийся запрос не отменяется этим правилом.
- Истечение сессии проверяется явно; физическое наличие ещё не удалённой TTL-механизмом записи не означает действующую сессию.
- Выход удаляет серверную сессию и очищает обе cookies.
- Обновление токенов должно согласовываться между вкладками клиента. Конкурентные запросы с одним refresh-токеном не должны независимо заменять его; детали обработки проигравшего запроса и клиентской координации определяются при реализации.

## Сессии при изменении способов входа

| Действие                   | Поведение                                              |
| -------------------------- | ------------------------------------------------------ |
| Изменение пароля           | Завершить остальные сессии, текущую обновить           |
| Перевыпуск секретного кода | Завершить остальные сессии, текущую обновить           |
| Сброс пароля через email   | Завершить все сессии; для продолжения нужен новый вход |

Под обновлением текущей сессии понимается замена её токенов с сохранением текущего входа. Поведение остальных сессий при завершении первоначальной настройки уточняется при реализации: отдельно для этого перехода правило ещё не выбиралось.

## Подтверждения и Redis

Эти правила относятся к кодам из писем для первоначальной настройки, смены email и сброса пароля; они не задают срок жизни стартового секретного кода аккаунта.

- Срок действия кода — 4 часа.
- Допускается 3 неверные попытки ввода, после чего подтверждение становится недействительным.
- Повторная отправка доступна через 1 минуту.
- Новый код отменяет предыдущий для той же операции.
- Успешное применение погашает код; повторное применение невозможно.
- Подтверждение связано с назначением операции и соответствующим аккаунтом, а при смене адреса — с конкретным новым email.
- Код, новый email, счётчики и другие данные незавершённой операции хранятся в Redis. Для первоначальной настройки также временно хранится хеш выбранного пароля.
- Потеря данных Redis допустима: пользователь повторяет запрос и подтверждение. Перенос незавершённых операций в MongoDB или их восстановление после перезапуска Redis не требуется.

## Детали, оставленные на реализацию

- Точные поля запросов и ответов, HTTP-статусы и единый контракт ошибок.
- Формат автоматически создаваемого логина, секретного кода и кодов из писем; ограничения и нормализация пользовательских полей.
- Настройки cookies и способ защиты от CSRF.
- Конкретные лимиты регистрации, входа и отправки писем в дополнение к правилам подтверждений.
- Привязка операции подтверждения к запросу клиента, обработка повторов и конкурентных изменений, включая refresh из нескольких вкладок.
- Политика сессий при завершении первоначальной настройки.
- Детали реализации на существующих репозиториях, JWT-, Redis- и почтовой инфраструктуре.

Эти пункты уточняются по текущему коду, без автоматического расширения согласованного объёма.

## Временный старый код

Корневая папка `.temp/auth` добавлена как исторический материал для изучения сценариев. Она не является целевой реализацией и не должна переноситься целиком. После использования её нужно удалить отдельным изменением в рамках реализации; запись этой спецификации сама по себе не удаляет папку.
