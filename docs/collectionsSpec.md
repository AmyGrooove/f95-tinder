# Подборки: спецификация API

Согласовано 22 октября 2026 года. Эндпоинты реализуются по одному для отдельного ревью. В коде реализованы `GET /collections/:id`, `POST /collections` и `GET /collections/:id/user`; остальные маршруты описывают целевой контракт. Детали DTO из отменённой массовой реализации являются предварительными и уточняются перед соответствующим эндпоинтом. Поведение в работающем окружении отдельно не проверено.

Связанные документы: [сущности](entities.md), [личная библиотека](projectFoundations/library.md), [границы MVP](mvpScope.md). Эта спецификация определяет отдельно согласованный объём подборок; прежнее исключение публичных подборок из стартового MVP не означает отказа от описанного здесь API.

## Модель

- `Collection` хранит основные данные, автора, тип custom/franchise/tag/feature, `deletedAt` и массив `blocks`. При `author=null` подборка принадлежит сайту, иначе — указанному пользователю. Отдельного поля ownership нет.
- Все подборки публичные; состав задаётся вручную. Приватность и автоматический отбор не предусмотрены.
- Порядок блоков определяется их порядком в массиве. У каждого блока стабильный ObjectId `id` и тип group или text.
- `group` содержит необязательные `title` и `description` на RU/EN. Группа без названия выглядит обычным списком. Полей `appearance` и сворачивания нет.
- `text` содержит `content` на RU/EN с хотя бы одним непустым переводом. Поля группы у текстового блока и content у группы запрещены.
- `CollectionItem` хранит состав отдельно от Collection: `collection`, `item`, обязательный `groupId`, `position` внутри группы и необязательную `note`. Ссылка groupId должна указывать на блок типа group той же подборки.
- Обычные участки списка, именованные группы и текстовые вставки могут чередоваться в любом авторском порядке. Отдельного раздела «Без группы» нет: все элементы относятся к группам, в том числе безымянным.
- Пара collection/item уникальна: произведение нельзя повторить в другой группе той же подборки.
- `UserCollection` хранит независимые личные реакции: `isFavorite`, целую оценку `rating` от 1 до 10 или null, `isHidden`.
- Состав подборок независим от библиотеки UserItem. Добавление и удаление Item в подборке не меняет статус, оценку, избранное, заметку или попытки пользователя.

## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| `GET /collections` | Список подборок с фильтрами и пагинацией: публичные, свои, избранные |
| `GET /collections/:id` | Основные данные и полная структура блоков без списков Item |
| `GET /collections/:id/items` | Страница Item с данными их включения в подборку, личными данными авторизованного пользователя, фильтрацией и сортировкой |
| `GET /collections/:id/filters` | Доступные теги, характеристики и режимы сортировки |
| `GET /collections/:id/user` | Реакция текущего пользователя на саму подборку |
| `POST /collections` | Создание подборки |
| `PATCH /collections/:id` | Единое атомарное редактирование основных данных, блоков, состава, заметок и порядка |
| `DELETE /collections/:id` | Мягкое удаление подборки |
| `PATCH /collections/:id/favorite` | Установить или снять избранное |
| `PATCH /collections/:id/rating` | Установить оценку или убрать её через null |
| `PATCH /collections/:id/hidden` | Скрыть подборку для текущего пользователя или отменить скрытие |

Отдельные маршруты изменения групп, состава и порядка не нужны: эти операции входят в единый PATCH. Отдельный `/collections/:id/items/user` не нужен: личные данные входят в страницу Item.

## Реализованное чтение подборки

`GET /collections/:id` доступен без авторизации. Успех — 200 с `Cache-Control: no-store` и полями `id`, `authorId` (строка или null для подборки сайта), `type`, `title`, `description`, `media`, `blocks`, `createdAt`, `updatedAt`. Переводы представлены объектом `{ru, en}` с nullable-строками, media — массивом `{src, language, type}`, даты — ISO 8601.

Блоки возвращаются полностью в авторском порядке. Группа содержит `id`, `type=group`, nullable `title` и `description`; текстовый блок — `id`, `type=text`, `content`. Состав Item, личные реакции и внутренние поля хранения не возвращаются.

Некорректный ObjectId возвращает 400. Отсутствующая или помеченная удалённой подборка возвращает одинаковый 404. Личное скрытие не ограничивает этот публичный маршрут. Чтение с фильтром `deletedAt=null` вынесено в `CollectionRepository.findNotDeletedById`; явное формирование DTO выполняет `CollectionService`.

## Реализованное создание подборки

`POST /collections` требует access cookie, активную серверную сессию и существующего пользователя. Автором становится текущий пользователь; поля author/authorId/ownership не принимаются. Создание подборок сайта относится к отдельной админке и не входит в этот маршрут.

Обязательное поле — `title` с хотя бы одним непустым переводом. Необязательны `description`, `media`, `type`, `blocks`, `items`. Переводы принимаются как `{ru?, en?}`, строки или null; отсутствующие переводы становятся null. По умолчанию type=custom, description={ru:null,en:null}, media/blocks/items пустые. Допустимы custom/franchise/tag/feature; состав всех типов ручной. null вместо необязательного объекта, массива или type не допускается.

Блок принимает `type`, необязательный `id` и поля своего типа. Для group разрешены nullable title/description; переданный title должен иметь непустой перевод. Для text обязателен content с непустым переводом; title/description запрещены. content у группы запрещён. Пропущенный id генерируется сервером; для ссылки на группу из начального состава клиент задаёт её id явно.

Начальные items имеют `{itemId, groupId, position, note?}`. position — неотрицательное безопасное целое. note допускает null, обрезается по краям, пустая строка становится null. ID блоков и itemId уникальны с учётом нормализации ObjectId; groupId указывает на group в этом же запросе. Некорректные данные, неизвестные поля и дубли возвращают 400; отсутствующий или удалённый Item — 404, недействительная авторизация — 401. Одинаковые position допускаются. Предварительные числовые лимиты из последнего раздела не введены этим маршрутом.

Collection и CollectionItem создаются одной транзакцией MongoTransactionService; проверка существования Item также выполняется в ней. UserItem не изменяется. ItemRepository.findNotDeletedByIds инкапсулирует выборку действующих Item, CollectionItemRepository.createForCollection — запись состава с ID подборки; оба принимают сессию вызывающего сервиса. Успех — 201 с CollectionResponseDto и Cache-Control:no-store. Формат ответа совпадает с GET и не включает состав Item. Глобальные CSRF, валидация и throttling применяются по общим правилам API.

## Реализованное чтение личной реакции

`GET /collections/:id/user` реализован в отдельном CollectionUserController и CollectionUserService. Требует действующий access cookie, активную серверную сессию соответствующего пользователя и существующий аккаунт. Возвращает 200 с `{isFavorite, rating, isHidden}` и `Cache-Control: no-store`. rating — целое от 1 до 10 или null. Без сохранённой реакции возвращает `{isFavorite:false,rating:null,isHidden:false}` без создания UserCollection.

ID в пути относится к Collection, а не к записи реакции. Некорректный ObjectId возвращает 400, недействительная авторизация — 401, отсутствующая или удалённая подборка — 404. Чтение разрешено также автору подборки; личное скрытие не ограничивает этот маршрут. Реакция выбирается только по паре текущий пользователь/подборка. Общие данные подборки, внутренние ID реакции и реакции других пользователей в ответ не входят.

CollectionRepository.checkIsNotDeleted проверяет существование неудалённой подборки; UserCollectionRepository.findByUserAndCollection выбирает только три поля реакции. Маршрут выполняет только чтение и не требует транзакции.

## Выдача Item

### Фильтрация

- Конкретная группа через `groupId`; без него — весь состав.
- Поиск по названиям и алиасам произведений.
- Теги: все выбранные обязательны; отдельно задаются исключаемые теги.
- Характеристики: подходящие для фильтрации категориальные значения, числовые и временные диапазоны.
- Личные данные: статусы библиотеки, оценка и избранное. Эти фильтры требуют авторизации.
- «Нет в библиотеке» — самостоятельное условие; оно не равно «Не завершено».
- Разные характеристики и личные условия объединяются через AND. Несколько статусов или значений одной характеристики объединяются через OR.

Сначала применяется фильтрация, затем сортировка, подсчёт total и выборка страницы. Из выдачи исключаются удалённые произведения. Пустые после фильтрации группы не отображаются.

### Сортировка

Режим задаёт область сортировки:

- `grouped`: группы идут в авторском порядке, произведения сортируются внутри каждой группы.
- `flat`: все произведения сортируются вместе, визуального разделения на группы и текстовых вставок нет. Принадлежность Item группе сохраняется в данных.

Варианты сортировки: авторский порядок по умолчанию либо название по возрастанию/убыванию с учётом выбранного языка. Порядок автора определяется массивом блоков и position внутри группы. К сортировке добавляется уникальный ключ для устойчивого порядка равных значений.

Предварительные query-параметры: `mode=grouped|flat`, `sort=collection|title`, `direction=asc|desc`, `language=ru|en`. По умолчанию sort=collection, direction=asc, language=ru; mode=grouped, если доступен, иначе flat. Запрос недоступного режима предполагает 400. Точные имена, правила языковой сортировки и отсутствующего перевода уточняются перед реализацией.

### Одна пагинация по произведениям

- В обоих режимах используются одна пара `page` и `limit`; по умолчанию limit=20, максимум 100.
- Лимит и total считают только Item, а не группы, заголовки или текстовые блоки.
- В grouped список последовательно набирается из групп в авторском порядке. Одна страница может содержать конец одной группы и начало другой.
- Пример: при limit=20 первая страница содержит 12 Item группы A и первые 8 группы B; вторая продолжает B и затем переходит к следующим группам.
- Если страница начинается с продолжения группы, её заголовок повторяется. У каждого Item есть groupId, структура группы доступна в основных данных Collection.
- Нет отдельной пагинации групп, вложенной пагинации или загрузки по limit элементов одновременно из каждой группы.
- При заданном groupId та же пагинация работает внутри выбранной группы.

Ответ соответствует [IPaginatedResult](../apps/api/src/infrastructure/database/types/IPaginatedResult.ts): `items`, `page`, `limit`, `total`, `pages`, `isNextPage`, `isPreviousPage` на одном уровне. Отдельная обёртка pagination не добавляется. IListResponse с nextCursor для этого маршрута не используется.

### Текстовые блоки

- Отображаются в grouped без активной фильтрации, в авторском порядке.
- При активной фильтрации скрываются. Само переключение сортировки или страницы фильтрацией не является.
- В flat скрываются независимо от фильтров.
- Текстовая вставка показывается один раз в своём месте последовательности, не повторяется при продолжении группы и не расходует limit.
- Предварительный вариант: дополнить ответ `mode` и `displayBlocks` с якорем `beforeItemId`. Заголовки групп повторяются на страницах продолжения; текстовые блоки не расходуют limit и показываются один раз. Точное представление и привязка текстов к страницам, включая начальные/конечные вставки и подборку без Item, уточняются перед реализацией `/items`.

### Личные данные

Для авторизованного пользователя Item страницы дополняются данными UserItem: статусом, оценкой, избранным и прогрессом. Отсутствие записи библиотеки должно отличаться от записи с пустой оценкой или прогрессом. Точный состав краткой карточки, формат отсутствующих личных данных и представление прогресса уточняются в DTO; полная история попыток автоматически в контракт не включается.

Неавторизованный пользователь может читать неудалённую подборку без личных данных. Проверка авторизации должна учитывать cookie JWT и серверную сессию по действующим соглашениям API.

## Доступные фильтры

`GET /collections/:id/filters` возвращает значения, действительно присутствующие в составе подборки, либо внутри указанного groupId:

- Доступные теги.
- Характеристики, пригодные для фильтрации: категориальные значения, диапазоны чисел и дат, имеющиеся булевы значения.
- Не любые произвольные строковые характеристики автоматически становятся фильтрами. Критерий категориальности и ограничения числа значений уточняются при реализации; порог 100 из отменённой реализации не является согласованным требованием.
- `sorting.availableModes`.

Варианты вычисляются до пагинации и не зависят от выбранных поисковых, теговых, характеристических или личных фильтров. Динамические фасеты и счётчики совпадений по текущему запросу на этом этапе не нужны. Невозможная комбинация доступных значений может дать пустой список Item.

Пример поля режимов:

```json
{
  "sorting": {
    "availableModes": ["flat", "grouped"]
  }
}
```

Режим grouped доступен, если во всей подборке не менее двух непустых групп **или есть текстовые блоки**. Иначе доступен только flat. При подсчёте непустых групп удалённые Item не учитываются. Выбранные фильтры и groupId не меняют глобальную доступность режимов.

При добавлении второй непустой группы или текстового блока grouped становится доступен. Пустая группа сама по себе его не включает.

## Изменения и удаление

- PATCH принимает только изменения, а не требует прислать весь состав, загруженный постранично.
- В одном запросе можно менять основные данные, создавать/редактировать/удалять блоки, добавлять/удалять Item, менять их заметки и группы, переставлять блоки и элементы.
- Весь запрос применяется атомарно либо отклоняется целиком. Согласованные изменения Collection и CollectionItem выполняются одной транзакцией слоя операций.
- При удалении группы удаляются все её CollectionItem. Сами Item каталога и UserItem не удаляются. Автоматического переноса в другую группу нет.
- Итоговое состояние проверяется на существование ссылок, принадлежность групп, уникальность состава и согласованность типа подборки.
- Для защиты от устаревшего сохранения предусмотрена версия подборки и 409 при несовпадении. Версия меняется при изменении метаданных, состава и порядка; поле и точный контракт будут добавлены при реализации PATCH.
- DELETE подборки устанавливает deletedAt, сохраняя связи. Удалённая подборка недоступна через обычные маршруты.

## Доступ и реакции

- Пользователь изменяет свои подборки; подборками сайта управляет администратор.
- Автор определяется сервером: для пользовательской подборки это текущий пользователь, для подборки сайта — null. Создание подборки сайта доступно только администратору; способ выбора этого действия уточняется при реализации POST.
- Все неудалённые подборки доступны для чтения без входа. Удалённая подборка возвращает 404.
- Автор не может оценивать свою подборку.
- Избранное, оценка и скрытие независимы друг от друга.
- Скрытие — личная реакция: оно не ограничивает доступ других пользователей к подборке и не меняет её состав или их реакции. Правила исключения скрытых из конкретных списков, прямой ссылки и доступа администратора к чужим пользовательским подборкам уточняются при реализации соответствующего маршрута.

## Кеширование и границы реализации

- Персональные ответы не кешируются общим публичным кешем; для согласованного варианта личные ответы не кешируются. Общие ответы и варианты фильтров могут кешироваться с проверкой доступа и инвалидацией при изменении состава, блоков, удалении Item, тегов или характеристик. Личная реакция не меняет общие варианты фильтров. Конкретный механизм кеширования пока не реализован.
- Скорость агрегаций, выборок и подсчёта total пока не измерена. Наличие индексов в исходниках не доказывает их наличие в БД или производительность сложного запроса.
- Существующие groups и CollectionItem с groupId=null потребуют отдельной миграции при наличии таких данных. Поле версии и индексы новых запросов предстоит добавить при реализации соответствующих операций. Миграции и операции с работающей БД не выполнялись.

## Предварительная детализация для поэтапной реализации

Этот раздел сохраняет варианты DTO и технические решения отменённой реализации для обсуждения. Они не являются уже работающими или отдельно согласованными контрактами. Перед каждым эндпоинтом уточняются относящиеся к нему пункты.

- `GET /collections`: scope=public|own|favorite (по умолчанию public), query, type, isHiddenIncluded, page, limit. own/favorite требуют входа. Сортировка — updatedAt desc, затем id desc. Возвращаются краткие карточки без blocks/description.
- `GET /collections/:id/items`: groupId, query, tags, excludeTags, features, statuses, isInLibrary, isFavorite, ratingMin, ratingMax, mode, sort, direction, language, page, limit.
- Массивы query принимаются повторяющимися параметрами либо списком через запятую. features — JSON-массив объектов `{featureId, values}` либо `{featureId, min, max}`; границы можно задавать по отдельности. Пустые условия, неизвестная характеристика, несовместимый тип и min > max возвращают 400. Булевы параметры принимают true/false.
- `GET /collections/:id/filters` принимает только необязательный groupId. availableModes остаются глобальными для подборки.
- PATCH: обязательное version; необязательные title/description/media/type и массивы upsertBlocks/removeBlockIds/blockOrder/upsertItems/removeItemIds. Передаётся хотя бы одно изменение. upsertBlocks задаёт полное определение затронутого блока; пропущенные его необязательные поля очищаются. Без id создаётся новый блок. Тип существующего блока не меняется. blockOrder, если указан, перечисляет все ID итоговых блоков ровно один раз.
- upsertItems принимает `{itemId, groupId, position, note?}` и добавляет либо перемещает Item. Отсутствующий note сохраняет прежнюю заметку; null или пустая строка очищает. Перенос в оставшуюся группу в одном запросе с удалением прежней группы сохраняет Item и его заметку. При одинаковых position дополнительный порядок определяется ID произведения.
- favorite принимает `{isFavorite:boolean}`, rating — `{rating:1..10|null}`, hidden — `{isHidden:boolean}`. Пропущенные реакции не сбрасываются; повторная установка идемпотентна. GET user без сохранённой реакции возвращает false/null/false. Снятие оценки собственной подборки разрешено; установка оценки запрещена с 409.
- Создание возвращает 201 и CollectionResponseDto; изменение и чтение — 200 с DTO; DELETE — 204 без тела. Ошибки используют существующий конверт API с code/message/details/requestId. Неизвестные поля отклоняются глобальной валидацией.
- Предложенные ограничения, требующие уточнения: 500 блоков и 1 000 000 байт их содержимого; 1000 изменений Item за запрос; 50 media; 100 тегов в каждом массиве и 100 условий характеристик; 20 000 символов на перевод текста, 10 000 на заметку Item, 200 на поиск. Числа page/position/version должны быть безопасными целыми.
- Реализация транзакций требует подходящего окружения MongoDB. Приложение, БД и тесты в рамках статической проверки не запускались.
