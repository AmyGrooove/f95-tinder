# Общие операции страниц

[Индекс покрытия](readme.md) · [Требования интерфейса](../../product/pages/shared.md)

## Реализовано

Все девять операций [UserItemController](../../../apps/api/src/endpoints/userItem/controllers/userItem.controller.ts) вызывают [UserItemService](../../../apps/api/src/endpoints/userItem/services/userItem.service.ts):

| Маршрут | Покрываемое действие |
| --- | --- |
| `POST /userItems` | Создать запись по `{ itemId, status }` |
| `PATCH /userItems/:id` | Сохранить переданные статус, оценку, избранное и заметку одной операцией |
| `DELETE /userItems/:id` | Удалить запись вместе с попытками и личными полями |
| `PATCH /userItems/:id/status` | Быстро изменить статус |
| `PATCH /userItems/:id/rating` | Поставить целую оценку 1–10 или очистить через `null` |
| `PATCH /userItems/:id/favorite` | Изменить избранное |
| `PATCH /userItems/:id/note` | Изменить или очистить заметку |
| `POST /userItems/:id/attempts` | Добавить попытку, в том числе повторный просмотр |
| `PATCH /userItems/:id/attempts/:attemptId` | Изменить статус, прогресс и даты попытки |

`:id` — ID UserItem. Создание и изменения возвращают личную запись с попытками; это не замена её чтению при новом открытии страницы. Прогресс измеряется в минутах. Доступ ограничен владельцем. Оценка, избранное и заметка требуют созданной записи; `POST` принимает статус явно. Переход в planned при активной попытке даёт 409. Подробности — в [контракте библиотеки](../librarySpec.md).

Регистрация, вход, восстановление и refresh уже реализованы; точные маршруты перечислены в [настройках и формах доступа](settings.md). Отдельного backend для окна входа, предупреждения об уходе или состояния загрузки не требуется.

## Оставшаяся общая работа

| ID | Состояние | Результат и потребители |
| --- | --- | --- |
| LIB-01 | Нет | Чтение личной записи по произведению/записи, включая её отсутствие, ID UserItem, заметку и подробные попытки только владельцу. Нужно странице произведения и полному редактору из любых карточек |
| LIB-02 | Нет | Чтение библиотеки с поиском, условиями и пагинацией; собственный и публичный варианты с безопасным составом полей. Нужны профилю, главной, Баттлу и Оценке; подробности условий — у соответствующих страниц |
| REC-01 | Нет | Выдача стартовых и персональных рекомендаций с обязательным исключением «Не рекомендовать»; общая основа главной, рекомендательного режима каталога и Пика |
| REC-02 | Нет | Чтение, установка и снятие «Не рекомендовать» независимо от UserItem; применение исключения в рекомендациях, поддержка явных условий обычных выдач |

- [ ] `LIB-01`: определить и реализовать чтение личной записи и загрузку полного редактора.
- [ ] `LIB-02`: определить и реализовать чтение библиотеки с разделением собственных и публичных данных.
- [ ] `REC-01`: определить и реализовать общую рекомендательную выдачу.
- [ ] `REC-02`: определить и реализовать независимое исключение из рекомендаций.

В [UserRecommendationState](../../../apps/api/src/entities/userRecommendationState/schemas/userRecommendationState.schema.ts) уже есть `isExcluded`, счётчики показов/пропусков и даты. Пользовательских операций над ними в текущих endpoints нет. Срок пропуска и бессрочное исключение нельзя отождествлять. [UserItemService](../../../apps/api/src/endpoints/userItem/services/userItem.service.ts) не пересчитывает метрики произведения, профиль вкусов или журнал действий; задачи статистики и истории находятся в [произведении](item.md) и [профиле](profile.md).

## Уточнить перед соответствующей реализацией

- Способ поиска личной записи, состав ответа и загрузка попыток; `null`/404 для отсутствующей записи и поведение удалённого Item.
- Общие параметры чтения библиотеки, граница публичного прогресса; заметка и подробные попытки остаются приватными.
- Контракт рекомендаций и реакций, поведение повторов и обновления выдачи. Соблюдать [ограничения рекомендаций](../../product/foundations/recommendations.md), не переносить обязательные исключения в обычный поиск без явного фильтра.
- Для гостя личные действия требуют входа. Операция не выполняется автоматически после входа; отображение ошибок и обновление состояния карточки относятся также к клиенту.
