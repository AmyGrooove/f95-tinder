# Настройки и формы доступа: покрытие API

[Индекс покрытия](readme.md) · [Требования настроек](../../product/pages/settings.md) · [Общие формы](../../product/pages/shared.md#формы-входа-и-служебные-состояния)

## Реализовано

Все 20 account/auth-маршрутов доступны через подключённые модули. Они покрывают настройки и общие формы входа, регистрации и восстановления:

| Маршрут | Действие |
| --- | --- |
| `GET /account` | Данные своего аккаунта: профиль, email, признаки установленных способов входа, даты |
| `GET /account/whoami` | Текущий пользователь и краткие данные текущей сессии |
| `PATCH /account/displayName` | Отображаемое имя |
| `PATCH /account/username` | Логин |
| `POST /account/setup` | Запрос первоначальной совместной настройки email и пароля |
| `PATCH /account/setup` | Подтверждение первоначальной настройки кодом письма |
| `POST /account/email` | Запрос смены email |
| `PATCH /account/email` | Подтверждение смены email |
| `PATCH /account/password` | Смена пароля с текущим паролем |
| `PATCH /auth/login/code` | Перевыпуск секретного кода |
| `GET /auth/session` | Список активных сессий, userAgent, даты, isCurrent |
| `DELETE /auth/session/others` | Завершение остальных сессий |
| `DELETE /auth/session/:sessionId` | Завершение выбранной сессии |
| `PATCH /auth/session/refresh` | Обновление токенов текущей сессии |
| `POST /auth/register` | Регистрация и выдача секретного кода |
| `POST /auth/login/code` | Вход по секретному коду до настройки пароля |
| `POST /auth/login` | Вход по логину и паролю |
| `POST /auth/logout` | Выход из текущей сессии |
| `POST /auth/password/reset` | Запрос восстановления по email |
| `PATCH /auth/password/reset` | Подтверждение восстановления и новый пароль |

Точки проверки: [account controllers](../../../apps/api/src/endpoints/account/controllers), [account services](../../../apps/api/src/endpoints/account/services), [auth controllers](../../../apps/api/src/endpoints/auth/controllers), [auth services](../../../apps/api/src/endpoints/auth/services). Подробные правила подтверждений и завершения сессий — в [действующем контракте](../accountAndAuthSpec.md).

`GET /account` уже возвращает `avatarUrl`, но маршрутов его загрузки и удаления нет. Секретный код читается только в момент регистрации/перевыпуска; отдельное постоянное чтение кода не требуется. Список сессий уже позволяет выделить текущую; устройство/браузер можно представить по доступному userAgent, география и лимит сессий не входят в требования.

## Уточнить

Требования к аватару, представление ожидания подтверждений и ошибок, сессии без userAgent. Сохранение отображаемого имени и логина уже выполняется отдельными маршрутами; при детализации общей кнопки формы определить обработку частичного успеха, не предполагать их атомарность. Повтор пароля, предпросмотр и предупреждение о несохранённом — клиентские сценарии, новые поля API для них не нужны.

OAuth, удаление аккаунта и настройки уведомлений не являются недостающими операциями описанной страницы.

## Проверка результата

Для новых операций проверять владение, загрузку/замену/удаление и чтение итогового avatarUrl. Наличие кода существующих маршрутов не подтверждает доставку писем, работу cookies или Redis в окружении; runtime-проверки не выполнялись.
