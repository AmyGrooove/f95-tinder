# Личная библиотека: спецификация API

Проверено по контроллеру и сервису 24 октября 2026 года. Ниже описаны девять реализованных операций; GET-маршрутов библиотеки пока нет.

Связанные документы: [принципы библиотеки](../product/foundations/library.md), [сущности](entities.md), [устройство API](readme.md).

## Реализованные операции библиотеки

| Метод  | Путь                                 | Назначение                                                                                            |
| ------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| POST   | `/userItems`                         | Добавить произведение: `{ itemId, status }`                                                           |
| PATCH  | `/userItems/:id`                     | Атомарно изменить переданные `status`, `rating`, `isFavorite`, `note`                                 |
| DELETE | `/userItems/:id`                     | Удалить запись со всеми её данными и попытками                                                        |
| PATCH  | `/userItems/:id/status`              | Изменить `{ status }`                                                                                 |
| PATCH  | `/userItems/:id/favorite`            | Установить `{ isFavorite }`                                                                           |
| PATCH  | `/userItems/:id/rating`              | Установить `{ rating }`: целое 1–10 или `null`                                                        |
| PATCH  | `/userItems/:id/note`                | Установить `{ note }`: строка или `null`; пробелы по краям удаляются, пустая строка становится `null` |
| POST   | `/userItems/:id/attempts`            | Добавить текущую или историческую попытку                                                             |
| PATCH  | `/userItems/:id/attempts/:attemptId` | Изменить переданные поля попытки                                                                      |

`:id` обозначает ID записи UserItem. Все операции требуют cookie `__Host-accessToken`, действующий JWT, активную серверную сессию своего пользователя и существующий аккаунт. Неуспешная проверка возвращает 401. Изменение существующей записи доступно её владельцу; чужая или отсутствующая запись возвращает 404. При добавлении недоступный или помеченный удалённым Item возвращает 404, повторное добавление — 409. Уже добавленное произведение остаётся доступно для редактирования после мягкого удаления из каталога. GET-маршруты не добавлены.

POST возвращает 201, PATCH — 200; оба возвращают итоговую запись с попытками. DELETE возвращает 204 без тела. Общий PATCH сохраняет пропущенные поля, разрешает `null` только для очистки оценки и заметки, отклоняет пустое тело и неизвестные поля. Изменять владельца, itemId и массив attempts через него нельзя. Удаление UserItem не меняет состав именованных списков.

Попытка имеет ID и обязательный статус `inProgress`, `onHold`, `completed` или `dropped`; необязательны `progress` (неотрицательное безопасное целое число минут или `null`), `unit` (только `minute`), `startedAt` и `completedAt` (даты ISO 8601 или `null`). Пропущенные поля PATCH сохраняются. Дата завершения не предшествует началу; у текущей попытки нет даты завершения. Одновременно допускается одна текущая попытка в inProgress/onHold; конфликт возвращает 409.

Добавление UserItem с planned создаёт пустую историю; другой статус создаёт первую попытку. Изменение статуса обновляет текущую попытку либо создаёт новую; повтор того же статуса не создаёт попытку. Начало текущей попытки через статус записывает текущее время начала, завершение или отказ — текущее время завершения. Перенос в planned при текущей попытке возвращает 409: сначала её нужно завершить или бросить.

Создание текущей попытки меняет статус UserItem; добавление или редактирование завершённой исторической попытки сохраняет текущий статус. Завершение текущей попытки через PATCH синхронизирует статус UserItem. При явном добавлении исторической попытки пропущенные даты остаются неизвестными; при добавлении текущей пропущенное startedAt становится текущим временем. Массив попыток не заменяется целиком через API.

Реализация находится в [модуле эндпоинтов](../../apps/api/src/endpoints/userItem/userItem.module.ts). Пересчёт ItemMetric и производных данных рекомендаций этими операциями пока не выполняется. Поведение в работающем окружении и миграция ранее сохранённых записей отдельно не проверены.
