# 5. Расширяемость

[Все основы проекта](../projectFoundations.md) · [Предыдущий пункт: личная библиотека и списки](04-library.md)

Документ фиксирует согласованные границы расширения проекта, а не состояние их реализации.

## Общий принцип

Система должна позволять добавлять произведения, источники, типы Item и версии рекомендаций предсказуемыми изменениями. Общие процессы переиспользуются, а специфичные поля и правила типов остаются явно описанными в коде.

## Границы расширения

| Что добавляется | Как происходит расширение |
| --- | --- |
| Новое произведение | Через согласованный процесс наполнения каталога |
| Новый жанр или feature | Через подготовленные данные и согласование в админке |
| Новый источник | Реализация получения данных источника и настройка его привязки к типам Item |
| Новый тип Item | Собственные поля и правила типа в коде с использованием общего процесса наполнения |
| Новая версия рекомендаций | Отдельная реализация с общим форматом запроса и результата |

## Новые произведения, жанры и features

Добавление отдельного произведения выполняется через [процесс наполнения каталога](02-catalogWorkflow.md). Подходящие произведения добавляются автоматически; новый жанр или feature применяется после согласования.

Features позволяют расширять набор характеристик со значениями в пределах [согласованной структуры данных](01-dataStructure.md). Собственные поля типа при этом не дублируются в features.

## Новые источники

Для источника реализуется получение его данных и задаётся привязка к подходящим типам Item. Настраиваются режимы и расписание сбора, а также использование источника при выборе значений полей.

Сохранение исходных данных, последующая нормализация, импорт, согласования и отчёты используют общие процессы проекта.

## Новые типы Item

Новый тип получает собственные поля и правила, как Movie, Game или AnimeMovie. Специфичные данные явно описываются в коде рядом с логикой своего типа.

Для нового типа определяются источники и правила допуска произведений. При этом переиспользуются общие процессы сбора, хранения исходных данных, AI-обработки, импорта, согласований, библиотеки и рекомендаций.

Например, подключение книг требует описать особенности этого типа и его источники. Загрузка данных, работа пользовательских списков и подключение к рекомендациям должны использовать общую основу.

## Новые версии рекомендаций

Версии механизма соблюдают [общий формат запроса и результата](03-recommendations.md#заменяемый-механизм-и-версии), сохраняют пользовательские данные и выполняют общие ограничения.

Будущий механизм через ИИ подключается как одна из реализаций. Замена алгоритма не должна требовать переделки каждого инструмента или одинакового внутреннего устройства профиля вкуса для всех версий.

## Что уточняется при реализации

Конкретная организация модулей, интерфейсов получения данных, настроек и экранов админки определяется при реализации. На уровне основ зафиксировано, какие расширения выполняются через данные и согласования, а какие требуют изменений кода.
