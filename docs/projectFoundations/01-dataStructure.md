# 1. Структура данных

[Все основы проекта](../projectFoundations.md) · [Следующий пункт: наполнение каталога](02-catalogWorkflow.md)

Документ фиксирует согласованные принципы, а не состояние их реализации.

## Компоненты описания произведения

### Общая часть — Item

Название, описание, тип произведения и другие общие данные.

Основные языки метаданных — русский и английский. Отсутствие перевода допустимо и не требует выдумывать значение.

### Данные конкретного типа

Movie, Game, AnimeMovie и другие типы имеют собственные поля, отражающие их специфику. Например, продолжительность фильма или поддерживаемые платформы игры.

### Теги

Смысловые признаки без отдельных значений: киберпанк, одиночество, нелинейный сюжет.

### Features

Дополнительные характеристики со значениями, которые не представлены собственными полями типа произведения. Например, бюджет может быть feature с суммой и валютой, если для него не предусмотрено отдельное поле.

### Embedding

Производное векторное представление произведения для поиска похожих произведений и рекомендаций. Оно строится на основе содержательных данных произведения и может пересчитываться при изменении данных или способа построения.

## Жанры, алиасы и иерархия

Одному понятию соответствует один канонический жанр с постоянным идентификатором и основным отображаемым названием.

Алиасы — альтернативные названия того же понятия. Например, у жанра «Научная фантастика» могут быть алиасы Sci-Fi, Science Fiction и НФ. Пользователю отображается основное название; алиасы помогают поиску, нормализации данных из разных источников и распознаванию общих признаков для рекомендаций.

Произведение связывается с каноническим жанром по его идентификатору. Алиасы принадлежат жанру и не создают дополнительные признаки или дополнительный вес в рекомендациях.

Поджанр является отдельным, более узким понятием со связью с более широким жанром. Например, внутри классификации Bisky можно использовать цепочку «Фантастика → Научная фантастика → Киберпанк». Это пример внутренней классификации, а не требование повторять структуру внешнего источника.

Определение жанра помогает отличать новое понятие от синонима существующего. Нейронка может предлагать новые жанры и связи в иерархии; их применение требует согласования, как описано в [процессе наполнения](02-catalogWorkflow.md#согласование-изменений).

Связь с более широким жанром позволяет учитывать его при поиске без отдельного назначения произведению всех предков. Рекомендации должны учитывать зависимость этих признаков, чтобы несколько уровней одной ветки не давали случайного многократного усиления.

## Правила

- Каждый факт имеет одно основное место хранения. Собственные поля типов не дублируются в тегах и features.
- Неполные данные допустимы. Описание произведения можно постепенно обогащать; неизвестное значение не заменяется нулём.
- Исходные данные сохраняются отдельно от embedding. Использование этих данных при его построении не считается дублированием фактов в модели.
- Теги, features и собственные поля доступны поиску и рекомендациям напрямую, независимо от embedding.
- Точные ограничения, например «фильм до двух часов», проверяются по соответствующим полям.

## Что уточняется позднее

Точный состав входных данных для embedding пока не выбран. Он может включать общее описание, теги, features, алиасы и подходящие поля конкретного типа произведения.

Теги и features не являются обязательным условием построения embedding. Решение об их включении принимается по тому, насколько они дополняют описание и улучшают результаты сравнения произведений.

Для конкретных характеристик ещё предстоит определить границу между собственными полями типа и features, сохраняя правило единственного места хранения факта.
