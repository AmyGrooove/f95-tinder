# 4. Личная библиотека и списки

[Все основы проекта](../projectFoundations.md) · [Предыдущий пункт: система рекомендаций](recommendations.md) · [Следующий пункт: расширяемость](extensibility.md)

Документ фиксирует согласованные принципы, а не состояние их реализации.

## Назначение

Пользователь может хранить и организовывать свои произведения на сайте. Личная библиотека является самостоятельной ценностью Bisky и помогает сохранять результаты поиска и выбора.

Статус, оценка, избранное и включение в собственные списки являются независимыми составляющими пользовательских данных.

## Статус произведения

У произведения в библиотеке пользователя один текущий статус:

- Запланировано.
- В процессе.
- Отложено.
- Завершено.
- Брошено.

Статус обязателен при добавлении произведения в библиотеку и не может быть `null`. Оценка, избранное и заметка доступны только после добавления; их изменение не создаёт запись библиотеки автоматически.

Стандартные разделы библиотеки, например «Запланировано», формируются по статусу. Для этого не требуется создавать отдельный пользовательский список с тем же смыслом.

## Оценка и избранное

Оценка по шкале 1–10 выражает отношение пользователя к произведению; её можно изменить или удалить. Избранное является отдельной отметкой.

Наличие оценки или отметки избранного не определяет статус и не меняет состав собственных списков. Добавление произведения в список также не изменяет эти данные.

## Собственные списки

Пользователь может создавать списки с произвольными названиями: например, «Посмотреть с друзьями», «Пересмотреть», «На выходные».

Одно произведение может входить в несколько списков одновременно. Его статус, оценка и отметка избранного остаются общими пользовательскими данными для этого произведения, а не отдельными значениями внутри каждого списка.

Например, фильм может одновременно иметь статус «Завершено», оценку 9, отметку избранного и входить в список «Пересмотреть».

## Заметки, прогресс и повторные попытки

В полном замысле сохраняются личные заметки, прогресс просмотра или прохождения и история отдельных повторных попыток. Эти возможности дополняют статус и оценку, а их конкретное поведение определяется при реализации.

## Отличие от состояний рекомендаций

Временный пропуск предложения и блокировка относятся к состояниям рекомендаций. Они не заменяют статус произведения в библиотеке.

Пропустить рекомендацию на сегодня и отложить уже начатое произведение — разные действия. Блокировка исключает конкретное произведение из будущих предложений без запроса причины.

## Связь с рекомендациями

Оценки, избранное, статусы и списки доступны системе рекомендаций с учётом значения каждого действия, описанного в [пункте 3](recommendations.md#сигналы-пользователя).

Добавление в запланированное выражает интерес, а завершение само по себе не означает положительную оценку. Конкретные правила выбора кандидатов из каталога и списков обсуждаются при реализации инструментов.

Если произведение помечено удалённым в каталоге, оно и пользовательские данные сохраняются в существующей библиотеке согласно [правилам удаления](catalogWorkflow.md#удаление-и-исчезновение-из-источников).

## Что уточняется при реализации

Интерфейсы библиотеки и списков, операции управления ими и конкретные правила работы инструментов определяются отдельно. На уровне основ зафиксированы независимость пользовательских данных и возможность создавать произвольные списки.

## Реализованные операции библиотеки

| Метод  | Путь                                 | Назначение                                                                                            |
| ------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| POST   | `/userItems`                         | Добавить произведение: `{ itemId, status }`                                                           |
| PATCH  | `/userItems/:id`                     | Атомарно изменить переданные `status`, `rating`, `isFavorite`, `note`                                 |
| DELETE | `/userItems/:id`                     | Удалить запись со всеми её данными и попытками                                                        |
| PATCH  | `/userItems/:id/status`              | Изменить `{ status }`                                                                                 |
| PATCH  | `/userItems/:id/favorite`            | Установить `{ isFavorite }`                                                                           |
| PATCH  | `/userItems/:id/rating`              | Установить `{ rating }`: целое 1–10 или `null`                                                        |
| PATCH  | `/userItems/:id/note`                | Установить `{ note }`: строка или `null`; пробелы по краям удаляются, пустая строка становится `null` |
| POST   | `/userItems/:id/attempts`            | Добавить текущую или историческую попытку                                                             |
| PATCH  | `/userItems/:id/attempts/:attemptId` | Изменить переданные поля попытки                                                                      |

`:id` обозначает ID записи UserItem. Все операции требуют авторизации и доступны владельцу записи; чужая или отсутствующая запись возвращает 404. При добавлении недоступный или помеченный удалённым Item возвращает 404, повторное добавление — 409. Уже добавленное произведение остаётся доступно для редактирования после мягкого удаления из каталога. GET-маршруты не добавлены.

POST возвращает 201, PATCH — 200; оба возвращают итоговую запись с попытками. DELETE возвращает 204 без тела. Общий PATCH сохраняет пропущенные поля, разрешает `null` только для очистки оценки и заметки, отклоняет пустое тело и неизвестные поля. Изменять владельца, itemId и массив attempts через него нельзя. Удаление UserItem не меняет состав именованных списков.

Попытка имеет ID и обязательный статус `inProgress`, `onHold`, `completed` или `dropped`; необязательны `progress` (неотрицательное безопасное целое число минут или `null`), `unit` (только `minute`), `startedAt` и `completedAt` (даты ISO 8601 или `null`). Пропущенные поля PATCH сохраняются. Дата завершения не предшествует началу; у текущей попытки нет даты завершения. Одновременно допускается одна текущая попытка в inProgress/onHold; конфликт возвращает 409.

Добавление UserItem с planned создаёт пустую историю; другой статус создаёт первую попытку. Изменение статуса обновляет текущую попытку либо создаёт новую; повтор того же статуса не создаёт попытку. Начало текущей попытки через статус записывает текущее время начала, завершение или отказ — текущее время завершения. Перенос в planned при текущей попытке возвращает 409: сначала её нужно завершить или бросить.

Создание текущей попытки меняет статус UserItem; добавление или редактирование завершённой исторической попытки сохраняет текущий статус. Завершение текущей попытки через PATCH синхронизирует статус UserItem. При явном добавлении исторической попытки пропущенные даты остаются неизвестными; при добавлении текущей пропущенное startedAt становится текущим временем. Массив попыток не заменяется целиком через API.

Реализация находится в [модуле эндпоинтов](../../apps/api/src/endpoints/userItem/userItem.module.ts). Пересчёт ItemMetric и производных данных рекомендаций этими операциями пока не выполняется. Поведение в работающем окружении и миграция ранее сохранённых записей отдельно не проверены.
