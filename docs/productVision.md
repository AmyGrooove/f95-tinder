# Bisky — концепция и полный список задуманных функций

## Что такое Bisky?

**Bisky — платформа для поиска, организации и персональных рекомендаций медиаконтента:** аниме, игр, adult-игр, фильмов, сериалов, книг и других произведений.

Главная идея — система изучает вкусы пользователя по его оценкам, действиям и интересам, а затем самостоятельно помогает выбрать, что посмотреть, во что поиграть или что прочитать. Причём предпочтения из одной категории должны помогать находить интересный контент в других.

**Основной принцип: минимум действий от пользователя, максимум понимания его вкусов.**

## 1. Единый каталог медиаконтента

- Фильмы.
- Сериалы.
- Аниме.
- Видеоигры.
- Adult-игры.
- Книги.
- Возможность добавления новых типов медиа в дальнейшем.
- Общая система поиска и рекомендаций для всех категорий.
- Отдельные полноценные карточки произведений со специфичными характеристиками.
- Связи между произведениями: продолжения, приквелы, ремейки, сезоны и другие отношения.
- Отдельные карточки актёров, персонажей, разработчиков и других связанных объектов.
- Франшизы, объединяющие связанные произведения.
- Поддержка нескольких языков, первоначально русского и английского.
- Оригинальные, локализованные и альтернативные названия.

## 2. Поиск и фильтрация

- Быстрый поиск по всему каталогу.
- Поиск по названиям на разных языках.
- Поиск по оригинальным названиям и альтернативным написаниям.
- Поиск по тегам, темам и характеристикам.
- Фильтрация по типу контента.
- Фильтрация по году выхода, продолжительности, стране и языку, где применимо.
- Фильтрация по специфическим характеристикам произведений.
- Возможность искать вручную, не используя рекомендации.
- Отображение только актуальной карточки при наличии нескольких записей одного произведения.

- Сбор информации из различных внешних источников.
- Интеграции с API сторонних сервисов.
- Парсеры сайтов, где это допустимо.
- Ручной импорт данных.
- Объединение информации из нескольких источников.
- Нормализация данных к общему формату.
- Автоматическое обнаружение дубликатов.
- Объединение дубликатов в одну карточку.
- Обнаружение противоречий между источниками.
- Использование AI для сопоставления произведений и разрешения неоднозначностей.
- Использование AI для перевода названий и описаний.
- Извлечение характеристик и тегов с помощью AI.
- Предложение новых тегов через AI с проверкой перед публикацией.
- Приоритеты источников и ручные исправления.
- Сохранение происхождения информации, чтобы понимать, откуда взялось значение.
- Обновление данных без создания повторных карточек.
- Возможность отменить ошибочное объединение произведений.
- Сохранение пользовательских оценок и списков при исправлении каталога.
- Постепенная автоматизация сбора и AI-обработки вместо постоянной ручной работы.

## 4. Режимы выбора контента

### «Bisky выбирает» — центральная функция

- Выбрать произведение для просмотра или игры прямо сейчас.
- Найти интересное произведение и сохранить на будущее.
- Получать готовые рекомендации без ручного заполнения сложных фильтров.
- Получать предложения даже без сформированного профиля вкусов.

### «Тиндер медиа»

- Последовательный просмотр карточек.
- Минимум информации для быстрого решения.
- Действия: сохранить, пропустить, оценить, больше не предлагать.
- Постепенное обучение рекомендаций по реакциям пользователя.

### «Царь горы»

- Выбор из заданной подборки произведений.
- Сравнение двух кандидатов.
- Победитель сравнивается со следующим.
- Продолжение сравнений до одного победителя.

### Быстрая оценка

- Последовательная оценка уже знакомых произведений.
- Шкала от 1 до 10.
- Возможность быстро сформировать начальный профиль вкусов.

### Помощь с оценкой

- Мини-опросник с вопросами «да/нет».
- Система предполагает числовую оценку на основе ответов.
- Пользователю проще оценить произведение, если трудно самостоятельно выбрать число.

## 5. Персональные рекомендации и профиль вкуса

- Постепенное изучение предпочтений пользователя.
- Формирование персонального профиля вкусов.
- Анализ оценок, избранного, сохранений, пропусков и других действий.
- Учитывание тегов, жанров, атмосферы, тем и характеристик произведений.
- Определение того, насколько сильно пользователю нравится конкретный признак.
- Разделение силы предпочтения и уверенности системы в нём.
- Сохранение нескольких независимых интересов пользователя: например, любовь одновременно к комедиям и мрачным триллерам.
- Отсутствие чрезмерных выводов по единственной оценке.
- Защита от доминирования одного популярного тега в рекомендациях.
- Учитывание распространённости тегов в каталоге.
- Временное снижение приоритета слишком часто рекомендуемых тем.
- Разнообразие рекомендаций, чтобы пользователь не получал постоянно похожие произведения.
- _Exploration_ — периодическое предложение неожиданных произведений за пределами привычных интересов.
- Учитывание негативных оценок без автоматического исключения всех похожих произведений.
- Постоянный запрет рекомендации конкретного произведения по действию «Не предлагать».
- Временное снижение приоритета пропущенного произведения и похожего контента.
- Постепенное ослабление влияния временных пропусков.
- Защита от постоянного повторения одних и тех же рекомендаций.
- Отдельные правила для поиска контента «на сейчас» и «на будущее».
- Начальные рекомендации по популярности, рейтингам и количеству оценок, пока система ничего не знает о пользователе.
- Переход к персональным рекомендациям по мере изучения вкуса.
- Объяснение причин рекомендаций: почему система предложила конкретное произведение.
- Возможность визуализации профиля вкусов.
- Сравнение нескольких алгоритмов рекомендаций.
- Сохранение истории рекомендаций и реакций для анализа их качества.
- Возможность пересчитать профиль вкусов по истории действий.
- Поддержка обновления алгоритмов без потери накопленных предпочтений.
- В дальнейшем — embeddings, машинное обучение и более сложные модели.
- В дальнейшем — симуляция пользователей с помощью нескольких AI-моделей для проверки качества рекомендаций.

**Отдельная ключевая задумка — рекомендации между разными типами контента.** Например, если пользователь любит игры с киберпанковой атмосферой, система может предложить ему аниме или фильм с похожей атмосферой, даже если он ещё не оценивал фильмы этой тематики.

**Стартовые ориентиры алгоритма, выбранные при обсуждении:** 24 часа до повторного предложения после показа, 7 дней после пропуска, затухание влияния пропуска с периодом полураспада 3 дня, до трёх центров интереса и 20% exploration.

## 6. Личная библиотека

- Личная коллекция произведений пользователя.
- Пять статусов: запланировано, в процессе, отложено, завершено, брошено.
- Оценки произведений по шкале 1–10.
- Возможность изменить или удалить оценку.
- Независимое избранное.
- Личные заметки к произведениям.
- Сохранение произведений на будущее.
- Фильтрация и сортировка личной библиотеки.
- Отслеживание прогресса просмотра или прохождения.
- Разные единицы прогресса в зависимости от типа контента: минуты, серии, главы, проценты и другие.
- Повторные просмотры и прохождения.
- Отдельная история каждой попытки просмотра или прохождения.
- Сохранение предыдущего прогресса при повторном прохождении.
- Возможность исправлять ошибочно записанные действия.
- История изменений оценок, статусов, прогресса и других действий.
- Предложения вернуться к незавершённым произведениям.
- Возможность иметь личные списки для организации произведений.
- В будущем — собственные пользовательские теги для группировки содержимого списков.

## 7. Аккаунты и авторизация

В документах есть изменение решения: первоначально планировались временные аккаунты с последующим переходом в постоянные, но позже была выбрана другая модель.

**Последний согласованный вариант:**

- Обычный сохраняемый аккаунт с самого начала.
- Возможность открыть публичный каталог без создания аккаунта.
- Регистрация с автоматически сгенерированным логином и постоянным секретным кодом.
- Возможность перевыпустить код.
- Авторизация через Яндекс для пользователей в РФ.
- Авторизация через Google для пользователей вне РФ.
- Возможность привязать дополнительные способы входа к существующему аккаунту.
- Необязательная электронная почта.
- Восстановление доступа через подтверждённую электронную почту.
- Восстановление доступа через доступный привязанный внешний сервис.
- Сохранение одного аккаунта и его данных при добавлении способа авторизации.
- Отсутствие автоматического объединения двух разных аккаунтов.
- Сессии с продлением срока действия.
- Управление активными сессиями и выход из них.
- Отсутствие автоматического удаления аккаунтов, библиотек и истории из-за неактивности.
- Возможность синхронизации с пользовательскими аккаунтами внешних медиаисточников в дальнейшем.

Email/пароль упоминался в раннем продуктовом замысле, но в актуальную первую реализацию не входит.

## Что было выбрано для первой версии

Несмотря на масштаб общего замысла, в документах для первого этапа были выбраны **только фильмы**, чтобы проверить полный цикл:

**Наполнение каталога → Поиск → Аккаунт → Библиотека → Профиль вкуса → Рекомендации → Реакции пользователя → Обновление вкуса.**

Остальные направления — не отменённые идеи, а дальнейшее развитие платформы.

Этот документ содержит продуктовые функции и направления без технических подробностей реализации: MongoDB-схем, индексов, транзакций, DTO и служебных механизмов восстановления после сбоев.
