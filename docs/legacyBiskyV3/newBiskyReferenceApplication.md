# Применение референсов к новому Bisky

[Навигатор архива](readme.md) · [Проверенные desktop-состояния](screensDesktop.md) · [Различия источников](differencesAndOpenQuestions.md)

Это **аналитические предложения**, а не согласованная спецификация страниц, дизайна, архитектуры или нового API. Старые 58 desktop-экспортов помогают увидеть возможные сценарии; их наличие не включает функцию в MVP. Старый Swagger остаётся историческим источником. Названия новых маршрутов здесь не фиксируются: сначала нужно согласовать поведение общих операций.

Основание: [актуальный навигатор](../readme.md), [основы](../product/foundations.md) и разделы о [данных](../product/foundations/dataStructure.md), [наполнении](../product/foundations/catalogWorkflow.md), [рекомендациях](../product/foundations/recommendations.md), [библиотеке](../product/foundations/library.md), [расширяемости](../product/foundations/extensibility.md), [MVP](../product/mvpScope.md), [аккаунт](../api/accountAndAuthSpec.md). Статическая сверка 24 октября 2026 года добавила [проверенный legacy-код](implementation.md) и актуальные контракты [библиотеки](../api/librarySpec.md) и [подборок](../api/collectionsSpec.md); наличие работающего интерфейса из этого не следует.

Уже определённые операции не нужно проектировать заново по старым экранам. Изменение библиотеки и попыток реализовано девятью маршрутами `/userItems`; отдельного GET библиотеки нет. Удаление UserItem удаляет запись вместе с оценкой, заметкой и попытками. Публичные ручные подборки имеют десять маршрутов отдельного контракта, блоки и контроль версии; они не заменяют приватные списки. Каталог, рекомендации и импорт сохраняют границы готовности из [обзора API](../api/readme.md).

## Рекомендуемый первый цикл

Рассмотреть компактную связку **каталог/поиск → карточка фильма → личная библиотека → рекомендации**, с общими личными действиями во всех этих местах. Аккаунт и настройки проектировать вокруг согласованного контракта. Это следует выбранному порядку: каталог → библиотека → рекомендации → сбор/импорт.

Отдельная насыщенная главная по старому образцу необязательна для этого цикла. Начальной страницей может быть каталог с входами в библиотеку и рекомендации; самостоятельная главная полезна, если её блоки решают подтверждённые пользовательские задачи. Решение о навигации остаётся открытым.

## Страницы и сценарии

| Референс | Польза | Соответствие MVP и предлагаемая адаптация |
| --- | --- | --- |
| Главная: карусель, топ, продолжение | Вход в каталог и возврат к незавершённому | Отдельная главная и её состав не согласованы. Переиспользовать карточки каталога и библиотечный прогресс; не переносить новые серии, факты и баннер автоматически. Без плеера «продолжение» может означать возврат к карточке с ручным прогрессом — это предложение |
| Начальный поиск и результаты | Запрос, фильтры, начальное состояние | Поиск фильмов по названию, тегам и основным фильтрам входит в MVP. Рассмотреть объединение с каталогом; убрать типы пользователей/клубов/коллекций. Начальное приглашение и нулевая выдача — разные состояния |
| Информация: релиз/онгоинг/анонс | Название, постер, описание, характеристики, ссылки и личные действия | Карточка фильма входит в MVP. Русский/английский и неполные данные допустимы. Продолжительность через feature, страна и смысловые признаки через теги по основам; единый Item. Сезоны/эпизоды и онгоинг аниме не нужны текущему типу movie |
| Список пользователя и hover | Открывать произведение, менять личные данные, фильтровать | Библиотека входит в MVP. Пять согласованных статусов вместо четырёх старых. Оценка, избранное, заметка и прогресс независимы; hover может раскрывать уже загруженные данные. Действия должны быть доступны и без наведения; дизайн ещё не выбран |
| Избранное профиля | Найти важные произведения | Независимое избранное входит в MVP. Рассмотреть фильтр библиотеки вместо публичной витрины; старый favoriteAnimes не определяет новый контракт |
| Профиль и история | Сводка собственных данных и возврат к действиям | Публичный профиль с друзьями/ролью/посещением и открытой историей вне стартового объёма. Личная сводка обсуждается отдельно. Хранение истории действий для рекомендаций не означает публичную страницу истории |
| АниПик | Один кандидат, краткая информация, сохранение/пропуск | Рекомендации и реакции входят в MVP; полный инструмент требует обсуждения. Рассмотреть простую выдачу с подписями «Сохранить», «Пропустить», «Не предлагать». Не переносить неизвестные счётчики и шаг назад |
| АниСудья | Необязательная оценка знакомых фильмов | Оценки 1–10 входят в MVP; отдельный БыстрыйРейтинг и его очередь не специфицированы. Переиспользовать оценивание, без неподписанных дробных показателей. Тождество старого инструмента БыстромуРейтингу не согласовано |
| АниБаттл: настройка/ошибка/пары/финал | Сократить набор попарным выбором | Относительное предпочтение предусмотрено основами, поведение инструмента обсуждается отдельно. Не включать полный баттл в этап автоматически. Определить источник кандидатов, отмену, срок жизни и необходимость сохранения раундов |
| Аккаунт и настройки до/после пароля | Объяснить вход и управлять своими данными | Следовать существующим 20 маршрутам. С регистрации аккаунт постоянный, секретный код — до настройки. Email/пароль устанавливаются вместе после подтверждения. Не переносить временность, удаление за неактивность, независимое преобразование через email/пароль/OAuth |
| Каталог и страницы коллекций | Тематическая организация | Публичные подборки и реакции уже реализованы отдельно от исходного MVP по своему контракту; общий список и поиск подборок ещё не добавлены. Старые категории, комментарии и официальные роли автоматически не переносятся. Личные произвольные списки — целевая возможность с ещё не выбранным этапом; публичная модель их не заменяет |
| Клубы/персоны озвучки | Связанные сущности и внешние ссылки | Старые домены не нужны стартовому каталогу фильмов. Если понадобятся участники создания фильма, обсудить источники и модель; не переименовывать dub-person в актёра автоматически |
| Плеер, выбор серии, лицензия/территория | Пояснить недоступность операции | Встроенный просмотр и эпизодный API вне исходного MVP. Ссылка источника не обещает воспроизведение. Разделять недоступность просмотра, удаление каталога и персональную блокировку рекомендаций |
| Комментарии, уведомления, поддержка | Обратная связь и статусы | Социальные функции вне стартового объёма. Можно рассмотреть простую страницу/ссылку контактов без системы обращений; необходимость и контакты обсуждаются. Старые email и соцсети не объявляются действующими |
| Достижения и AnimePass | Долгосрочная мотивация | Геймификация вне стартового объёма; расчёт опыта, награды и связанные уведомления не нужны базовому циклу |
| Ошибки 401/403/404/500 | Объяснить состояние и следующий шаг | Рассмотреть сообщения, повтор и вход по текущему контракту. Самостоятельный URL и endpoint на каждый код не требуются |

Новых mobile, модальных окон и раскрытых меню нет. Их прежние описания сохранены как дополнительный материал; адаптивный интерфейс, форма входа и меню из них не считаются утверждёнными.

## Общие данные и операции backend

Ниже — потребности сценариев, не DTO и не соответствие «один блок — один маршрут». Запросы проектируются с учётом объёма данных, повторного использования, приватности и стоимости получения.

| Общая операция / данные | Где используются | Что определить |
| --- | --- | --- |
| Выборка каталога и поиск | Каталог, поиск, возможные ряды главной, выбор для будущих списков | ID, название, постер, краткие характеристики; запрос, теги, features; порядок и продолжение. Каталог/поиск могут разделять операцию с разными условиями |
| Справочники | Фильтры, карточка, подбор | Канонические ID, названия, алиасы, иерархия, типы значений и единицы; доступные фильтры и неизвестные значения |
| Карточка Item и связи | Полная страница, инструмент, библиотека | Поля Item, теги/features, источники, связи, медиаматериалы. Не копировать base/mini/additional без обоснования; краткое представление может входить в список, тяжёлое — догружаться |
| Чтение личного состояния набора Item | Каталог, карточка, библиотека, рекомендации | Статус, оценка, избранное, заметка, прогресс с приватностью владельца. Пакетное чтение или личная часть ответа могут избежать запроса на каждый постер; способ не выбран |
| Изменение личных данных Item | Все места сохранения/оценки/избранного/заметки | Использовать действующие общий и частные PATCH `/userItems`, не изобретать операции заново по legacy. Оценка, избранное и заметка не меняют статус; статус и текущая попытка синхронизируются по контракту |
| Библиотека и прогресс | Пять разделов, избранное, возврат к незавершённому | Изменения попыток уже определены: ID, статус, даты, прогресс в минутах. DELETE удаляет UserItem вместе с попытками. Для будущего чтения остаются поиск/фильтрация, стабильный порядок и пагинация; мягко удалённый из каталога Item остаётся в существующей библиотеке |
| Выдача рекомендаций | Отдельная выдача, потенциальные инструменты и ряды | Условия, упорядоченные кандидаты, происхождение и версия механизма/настройки; общие исключения блокировок/удалённых. Версия embedding учитывается отдельно при его применении; это не включает embedding в первый этап |
| Показ и реакция | Любое место реального предложения | Полученная порция отличается от фактически показанного элемента. Сохранить, временно пропустить, не предлагать; история независима от версии алгоритма и позволяет пересчёт профиля. Библиотечное сохранение и журнал должны согласованно отражать одно действие |
| Относительный выбор и оценка | Будущие баттл и БыстрыйРейтинг | Общая оценка и кандидаты переиспользуются; журнал сравнений и серверная сессия зависят от требований восстановления. Проигрыш не равен отрицательной оценке |
| Аккаунт, настройка, сессии | Шапка, вход, настройки, защищённые действия | Использовать согласованные whoami/account, setup, email, password, code, session. Новый экран не расширяет ответы секретами, географией или сохранённым открытым кодом |
| Сбор/импорт | Последующий этап наполнения; старых экранов админки нет | Исходные выгрузки в S3, подготовленный JSON, проверка/применение без дублей, согласования, ручные исправления и отчёт. animeParse/mainFeed не являются готовой новой архитектурой |

Агрегация ответов, число запросов и границы маршрутов выбираются после определения поведения. Переключение вкладки, hover, меню, раскрытие полученного текста и сортировка сами по себе не требуют отдельного endpoint. Несколько страниц могут использовать одну операцию; одна страница — несколько запросов по независимым данным.

## Что упростить сначала

1. Только фильмы по правилам допуска, включая документальные; убрать эпизодные термины. Строить карточку из Item, тегов и features с допустимыми пробелами переводов.
2. Рассмотреть общую панель поиска/фильтров и карточки каталога. Топы, карусели и факты обосновать пользовательской задачей до добавления загрузки и поддержки данных.
3. Переиспользовать личные действия. Пять статусов не сливаются с оценкой, избранным, заметкой, временным пропуском или «Не предлагать».
4. Начать с простого механизма рекомендаций и понятных подписей. Не показывать выдуманные оценки соответствия или график вкуса. Необязательное оценивание знакомого полезно для холодного старта; обязательный опрос не следует из требований.
5. Настройки строить вокруг совместной первоначальной установки email/пароля и подтверждений. Секретный код показывается только при выдаче/перевыпуске; старое постоянно маскированное поле не требует хранить или возвращать код.
6. Не добавлять социальные блоки и геймификацию ради заполнения старой композиции. Для уже реализованных публичных подборок использовать их контракт; новые страницы и старые дополнительные функции из него автоматически не следуют.

Сохранение старой структуры дало бы готовую композицию, но потребовало бы данных о сериях, друзьях, коллекционных рейтингах, заданиях и озвучке, не нужных текущему циклу. Поэтому рекомендуется использовать отдельные полезные сценарии и общие действия, определив новый внешний вид и навигацию отдельно. Это оценка по текущим границам, не утверждение дизайна.

## Решения до определения эндпоинтов

| Вопрос | Что он меняет |
| --- | --- |
| Совмещать ли каталог/поиск, что показывает начальная страница? | Выборки и необходимость агрегированной главной вместо API на каждый ряд |
| Какие поля в списочной/полной карточке, что делать без перевода/постера? | Ответы, подстановка доступных данных, необходимость догрузки |
| Какие фильтры доступны, как сочетаются теги/иерархия и features? | Семантика запроса, единицы, диапазоны, неизвестные значения; точные ограничения длительности проверяются по feature |
| Какие сортировки и как продолжать при одинаковых значениях? | Стабильный порядок, пагинация, сброс фильтров |
| Какие личные состояния нужны со списком, как обновлять их между вкладками? | Пакетное чтение, приватность, согласованность действий |
| Как показать удаление, ручной прогресс и повтор фильма без плеера? | Интерфейс должен объяснять действующий контракт: удаление всей записи, попытки с ID и прогресс в минутах; выбор поведения API уже сделан |
| Что считать показом, когда заканчивается пропуск и можно ли отменять? | События, повторные показы/запросы, конкуренция, шаг назад; получение списка не равно показу всех элементов |
| Как объяснить «Брошено», «Отложено», пропуск и «Не предлагать»? | Раздельные смыслы и данные. Блокировка конкретного Item без причины уже задана основами; срок пропуска ещё нет |
| Какие инструменты входят в ближайший законченный этап? | Необходимость сохранения сравнений/раундов и восстановления между устройствами |
| Нужны ли произвольные личные списки в первом этапе? | CRUD состава списков. Стандартные разделы по статусам уже нужны и не требуют копий списков |
| Какие служебные состояния интерфейса нужны? | Гость, загрузка, пустая библиотека, нет результатов/кандидатов, ошибка записи, истёкшая сессия, удалённый Item; большинство отсутствует в PNG |
| Какой минимум управления наполнением нужен после пользовательских этапов? | Пакет, запуск/статус/отчёт, согласования. Полная админка, расписания и embedding требуют выбора объёма |

Эти вопросы не задерживают обновление архива и не означают согласия на реализацию предложений. Открытые контракты каталога, чтения библиотеки и рекомендаций обсуждаются в соответствующих задачах; действующие контракты аккаунта, изменений библиотеки и подборок сохраняются.
