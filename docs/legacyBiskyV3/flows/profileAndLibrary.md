# Профиль, библиотека и пользовательская история

[Карта страниц](../pagesAndFlows.md) · [Старый Swagger](../swagger.md)

**Источники:** desktop-сведения сверены с новыми экспортами; [описание каждого из 58 состояний](../screensDesktop.md) содержит наблюдения и ограничения. Mobile, модальные окна и меню ниже — сведения прежнего исследования, не проверенные новыми изображениями. Связи со Swagger являются сопоставлениями, а не трассировкой запросов.

## Публичный профиль

Desktop `4127:16292`, mobile `4199:16474`. [Снимок](../screenshots/desktop/profileInfo.png).

Шапка содержит фон, аватар, имя, последнее посещение, роль и значок жалобы. Вкладки: «Инфо», «Избранное», «Список аниме», «Комментарии». Информационная вкладка содержит друзей, добавление в друзья, распределение списка по статусам, дату регистрации, просмотренные минуты, счётчики достижений, комментариев и правок/предложений, последние действия, достижения, AnimePass и календарь активности с выбором года.

Чтения: `GET /profile/{ID}`, `/additional`, `GET /profile/{slug}/meta`. Распределение блоков между основным и дополнительным ответом не известно. Политики приватности, видимость чужих данных, география и роль не выводятся из наличия публичного макета.

Окно друзей `4181:34207` показывает список людей. В старом списке API нет явных маршрутов чтения друзей, отправки/принятия/отклонения заявок. Они могли находиться в другом API, но здесь не восстановлены.

## Избранное

Desktop `4160:15853`, mobile `4201:16081`: поиск, сортировка и сетка произведений с рейтингом. [Снимок](../screenshots/desktop/profileFavorites.png).

`GET /profile/{ID}/favoriteAnimes` сопоставляется с чтением. Окно `4181:34144` содержит поиск нового аниме, элементы и «Сохранить»; `PATCH /profile/favoriteAnimes` — кандидат для этой операции. Не известно, является ли это полным избранным, отдельным избранным на витрине профиля или упорядоченным подмножеством. Оно не приравнивается автоматически к `POST /anime/{ID}/favorite`.

## Список пользователя

Desktop `4160:16536`, hover `4161:14407`; mobile `4201:16731`. [Снимок](../screenshots/desktop/profileAnimeList.png).

Есть поиск, фильтры, сортировка, четыре раздела: «Добавлен», «Смотрю», «Просмотрен», «Брошен». Hover затемняет первую карточку, раскрывает длинное название и показывает кнопку с вертикальным многоточием; рейтинг остаётся видимым. Содержимое меню не раскрыто. Чтение сопоставляется с `GET /profile/{ID}/animeList`. Пагинация, серверные фильтры, редактирование чужого списка и точный состав карточек не заданы.

Окно редактирования `4181:34157`:

- Выбранный статус; действия «В список», «Смотрю», «Просмотрел», «Бросил».
- «Удалить» и «Пересмотреть» как отдельные действия, а не дополнительные статусы.
- Шкала из десяти звёзд, изменение/удаление оценки.
- Счётчик пересмотров с уменьшением/увеличением.
- Независимое избранное; «Отмена» и «Сохранить».
- Вкладка «Серии» (`4181:34192`) с прогрессом.

Отдельные окна: `StarModal` `4181:34857`/`4181:34863` для постановки и изменения оценки; `ListStatusModal` `4181:34869`/`4181:34876` для статуса, удаления и пересмотра.

Сохранение сопоставляется с `PATCH /anime/{ID}/userReaction`, отдельными `/score`, `/favorite`, `/userStatus`, удаление — с `DELETE /anime/{ID}/userReaction`, прогресс серий — с эпизодными маршрутами. Список Swagger не описывает, что именно удаляется, как хранится повторный просмотр и сохраняется ли прежний прогресс.

[Сверка модели и контроллеров](../implementation.md) подтверждает `UserAnimeReaction` с уникальной парой `author`/`animeID`, четырьмя статусами `added`, `watching`, `completed`, `dropped`, отдельными `score`, `isFavorite`, `reWatchedCount`. Прогресс эпизодов хранится отдельно в `UserEpisodeProgress`; счётчик пересмотров не является историей попыток. В новом API используются `UserItem`, пять статусов и [попытки с собственными ID](../../api/librarySpec.md). Удаление новой записи физически удаляет и её попытки; сохранение истории после удаления не является действующим контрактом.

Фрейм mobile `4227:16807` назван «Список аниме», но тексты в нём — комментарии. Имя сохранено в реестре как есть. «Комментарии пользователя» (его сообщения) и «Комментарии по пользователю» (обсуждение страницы) — разные сценарии, хотя относятся к одному человеку.
