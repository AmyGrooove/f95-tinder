# Инструменты выбора и оценивания

[Карта страниц](../pagesAndFlows.md) · [Старый Swagger](../swagger.md)

**Источники:** desktop-сведения сверены с новыми экспортами; [описание каждого из 58 состояний](../screensDesktop.md) содержит наблюдения и ограничения. Mobile, модальные окна и меню ниже — сведения прежнего исследования, не проверенные новыми изображениями. Связи со Swagger являются сопоставлениями, а не трассировкой запросов.

## АниПик

Desktop `4011:10065`, шаг назад `4016:7798`; mobile `4182:16375`, `4182:16507`. [Снимок](../screenshots/desktop/aniPick.png).

На desktop слева находятся название, характеристики, рейтинг, возраст, раскрываемое описание и кадры; справа — постер, иконки списка/фильтра и действий, стрелка назад, числовой индикатор и «Смотреть сейчас». На главной инструмент описан как показ тайтла с краткой информацией и выбор «добавить в список или пропустить».

Старый API: `GET /aniPick`, `POST /aniPick/skipList`. Сохранение статуса, оценки и избранного сопоставляется с общими операциями `/anime/{ID}/...`. Отдельный сценарий постоянной блокировки в присланном API не идентифицирован.

По картинке нельзя точно установить смысл каждого безымянного значка, числового индикатора, атомарность перехода к следующему элементу и то, отменяет ли шаг назад уже сохранённое действие. Новый вариант «шаг назад» добавляет маленький розовый глаз в левом нижнем углу постера; остальные основные элементы сохранены. Название файла не доказывает отмену серверной реакции. Наличие `skipList` не задаёт срок пропуска. `POST /bannedAnime` нельзя автоматически считать пользовательским «Не предлагать».

[Проверка legacy-кода](../implementation.md) уточняет персональный пропуск: `AniPickService` записывает пользователя и аниме в `SkippedAnime`, исключает его пропущенные ID из кандидатов; схема задаёт TTL 90 дней. Это не проверка установленного индекса или точного момента удаления записи. Отдельный `POST /bannedAnime` требует администратора и работает с глобальными `shikimoriIDs`. Срок и семантика пропуска нового Bisky определяются отдельно; постоянное персональное «Не предлагать» эти legacy-механизмы не заменяют.

Завершение списка: окно `4181:34333` (в Figma «Концвока АниПик») сообщает, что список окончен, и предлагает новый выбор/просмотр, переходы к АниПик и АниБаттл. Формат сохранённого набора кандидатов не известен.

Мобильный фрейм заметно компактнее. Подробности могут открываться в общем `InfoModal` `4181:36995`, но конкретный переход прототипа не проверен.

## АниБаттл

| Состояние | Desktop | Mobile |
| --- | --- | --- |
| Настройка | `4011:10304` | `4184:14980` |
| Ошибка настройки | `4011:11006` | `4184:15147` |
| Начало | `4011:10869` | `4183:14786` |
| Следующие шаги | `4011:10736` | `4186:15244` |
| Победитель | `4011:11112` | `4186:15304` |

Настройка позволяет выбирать четыре старых статуса списка. Текст объясняет последовательное сравнение двух аниме: выбранное остаётся, проигравшее заменяется новым кандидатом. Пары содержат «Выбрать», `VS` и счётчик раунда. Победитель предлагает начать просмотр. В новой обычной настройке выбран «Добавлен», ошибки нет, кнопка «Начать» яркая; в ошибочной выбран «Смотрю», показано красное сообщение о списке меньше двух и затемнена кнопка. Начало и следующие шаги различаются примерным индикатором 1/18 и 8/18, а также тёмной/яркой стрелкой назад. Фактическая доступность кнопок не проверена. Desktop-финал показывает один постер и «Начать просмотр», без VS и счётчика. Окно из прежних сведений `4181:34329` требует два или более аниме и предлагает АниПик.

Старый API содержит только `GET /aniBattle` с описанием «Получение списков аниме по статусам». Маршрутов создания серверного баттла, записи победителя пары, восстановления сессии баттла и фиксации финала не указано. Сравнения могли быть локальными, но это не подтверждено. Повторённые числа раундов в mobile-макетах нельзя использовать как алгоритмическое требование.

## АниСудья / AniJudge

Desktop `4011:11247`, mobile `4191:14901`. [Снимок](../screenshots/desktop/aniJudge.png).

Есть постер и название произведения, отметка «Просмотрено», десятизвёздочная шкала, числовые показатели, стрелка между двумя дробными значениями, избранное и «Дальше». Значение показателей вроде `126` и `8.76 → 6.41` не подписано; они не объявляются формулой изменения рейтинга или профиля вкуса.

`GET /aniJudge` возвращает список для инструмента по исходному описанию. Оценивание и избранное сопоставляются с общими `/score` и `/favorite`; сохранение по клику звезды либо по «Дальше» не установлено. Окно `4181:34340` требует хотя бы одно произведение в просмотренном и предлагает АниБаттл.

Это близко к задумке БыстрогоРейтинга, но их полное тождество и перенос имени не согласованы. Старые экраны не определяют алгоритм рекомендаций, запись фактических показов, сроки пропуска и объяснение результата для нового Bisky.
