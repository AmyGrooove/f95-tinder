# Bisky — границы MVP backend

Согласовано 12 октября 2026 года.

## Цель

Проверить цикл: найти фильм → оценить или сохранить → получить рекомендации → улучшить рекомендации своими реакциями.

## Состав первой версии

1. Только фильмы. Поддержка русского и английского языков.
2. Каталог: ручной импорт, карточки фильмов, теги, характеристики и привязка внешних источников.
3. Поиск по названию, тегам и основным фильтрам.
4. Аккаунт: регистрация с логином и постоянным секретным кодом, вход, выход и управление сессиями.
5. Личная библиотека: пять статусов, оценки 1–10, избранное, заметки и прогресс просмотра.
6. Рекомендации: по рейтингу для нового пользователя, по предпочтениям в тегах после появления оценок.
7. Реакции: сохранить, пропустить и «не предлагать». История действий и ограничение повторных предложений.

## Отложено

OAuth, автоматические парсеры, AI-обработка, embeddings, социальные функции, подборки, геймификация и оплата.

## Порядок работ

1. Завершить модель данных: определить поля Movie и необходимые значения enum, согласовать хранение истории действий; устранить ссылки AppModule на отсутствующие модули в соответствии с составом MVP. Проверить типы и регистрацию моделей.
2. Реализовать ручной импорт фильмов: определить входной формат, проверять данные, сопоставлять записи и повторно импортировать без создания дублей. Сохранять привязку внешних источников.
3. Реализовать публичный API каталога: карточка фильма, поиск, фильтры и пагинация. Определить минимальный набор фильтров перед реализацией.
4. Реализовать аккаунты и сессии: генерация логина и секретного кода, вход, перевыпуск кода, продление и отзыв сессий; проверка владельца пользовательских данных.
5. Реализовать библиотеку и запись истории действий: статусы, оценки, избранное, заметки, прогресс и повторные просмотры.
6. Реализовать пересчёт профиля вкуса по оценкам и действиям пользователя.
7. Реализовать рекомендации и реакции: стартовая и персональная выдача, сохранение истории показов, пропуски, постоянное исключение и ограничение повторов. Перед реализацией определить формулу ранжирования и сроки повторных предложений.
8. Проверить полный пользовательский цикл и подготовить запуск: конфигурация, индексы, логи и резервное копирование. Проверку тестами согласовать отдельно.

## Критерии готовности

- Фильмы можно импортировать повторно без появления дублей и найти через публичный API.
- Пользователь может создать аккаунт, повторно войти и управлять своими сессиями.
- Библиотека сохраняется между сессиями; пользователь может изменять её состояние.
- Новый пользователь получает стартовые рекомендации; оценки влияют на персональную выдачу.
- Реакции сохраняются, ограничения повторов учитываются, исключённые фильмы больше не рекомендуются пользователю.
- Истории действий достаточно для пересчёта профиля вкуса.
- Один пользователь не может читать или изменять приватные данные другого.

Согласование этого документа не означает, что перечисленные возможности уже реализованы, и не является разрешением на изменение production-кода.
