# F95 Tinder

Многопользовательский веб-сервис с API на NestJS, SPA на React/Vite, MongoDB и Redis.

## Архитектура

- `apps/api`: API на NestJS и бизнес-логика, принадлежащая бэкенду.
- `apps/web`: браузерное приложение на React/Vite.
- `packages/contracts`: общие контракты API.
- `packages/config`: общая конфигурация рабочего пространства.

MongoDB хранит каталог и постоянное состояние пользователей. Redis необходим
для очередей, блокировок, кеширования, отмены действий и ожидающих решений.

## Локальная разработка

Требования: Node.js 22+, pnpm, MongoDB и Redis.

1. Установите зависимости рабочего пространства:

   ```sh
   pnpm install
   ```

2. Скопируйте `apps/api/.env.example` в `apps/api/.env` и замените
   `TOKEN_ENCRYPTION_KEY` секретным 32-байтным ключом в кодировке base64:

   ```sh
   openssl rand -base64 32
   ```

3. Запустите API и веб-приложение:

   ```sh
   pnpm dev
   ```

Веб-приложение доступно по адресу `http://localhost:5173`; Vite перенаправляет
запросы `/api` к API по адресу `http://localhost:3000`.

## Docker Compose

1. Скопируйте `.env.example` в `.env`.
2. Сгенерируйте уникальный `TOKEN_ENCRYPTION_KEY` и добавьте его в `.env`.
3. Запустите стек:

   ```sh
   docker compose up --build
   ```

Полное приложение доступно из одного источника по адресу `http://localhost`.
Укажите `WEB_PORT` в `.env`, чтобы опубликовать его на другом порту хоста.
Данные MongoDB и Redis хранятся в именованных томах `mongodb-data` и
`redis-data`.

## Обязательная конфигурация

- `TOKEN_ENCRYPTION_KEY`: секретное каноническое значение base64, кодирующее
  ровно 32 случайных байта. Никогда не добавляйте пример значения в репозиторий
  и не используйте его повторно.
- `TOKEN_ENCRYPTION_KEY_VERSION`: идентификатор, сохраняемый вместе с
  зашифрованными токенами; изменяйте его при добавлении новой версии ключа
  шифрования.
- `CORS_ORIGINS`: разделённый запятыми список источников браузерных запросов,
  принимаемых API.
- `CATALOG_SYNC_CRON`: cron-выражение из пяти полей для обновления каталога.

Стек Compose предоставляет внутренние значения `MONGODB_URI` и `REDIS_URL`.
Redis необходим для очередей, блокировок, кеширования и ожидающих решений
пользователей.

## Одноразовая миграция

Перед развёртыванием версии без постоянных пустых решений удалите старые
документы MongoDB:

```javascript
db.userGameStates.deleteMany({ status: null })
```

## Конечные точки

- Веб-приложение: `/`
- Проверка состояния API: `/api/health`
- Документация API при локальной разработке: `/api/docs`
- SSE с ходом синхронизации каталога: `/api/catalog/sync/events`
